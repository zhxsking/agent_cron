## 任务目标
从大语言模型（LLM）领域挑选一篇经典、有影响力的论文进行精读，并生成一篇通俗易懂、结构清晰、图文并茂、且充满阅读趣味的论文解析。通过每日一篇的积累，逐步带领读者了解并熟悉该领域的起步、发展、现状与未来，同时保证足够的趣味性和吸引力，让读者有兴趣持续追读下去，最终形成完整的大模型知识体系。

### 1. 论文选择
- 从大语言模型（LLM）领域挑选一篇经典、有影响力的论文。经典论文是指那些对该领域发展有重大贡献、被广泛引用的论文。
- **按领域演进脉络选择**：论文选择应遵循大模型领域的发展时间线，从起步期到最新进展，让读者能跟随系列解析逐步建立对整个领域的系统认知。
- 依据步骤 0 中确认的 papers_covered 清单，按演进顺序选择下一篇尚未解析的论文，避免重复。若步骤 0 中 next_preview 已指定选题，以其为准。
- 如果不确定该选哪篇，优先选择奠基性、里程碑式的论文。

### 2. 深度精读
对所选论文进行深度精读，充分理解其：
- 研究背景与动机
- 核心问题与挑战
- 方法创新与技术细节
- 实验设计与结果
- 对领域的影响与局限性
- 论文背后的故事（研究团队的灵感来源、有趣轶事、发表过程中的波折等，增加趣味性）

### 3. 论文解析生成
生成一篇高质量的论文解析，要求：

#### 通俗易懂
- 用平易近人的语言解释复杂概念，适当使用类比和生活化比喻，让非专业读者也能理解核心思想
- 遇到专业术语时，先用通俗语言解释再给出术语

#### 结构清晰
严格参照模板文件 `trae/data/llm_paper_daily/template.html` 的章节结构，依次包含：
- **顶部信息区**：系列标识 + 序号、论文原文标题（主标题）、中文意译标题（副标题）、作者、机构、发表时间、arXiv/GitHub/Project 链接（无 Project 主页则删除该行）
- **开篇引子**（用一个引人入胜的故事、问题或场景开头，激发阅读兴趣；禁止使用首字下沉/放大效果）
- **一句话总结**
- **领域定位**（本论文在大模型发展历程中处于什么位置，承前启后的作用）
- 研究背景（为什么需要这项工作，之前的方法有什么不足）
- 核心问题（要解决什么问题）
- 方法详解（怎么解决的，分步骤讲解）
- 实验结果（效果如何，有哪些令人惊讶的发现）
- 影响与意义（对领域的贡献）
- 局限性与未来方向
- **领域演进脉络**（简要梳理从起步到现状的发展线索，标注本论文位置，帮助读者建立全局视野）
- **趣味延伸**（论文背后的故事、研究团队的趣闻、或该技术在现实中的有趣应用）
- 个人解读与延伸思考
- **下期预告**（放在全文末尾作为结尾钩子，预告下一篇将要解析的论文，设置悬念，吸引读者持续关注；预告的论文标题需明确、具体，不使用模糊表述，因为这将作为下一次任务的强制选题依据）

#### 图文并茂
使用 SVG 图表、示意图、流程图等可视化方式辅助说明关键概念、模型架构、数据流程等。至少包含 4-5 个可视化图表，包括：
- 模型架构/方法示意图
- 数据流程或训练流程图
- 大模型领域发展时间线图（标注当前论文位置，高亮已解析部分）
- 关键概念对比图或其他辅助理解的可视化
- 趣味性插图（可选，用轻松的方式呈现某个概念）

#### 保证阅读兴趣与持续性
- **故事化叙述**：将论文解析写成一篇有故事性的文章，而非枯燥的学术翻译。用"问题-探索-突破-影响"的叙事结构推进
- **设置悬念与钩子**：开篇设置吸引人的问题或悬念，在关键处留下"为什么"引导读者继续阅读
- **生动比喻**：大量使用生活中的类比来解释抽象概念（如用"图书馆管理员"类比注意力机制等），使用模板中的 `callout` 容器呈现
- **适当幽默**：在保持专业性的同时，适当加入轻松幽默的表达，让阅读不枯燥
- **情感共鸣**：讲述研究者面对困难时的坚持、突破时的惊喜，让读者产生共鸣
- **系列连贯性**：每篇解析之间通过"上篇回顾"和"下期预告"建立联系，让读者有追剧般的体验
- **阅读节奏感**：长短段落交替，重点内容用特殊样式突出，避免大段密集文字造成视觉疲劳
- **互动感**：在文中适当设置思考题或小问题，使用模板中的 `think` 容器呈现，邀请读者思考，增强参与感

### 5. HTML 严格风格规范（学术报告风）

**必须严格参照模板文件 `trae/data/llm_paper_daily/template.html`**（文章模板）和 `trae/data/llm_paper_daily/index_template.html`（索引页模板），包括其 CSS 类名、命名规范、字体加载方式与配色变量，仅替换模板中 `[方括号]` 标注的内容与图表数据，不得随意改动既有的 class 结构。

**字体加载（必须加载 Web 字体，不得使用系统字体回退或伪斜体）：**
- 标题/正文：Lora（需加载包含 ital 轴的完整字重，即 Lora:ital,wght@0,400..700;1,400..700），禁止使用 font-style: italic 伪斜体模拟，所有斜体必须通过真实字体的 ital 轴实现
- **中文不使用斜体强调**（Lora 无中文斜体字形，强行倾斜属于伪斜体）：中文/中英混排的强调内容用默认 `<em>`（颜色+字重，不倾斜）；仅当强调内容为纯英文/拉丁字母时才使用 `<em class="latin">`（真实斜体）。判断标准：整个 `<em>` 标签内是否全部为拉丁字符，只要出现中文字符即视为中文/混排情形
- 代码/数据/标签/图注：JetBrains Mono，表格内数字必须加 font-variant-numeric: tabular-nums
- 数学变量与公式：统一使用 KaTeX 渲染，不得使用 <em> 标签或 CSS 伪斜体替代单个数学符号
- 章标题（h2）的序号需与标题正文使用相同字体（Lora），不使用等宽字体，仅用颜色区分

**色彩系统（Palette）：**
```css
:root {
  --bg:      #F4EFE4;
  --bg2:     #ECE4D4;
  --ink:     #2E2A22;
  --muted:   #96897A;
  --rule:    #96897A;
  --accent:  #B54A2C;
  --accent2: #24555A;
}
```

**背景与材质约束（最高优先级，必须严格遵守）：**
- 页面背景 background 只允许使用纯色 var(--bg)，绝对禁止 background-image、SVG pattern、噪点滤镜（feTurbulence）、paper-texture、grid-texture、repeating-linear-gradient、radial-gradient 等任何叠加纹理或图案
- 卡片与代码块底色使用 var(--bg2)，同样为纯色，不加任何纹理
- "纸面"效果仅通过色相与色温（暖白米色）体现，不通过任何视觉材质效果体现
- 禁止使用任何 CSS noise、grain、texture 相关的背景效果

**组件规范：**
- 表格：三线表样式，仅表头下方与表底各一条 --rule 线，行间用 --muted 极低透明度（约 0.06）斑马纹
- 代码块：--bg2 底色 + 左侧 3px --accent2 竖线，无阴影、无大圆角（border-radius 不超过 2px）
- 公式块：独立居中显示，右侧小号 JetBrains Mono 编号
- 分割线：全篇统一使用 1px --rule 细线，只出现在每章内容结束、下一章开始之前，标题下方不加分割线，禁止使用粗框线
- 外部链接（arXiv/GitHub/Project）为纯文字链接，不加箭头等装饰符号
- **禁止使用首字下沉/首字放大效果**（如 CSS `::first-letter` 配合大字号），尤其当段落开头是数字或字母时，容易被拆分导致视觉错乱。正文中所有段落保持统一字号，不做首字特殊处理。

**视觉风格：**
- Academic paper aesthetic，克制严肃，无装饰性背景效果
- 排版美观，有良好的视觉层次，配色舒适，适合长时间阅读
