大模型经典论文精读系列 #036

Voyager: An Open-Ended Embodied Agent with Large Language Models Voyager：把 GPT-4 塞进《我的世界》——会自己定目标、写代码、攒技能、永不遗忘的终身学习智能体

作者：Guanzhi Wang, Yuqi Xie, Yunfan Jiang, Ajay Mandlekar, Chaowei Xiao, Yuke Zhu, Linxi "Jim" Fan, Anima Anandkumar 机构：NVIDIA, Caltech, UT Austin, Stanford, ASU 发表：2023-05 / arXiv（后收录于 TMLR 2024，ICLR 2025 Journal Track）
arXiv GitHub Project

2023 年 5 月的一个深夜，一只手无寸铁的 AI 智能体被空投到了《我的世界》的一片随机方块世界里。它没有被告知要去打龙，也没有被告知要造房子，唯一的指令只有一句含糊的"尽可能多地发现新东西"。换作以前的强化学习智能体，多半会在原地转圈直到饿死；可这一次，它先是抬头看了看树，自己写了一段 JavaScript 代码去砍木头，接着又自己写代码做工作台、做石镐、挖铁矿、打僵尸——几个小时后，它居然造出了一把钻石镐。

让这只智能体"活过来"的，是一篇叫 Voyager 的论文。它没用一行梯度下降，没动一次模型权重，只靠着不断向 GPT-4 提问、把答案写成代码、再把能跑通的代码存进一个"技能库"，就完成了过去需要训练几十亿步的强化学习才能做到的事。这篇解析，就带你看看 NVIDIA 团队是如何把"思考—行动—反思"的循环，焊成一个能在方块世界里终身学习的探险家的。

一句话总结 Voyager 把 GPT-4 当作"会写代码的大脑"，用"自动课程 + 技能库 + 迭代提示"三件套，让智能体在《我的世界》里自己出题、自己写代码、自己查 bug、自己把技能存起来复用，第一次让大模型驱动的智能体展现出真正的终身学习能力。

01领域定位

如果把整个大模型的发展史看成一条长河，Voyager 处在一个非常特别的分岔口：它既不是底层模型的进步（它直接调用 GPT-4，一行权重都不训），也不是单纯的提示工程（它有一整套系统化的"记忆—课程—反思"结构），而是把前面二十多篇论文攒下的"零散能力"焊在了一起，第一次拼出了一个能持续自主进化的智能体骨架。

具体说，它承接了三条线：一是第 35 篇我们讲过的 ReAct——"思考—行动—观察"循环奠定了 LLM 调工具的基本范式；二是第 31 篇 Reflexion——把失败写进语言记忆、下次避开同样的坑；三是第 34 篇 Toolformer——把工具调用训进权重。Voyager 把这些思路拉到极限：不微调、不训练，全靠 prompt + 外部记忆，却要解决一个比单轮问答难得多的任务——在无限世界里越玩越强，而且永远不忘。

它开启的，则是后来被称为 LLM Agent 的整个赛道：之后的 AutoGPT、BabyAGI、斯坦福小镇、MetaGPT、甚至今天的各类"通用智能体"框架，几乎都能在 Voyager 这套"课程—技能库—自我验证"的骨架里找到自己的影子。可以说，它是LLM agent 时代的奠基样本之一。

02研究背景

要理解 Voyager 解决了什么，得先看看《我的世界》为什么是 AI 研究的"终极考场"。这游戏有两个最反常识的特点：第一，它没有目标。不像下棋要赢、不像超级马里奥要通关，整张地图是程序随机生成的，玩家想干嘛干嘛。第二，它有科技树——空手砍不动石头，得先做木镐；石镐才能挖铁；铁镐才能挖钻石。技能之间有严格的偏序关系，必须按顺序点亮。

这两个特点加在一起，恰好把"通用智能"压成了一个非常干净的考题：一个智能体能不能在没人指挥的情况下，自己摸清这个世界的能力层级，然后一层一层爬上去？这正是 Jim Fan 团队此前发起的 MineDojo 项目（NeurIPS 2022 杰出论文奖）所关心的核心问题。

在 Voyager 之前，主流解法是强化学习：从零开始，让智能体用像素当眼睛、用按键当手脚，靠"挖到钻石给奖励"这种稀疏信号训练。从 2016 年的 MineRL 大赛到 2022 年 OpenAI 的 VPT（看视频学操作），整整六年，研究者烧掉了天文数字的算力，最好的成绩也不过是偶尔挖到钻石，而且换张地图就废。痛点很清楚：奖励太稀疏、探索太低效、学到的策略像一张脆弱的纸，稍微换个环境就撕了。

另一条线是 LLM agent。2023 年春天，ReAct、Reflexion、AutoGPT 这些工作接连冒出来，证明 GPT 这类大模型可以直接当"大脑"，边想边调工具。但它们都有一个共同的硬伤——不积累。问一次答一次，下一轮又从零开始，跨不过几十轮，更别提"越玩越强"的终身学习。

类比 旧式强化学习像让一个婴儿从零开始摸索世界，每挖一块石头都要试错几百万次；早期的 LLM agent 像请了一位博学的教授，但你每次问他都得从头解释一遍背景，他答完就走了，第二天再来他什么都不记得。Voyager 想做的，是给这位教授配一本笔记本——他每答对一题就把解法抄下来，下次再遇到类似题直接翻笔记本。

03核心问题

把背景压成一句话，Voyager 要回答的问题是：能不能让一个 LLM 驱动的智能体，在没有任何人类干预的开放世界里，持续地提出任务、积累技能、永远不忘、还能把学到的本事迁移到新环境？

这个问题被拆成了三个子目标，恰好对应 Voyager 的三大组件：

  • 该干嘛：开放世界没有外接任务清单，智能体得自己根据当前状态（手里有什么、身处什么地形、已经会什么）挑一个难度刚好的下一个目标——既不能太简单到无聊，也不能难得让人崩溃。
  • 怎么干：Minecraft 的低级动作（转视角、按键）粒度太细，长任务动辄上千步。光靠 LLM 一字一句地输出动作根本撑不住。需要一种粒度可大可小、还能复用的动作表示。
  • 记什么：上下文窗口是有限的，把所有历史塞进 prompt 不现实。需要一种能跨轮次、跨任务稳定存储且语义可检索的长期记忆，而且加新技能时不能把旧技能搞乱（即避免强化学习里臭名昭著的"灾难性遗忘"）。
思考一下 假如让你设计这样一个智能体，你会让"下一个任务"由谁决定？是写死一张科技树任务清单，还是问 GPT-4"你觉得下一步该干嘛"？前者稳妥但僵化，后者灵活但可能瞎出题。Voyager 选了后者，你猜它怎么防止 GPT-4 一直出无意义的题？

04方法详解

Voyager 的整套设计可以用一句话概括：把大模型当大脑，把游戏当调试器，把技能库当硬盘。下面分三个模块拆解。

子方法一：自动课程（Automatic Curriculum）

第一个模块要回答的是"下一步该干嘛"。Voyager 不写死任务清单，而是每完成一个任务就回头问 GPT-4："根据我现在的状态（手里有什么、站在什么生物群系、已经会什么、最近失败过什么），给我一个既新颖又不至于太难的新任务。"这被作者称为"上下文内的新颖性搜索"——GPT-4 凭着它从全网学到的世界知识，能很自然地提出"还没做过但够得着"的事。

这个 prompt 由四部分组成：一条鼓励多样性的总指令（"发现尽可能多的不同东西"）、当前智能体状态（背包、装备、生命值、生物群系）、最近完成和失败的任务清单、以及用 GPT-3.5 自问自答补充的额外上下文。如果某个任务连续失败，课程会主动把它拆成更简单的子任务或者干脆暂时搁置，避免在死胡同里耗光预算。

这里有个反直觉的细节：课程 prompt 用了 chain-of-thought（思维链，见第 24 篇）提示——先让模型推理"什么是新颖且可行的"，再产出任务。temperature 设为 0.1，既保留一点随机性以鼓励多样性，又不会乱出题。整个系统里没有一条手写的"先砍木头再做木镐"的规则，科技树的顺序完全是 GPT-4 凭常识涌现出来的。

类比 自动课程就像一个会因材施教的私人教练。它不像传统课程表那样把所有学生塞进同一条流水线，而是看你今天状态如何、上次卡在哪、手里有什么，临时给你挑一道"再跳一跳就够得着"的题。这种"最近发展区"教学法，正好对应 Minecraft 科技树那种"必须先会 A 才能学 B"的硬约束。

子方法二：迭代提示机制（Iterative Prompting Mechanism）

有了任务，第二步是写代码去执行。Voyager 选了一个非常激进的动作空间——直接把 JavaScript 函数当作动作。它不用低级的"转视角—按键"序列，而是让 GPT-4 写一段调用 Mineflayer API 的 JS 代码（比如 bot.dig、bot.placeBlock、bot.craft），整段代码扔进游戏执行，结束后再统一回收反馈。

这个选择是 Voyager 最深的洞察之一。代码有三个天然优势：一是可组合（函数可以调函数），二是可验证（要么跑通了要么没跑通，没有中间态），三是可解释（人类能直接读出智能体"知道"什么）。这三个性质让"技能累积"第一次在 LLM agent 上变得可行。

但 GPT-4 一次写对的概率并不高。Voyager 设计了一个紧凑的修复循环：每次代码执行后，回收三路反馈——环境状态（执行后背包多了什么、走到哪了）、执行错误（JS 运行时报错、API 调用异常）、以及一个独立的 GPT-4 实例扮演的"自我验证裁判"判断"任务到底完成了没有"。如果三路有任何一路说没成，原始 GPT-4 会被重新提示，把上一次的代码、错误信息、裁判建议一起喂回去，再写一版。这个循环最多跑 4 轮，4 轮还失败就把任务退回课程模块，让它拆解或搁置。

这里有个跟 Reflexion（第 31 篇）和 ReAct（第 35 篇）的关键差别：那两个工作每一步只吐一个文本动作，Voyager 一次吐一整段程序，可能跑几十个游戏 tick、调很多 API。这种"动作粒度放大"让模型把推理成本摊销到一堆低级动作上，也让产出的程序本身就成了一个可复用、可入库的"技能单元"。

子方法三：技能库（Skill Library）

第三个模块是 Voyager 区别于所有前辈的灵魂。当一个任务被自我验证裁判判定成功后，对应的 JavaScript 函数不会随风飘走——它会配上一段 GPT-4 生成的自然语言描述，连同描述的向量嵌入（用 OpenAI 的 text-embedding-ada-002）一起塞进一个向量数据库。下次新任务来了，系统把任务描述做嵌入、检索 Top-5 最相关的旧技能，作为可调用的"helper"拼到新 prompt 里。新代码可以直接调旧函数，比如 craftStonePickaxe() 里可以调用之前学过的 mineWoodLog() 和 craftWoodenPickaxe()。

这个设计的妙处在于它把"学习"从权重更新搬到了代码累积。权重更新有灾难性遗忘——学新技能会冲掉旧技能；代码累积没有这个问题，新加的函数不会动旧的半根毫毛。技能库就是智能体给自己写的一份不断膨胀的简历，而且每一项都经过验证（没跑通的不许入库），所以每一项都站在已验证的地基上。这被作者称为"学习在复合"——能力像滚雪球一样越滚越大。

关键设计 技能库的两条铁律让"复合"变得可信而不是堆垃圾：第一，前置技能必须已经在库里——你不能跳过石镐直接挖铁；第二，新代码必须验证通过才入库——没跑通的程序永远进不了库。这两条规则共同保证了库里的每一段代码都站在已测试的地面之上，复合不会复合出 bug。

05实验结果

实验在 Minecraft Java 版上跑，基线是当时最强的三种 LLM agent 框架——ReAct、Reflexion、AutoGPT。所有方法都接 GPT-4，都看不到像素，只通过文本状态交互。Voyager 的成绩单相当炸眼。

最扎眼的数字是钻石工具——在 MineRL 比赛 + VPT 那条 RL 路线苦战六年都打不下来的目标，Voyager 是唯一摸到的，而且只用了 102 轮 prompt 迭代。注意这是"3 次实验中 1 次"，作者很诚实地在论文里标了这点，避免读者误以为钻石是稳的。

更耐人寻味的是消融实验。去掉技能库，Voyager 在前期还能跟上，后期明显停滞——因为没有可复用的"积木"，每个新任务都得从零写代码，复杂度一上去就垮。去掉自动课程改用手写课程，表现也明显下滑，因为手写课程不知道智能体现在手里有什么。去掉自我验证裁判，科技树进度大幅退化——没有裁判盯着，很多其实没完成的任务被错判为完成，垃圾代码混进库，复合就崩了。

另一个让人惊喜的发现是零样本迁移：研究者把 Voyager 在一个世界攒下来的技能库，原封不动搬到一个全新的 Minecraft 世界（地形、生物群系全不一样），让它去解从没见过的新任务。它能直接调用旧技能，从零搞定新任务；而 ReAct、Reflexion 这些没有技能库的基线，在新世界里几乎从零开始，举步维艰。这恰恰是"终身学习"该有的样子——本事应该能搬走。

06影响与意义

Voyager 发出后，几乎一夜之间把"LLM agent"从一个零散的实验方向，焊成了一个有清晰方法论的研究范式。它的三件套——自动课程、技能库、自我验证循环——成了之后无数 agent 框架抄作业的模板。无论是之后冒出来的 AutoGPT、BabyAGI 这类"自主任务 agent"，还是斯坦福小镇那种"多智能体社会模拟"，乃至今天形形色色的"通用智能体"产品，骨架里都能找到 Voyager 的影子。

它的两个方法论贡献尤其深远。一是代码作为动作空间：把"动作"从低级按键升到可执行程序，一举解决了长任务里动作粒度太细、上下文塞不下的问题，也顺势让"技能"成了可累积、可验证、可组合的一等公民。二是外部向量记忆替代权重更新：证明了"学习"未必非要梯度下降，把验证过的程序往数据库里塞，同样能做到"越用越强"，而且避开了灾难性遗忘这个 RL 的老顽疾。这两条思路后来被反复重用，几乎是 LLM agent 领域的"设计模式"。

更宏观看，Voyager 把 Minecraft 从"RL 的苦役场"重新定义成"LLM agent 的启蒙乐园"。在这之后，Minecraft 几乎成了 agent 论文的标配测试床，连 OpenAI 后来一些早期 agent 探索也用过它。论文本身后来被 TMLR 接收（2024 年 3 月），还拿到了 ICLR 2025 的 Journal Track 认证——对于一个"应用层"工作来说，这是相当高的待遇。

07局限性与未来方向

Voyager 并非没有短板。最显眼的一条是对 Minecraft 文本的强依赖。它能跑通，很大程度上是因为 Minecraft 的事件能用文本说清楚（背包多了什么、走到哪了），而且 GPT-4 在预训练时见过海量的 Minecraft 视频、wiki、论坛帖——它"知道"这个游戏该怎么玩。换成视觉主导、文本稀疏的真实世界（比如让机器人做饭），这条路未必走得通。一位 TMLR 审稿人就直言："我不确定这方法能否推广到 dynamics 完全不同、训练数据里没怎么覆盖过的游戏。"

第二条是感知被完全外包给了 Mineflayer API。Voyager 不看像素，所有"看见"都来自 API 已经结构化好的状态。这绕开了视觉感知的难题，但也意味着它没解决真正的"embodied perception"——一旦环境没有现成 API，它就瞎了。后来的工作（如 DEPS、SWITCH）开始尝试把视觉模型接进来，但这都是 Voyager 之后的事。

第三条是成本与延迟。每个任务最多 4 轮 GPT-4 调用，每轮都是黑盒 API 请求，单次实验跑下来 API 费用不菲，速度也远谈不上实时。对于"在线交互"型任务（比如和真人对话的客服 agent），这个延迟是致命的。

第四条是"开放世界"的边界。Voyager 的"终身学习"是在 Minecraft 这一封闭规则世界里的开放探索，规则不变、物理稳定。真正的开放世界——比如互联网、物理世界——规则会变、会有对抗者、会有分布漂移，Voyager 的技能库能否扛住这种"规则漂移"，论文没给出答案。

08领域演进脉络

把 Voyager 放回大模型发展的长河里，它处于一条非常清晰的从"模型即智能"到"系统即智能"的演进路径上。早期（2017—2020），大家的注意力全在把模型做大：Transformer、GPT-2、GPT-3，思路是参数够多就够聪明。规模化探索期（2020—2022）开始关心数据配比，Chinchilla 证明了"小模型多数据"能反杀大模型。

对齐与应用期（2022—2023）则拐了一个弯：研究者发现光有大模型不够，得教它听人话、会反思、会用工具。InstructGPT 用人类反馈教模型听话；CoT、Self-Consistency、Tree of Thoughts 一路把"推理"做成可提示的技能；Reflexion 把失败写进语言记忆；Toolformer 把工具调用训进权重；ReAct 把"思考—行动—观察"焊成循环。每一步都在给模型加外挂——但每个外挂都是单点突破，彼此不连。

Voyager 出现在这条线的汇流处。它没发明任何一个全新组件，但它把"自动出题（curriculum）+ 工具调用（code as action）+ 反思循环（iterative prompting）+ 长期记忆（skill library）"这四样分别来自不同论文的思路，第一次焊成了一个能持续运行、自我积累的闭环系统。在它之后，LLM agent 研究正式从"单点技巧"进入"系统工程"阶段——之后无论是 MetaGPT 的多智能体协作、斯坦福小镇的社会模拟，还是今天的各类 agent 框架，本质都是在这个骨架上换组件、加组件。这条线一直延伸到今天，是 LLM 应用层最活跃的方向之一。

09趣味延伸

Voyager 背后有个挺有意思的人物——通讯作者 Linxi "Jim" Fan。这位 NVIDIA 的高级研究员，其实是 OpenAI 的第一位实习生。2016 年夏天，已经被斯坦福录取的他闲着没事，朋友说城里有家新公司让他去看看，他就去了，那家公司就是 OpenAI。他的实习导师是 Andrej Karpathy 和 Ilya Sutskever，做的是 World of Bits——让 AI 看屏幕像素、控键鼠的最早 AGI 尝试之一。换句话说，Jim Fan 的整个学术生涯就是一场"如何造 agent"的长跑，从 2016 年的像素 agent，到 2022 年的 MineDojo（NeurIPS 杰出论文奖），再到 2023 年的 Voyager，他一直在追问同一个问题：怎么让 AI 在开放世界里持续变强。

Voyager 一发布就炸了圈。Karpathy 本人在推特上感慨："还记得 2016 年在《我的世界》里做 AI agent 是多么绝望吗？现在画风变了——正确的做法是先拿全网数据训一个 LLM 学世界知识、推理、工具使用，然后像 NVIDIA 这样让它去解决问题。"他还补了一句："如果 2016 年有人给我看这种无梯度的 agent 方法，我肯定会大惊失色。"——一个前 OpenAI 核心成员、当时已是特斯拉 AI 总监的人，公开承认"被震到"，这是相当高的赞誉。

还有个细节很有意思：Voyager 上 arXiv 是 2023 年 5 月 25 日，两天后，另一篇几乎同主题的工作 Ghost in the Minecraft（GITM）就贴出来了。两支团队几乎是同时独立地想到"用 GPT-4 玩 Minecraft"，可见这个 idea 在 2023 年春天已经"在空气中"了——GPT-4 一发布，"让它去打游戏"几乎是所有 agent 研究者的第一直觉。

Jim Fan 后来在一次访谈里把 Minecraft 形容为"开放式 agent 涌现的完美原汤"——它的开放性、科技树的偏序结构、文本友好的事件描述，几乎是为 LLM agent 量身定做的考题。他还调侃自己 Minecraft 玩得不好，"所以我希望我的 AI 能弥补我糟糕的游戏技巧"——这种"造个 AI 替我打游戏"的自嘲，反而让 Voyager 多了几分人情味。

10个人解读与延伸思考

读完 Voyager，最让我念念不忘的不是那些炸眼的数字，而是它隐含的一个哲学转向：它把"学习"重新定义成了"往数据库里塞验证过的代码"，而不是"调权重"。这看似只是工程上的取舍，实则是对"智能是什么"的一次重新发问。如果一套系统不需要改一个参数、只靠累积可执行程序就能越用越强，那"智能"的核心到底在权重里，还是在外部记忆 + 调用结构里？Voyager 没回答，但它把这个问号摆到了台面上。

这条思路今天看来越发不像是"工程小聪明"。当下的 agent 框架几乎都在沿这条路走——把大模型当推理引擎，把工具调用、记忆检索、规划循环当外挂系统，"智能"被分布式到了一整套系统里，而不是锁在某个模型参数矩阵里。某种意义上，这跟大脑（模型）+ 笔记本 + 工具箱 + 反思习惯的人类认知结构遥相呼应。Voyager 在 Minecraft 这个"玩具世界"里把这个结构跑通了，它的意义远不止"AI 会打游戏"。

当然，我也保持一份清醒。Voyager 跑通的世界，规则封闭、文本友好、API 现成——这三个条件在真实世界里几乎同时满足不了。真实世界没有 bot.dig 这种现成动作，视觉感知也没法外包给 API，规则还会漂移。Voyager 证明了"终身学习 agent"在受限世界里的可行性，但从 Minecraft 走到物理世界这段路，可能比从"无 agent"到"Voyager"这段路更长、更难。Jim Fan 自己后来也把研究重心转到了机器人（Eureka、Project GROOT），这本身就是一个信号：方块世界跑通了，下一步是真实世界。

留个问题给你 假如把 Voyager 的技能库搬到一个"规则会变"的世界——比如某个游戏每隔几小时就更新一版配方表——它的技能库会不会反而成为累赘，让它在过时代码上越陷越深？你觉得该给技能库加什么机制，才能让它在规则漂移下依然有用？欢迎带着这个问题，等下一篇。
