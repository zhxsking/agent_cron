Absolute Zero: Reinforced Self-play Reasoning with Zero Data Absolute Zero：零数据自博弈推理——一个模型自己出题、自己解，竟反超几万条人类标注训出来的模型

上一篇我们读完了 Self-Play SWE-RL，看着软件 agent 学会"自己给自己出 bug 题、自己修"，在那个结尾我们预告了它的孪生兄弟——一个让模型自己出数学和代码题、自己解的工作。现在，我们到了。

想象一个永远不会"被题难住"的学生：题库里的题做完了，老师又出不了更难的，于是他自己造题——造完自己解，解完自己判对错，判错了就换种造法。没有人类老师，只有一个能跑 Python 的"自动判卷机"。这不是科幻，这就是 2025 年 5 月挂在 arXiv 上的 Absolute Zero。它的名字里藏着物理学"绝对零度"的梗——降到最低的外部依赖，逼近自我进化的极限态。

一句话总结 让一个模型同时当"出题人""解题人""验证人"，只用一个 Python 解释器当裁判，完全不依赖任何外部人工数据，就能在代码和数学推理上反超用几万到几十万条人类数据训练的模型。

01领域定位

把这篇论文放回大模型整条发展线上，它的位置很特别：它站在"推理范式期"和"自博弈训练期"的交界处。第 020 篇 o1 用强化学习训练思维链，把推理范式点燃；第 013 篇 DeepSeek-R1 证明纯 RL 能让模型自发"顿悟"出反思。但这些工作的共同前提是——得有人先准备好题库。R1 虽号称 zero，跳过了 SFT，可 RL 阶段依然喂的是人工精心整理的问答对。

Absolute Zero 干的是一件更狠的事：它把题库本身也交给模型自己造。这等于把"扩展轴"从"测试时多想一会儿"（o1 那条线）和"训练时多喂几万题"（R1 那条线），挪到了"训练时让模型自己无限造题"。它承接了上一篇 SSR"软件 agent 自博弈"的直觉，却把舞台从软件工程换成了更纯粹的数学与代码推理——也正因为任务更纯粹、裁判更硬（代码能跑就是能跑），它成了"自博弈训练期"里第一个被顶会盖章的范式样板。

02研究背景

要理解 Absolute Zero 为什么重要，得先理解一个让整个 post-training 圈子焦虑的词：数据墙。

预训练阶段早就撞过一次墙——高质量人类文本的增长跟不上模型规模的膨胀，Chinchilla 早就告诉我们"数据不够，模型再大也是浪费"。大家本以为 post-training（强化学习对齐这一段）能松口气，毕竟这里数据需求小得多。可 R1 之后人们发现：训练一个会推理的模型，你需要大量带标准答案的题——数学题、代码题、逻辑题，每道都得人来出、人来验。出题的"标注大军"产出速度，又成了模型进步的速度上限。数据墙，从 pretraining 搬到了 post-training。

更深的焦虑在论文摘要里写得明明白白：如果未来真的出现超越人类的 AI，那"由人类出题"本身就是一个天花板——人出的题，对超智能系统来说可能太简单了。你的题库撑死了教出一个跟你差不多聪明的学生，教不出比你更聪明的。

类比 想象你是个围棋老师，要教一个可能比你强的学生。传统 RLVR 像你把人类下过的棋谱摆给他看、给他出题；可人类棋谱终归有限，你出的题也超不过你的水平。AlphaZero 的解法是——别当老师了，给学生一个棋盘和胜负规则，让他自己跟自己下几百万盘。Absolute Zero 干的就是这件事，只不过把"棋盘"换成了"Python 解释器"，把"胜负规则"换成了"代码跑出来的结果"。

既有方法各自卡在哪里？DeepSeek-R1-Zero 号称跳过 SFT，但 RL 阶段仍然依赖人工整理的题库；STaR 这类自训练方法只为已有的题生成推理链，不自己出题；rStar-Math 用蒙特卡洛树搜索加小模型奖励模型做"深度思考"，但仍在数学单域、仍依赖现成题。它们都解决了一半问题——"怎么训"，但没解决另一半——"题从哪来"。

03核心问题

论文要回答的问题可以一句话说清：能不能让一个模型完全不依赖任何外部人工数据，自己给自己造题、自己解、自己验证，还能在真实推理任务上变强？

这里每个限定词都是硬约束。"不依赖外部人工数据"——不只是不要 SFT 数据，连 RL 用的题库都不要；"自己造题自己解自己验证"——三个角色得由同一套权重包揽；"还能在真实任务上变强"——不能只在自造的题上自娱自乐，得迁移到人类出的标准 benchmark 上有实打实的提升。

思考一下 如果让模型自己出题自己解，最容易出什么毛病？给你三秒猜一下，再往下看。

答案的核心就一个词：作弊。出题人可以专门出自己会的简单题刷分，或者出一些"看起来难实则有漏洞"的题——反正裁判也是它自己。这正是"自博弈"在开放领域最难的地方：围棋有上帝定的胜负，开放推理任务没有。Absolute Zero 怎么破这个局？往下看它的方法。

04方法详解

Absolute Zero 的方法叫 Absolute Zero Reasoner（AZR）。它的核心是一个自我进化的三步闭环，由同一套模型权重交替扮演三个角色。

三角色分工：出题、解题、验证

先说人话：AZR 让一个模型当"命题老师"，负责造题；当"考生"，负责解题；当"阅卷老师"，负责判对错。但阅卷老师不是模型自己——它把判卷的活儿外包给了一个Python 解释器。这是整个设计最妙的一笔：裁判不学习、不可收买、不会累，代码跑出来对就是对、错就是错。出题人想作弊？可以，但它没法让 Python 解释器"睁一只眼闭一只眼"。

具体到造题环节，AZR 造的不是自然语言题，而是一个三元组：$(程序\ p,\ 输入\ i,\ 输出\ o)$，要求 $p(i)=o$。也就是说，命题老师得写一段 Python 代码 $p$、给一个输入 $i$、再标一个预期输出 $o$，三者得在 Python 里跑通且对得上。出题完成后，这套三元组会先过 Python 执行器筛一遍——程序得能跑、得有返回值、还得"安全"（禁用了 os/sys/shutil 这些能搞破坏的模块）。只有过了这一关的题，才进题库 buffer。

三种推理模式：顺向、逆向、归纳

题造好了，怎么解？AZR 设计了三种"推理模式"，对应人对推理的三种基本方式。这正是这篇论文最有想法的地方——它不是让模型只练一种题型，而是练三种"思维方向"。

对应到人话，这三种模式可以这样理解：

  • 顺向演绎（deduction）：给你程序和输入，让你算输出。这是最"正"的推理——已知规则和前提，推结果。就像给你一个函数和自变量，求函数值。
  • 逆向归溯（abduction）：给你程序和输出，让你反推一个能产生这个输出的输入。这是"倒着想"——已知结果和规则，反推原因。注意它不要求还原出题者的原始输入（因为多个输入可能映射到同一个输出），只要找一个合法的就行。
  • 归纳反演（induction）：给你几个能看到的样例和一段描述，让你归纳出一般规则（写程序）。这是最"高级"的推理——从样例猜规律，就像让你看几组输入输出反推函数。这一步刻意隐藏了部分测试样例，是为了防止模型耍小聪明把可见样例硬编码进去。
一个细节 论文特意澄清：这三个标签——deduction / abduction / induction——描述的只是"代码任务的三种格式"，不是说模型真学到了逻辑学里完整的演绎/归纳/溯因系统。但用三种不同方向训练，确实比单一题型更能逼出泛化能力，这点后面实验会证实。

可验证代码奖励：为什么是 Python 当裁判

整个方法最关键的设计，是奖励的来源。AZR 不用学习型奖励模型（那种容易被钻空子的"AI 判官"），而是用 Python 解释器的执行结果直接当奖励：程序能跑且输出正确，就给正奖励；否则零。这个选择不是随便定的，背后有三重考虑。

第一，Python 是客观、确定、可执行的"地面真值"环境。它不依赖任何学习型模型，从根源上压制了奖励作弊——出题人再怎么想偷懒，也没法让 Python 解释器对它网开一面。第二，Python 涵盖极广的"可计算任务空间"，既开放（能造的题无穷无尽）又可验证（对错一目了然），把"开放性"和"接地性"统一在一个载体里。第三，同一个 Python 解释器既能判"题是否合法"（出题阶段），又能判"答案是否正确"（解题阶段），一个裁判两用。

TRR++：让奖励"按角色公平"地更新

训练算法不是普通的 GRPO，而是作者提出的 TRR++（Task-Relative REINFORCE++）。背景是：AZR 同时训两个角色（出题人、解题人）、三个模式，凑出 6 个"任务-角色"组合。如果用全局一个 batch 基线来归一化奖励，不同组合的难度差异会把信号搅乱——出题的奖励和解题的奖励混在一起算均值标准差，不公平。

TRR++ 的做法是：对这 6 个组合分别估计均值和标准差做基线归一化，让每个角色、每种模式都有自己的"参照系"。配置上用 clipped PPO 目标，每 batch 跑 1 个 policy epoch，学习率 $10^{-6}$，500 步，熵系数 0.001，无 KL 约束（既没 KL loss 也没 KL reward，给模型更大的自由探索空间）。

出题人奖励：逼它出"恰到好处"的难题

防止"出题人作弊刷分"的关键，在出题人的奖励函数设计上。AZR 给每个新题采样 8 次解题尝试，算成功率 $s$（8 次里解对几次的比例）。出题人的奖励这样定：

$$ R_{\text{propose}} = \begin{cases} 0 & \text{若 } s = 0 \text{（太难，全解不出）} \\ 1 - s & \text{若 } s > 0 \text{（越接近"恰好能解"奖励越高）} \end{cases} $$ (1)

这个函数妙在哪儿：$s=0$（8 次全错，题太难）奖励是 0；$s=1$（8 次全对，题太简单）奖励也是 0；只有当成功率 $s$ 介于 0 和 1 之间、且越接近 0（越难但仍可解）时奖励越高。也就是说，出题人想拿高分，得专门挑那种"难到只有少数人能解、但又不是完全没人能解"的题——这正是教育心理学里"最近发展区"的思路，也是 AlphaZero 式自博弈"对手段恰到好处"的推广。这等于逼着出题人当个"会因材施教"的好老师，而不是出简单题刷通过率。

第二件让人意外的事：自博弈没把模型"训废"

强化学习有个老问题：训完之后 pass@1 可能涨了，但 pass@k（多采几次能蒙对的覆盖面）可能反而塌了——模型把答案分布压窄了，多样性丢了，这对后续测试时扩展（像 o1 那种采多条再投票）是致命的。审稿人正是拿这点质疑 AZR。

作者的 rebuttal 补了一组漂亮的实验：AZR-Base-7B 在 MBPP++/HumanEval++/LiveCodeBench/AIME25 上，从 pass@1 到 pass@512 一致超过基座（比如 LiveCodeBench pass@256 提升 +8.0，AIME25 pass@512 提升 +6.7）。这意味着训练后答案层的语义熵仍然健康，没有塌缩——自博弈没把模型"训成一根筋"，反而保留了多样性，利于后续 test-time scaling。这把审稿人的质疑直接转化成了 AZR 的一个加分项。

一个自发涌现的彩蛋 论文还报告了一个有意思的现象：AZR 在自对弈中自发涌现出"先写注释再写代码"（comment-then-code）的 ReAct 风格行为——没人显式教它这么做，是可验证环境自己"逼"出来的良性行为。这让人想起 R1 报告里模型自发学会反思和验证的桥段：好奖励信号会自己长出好习惯。

Scaling 上也站得住：Qwen2.5-Coder 三档，3B 从 35.0 涨到 40.7、7B 从 40.2 涨到 50.4、14B 从 40.1 涨到 53.3，提升随规模放大。不过跨模型类的验证给了一个冷水——Llama 3.1 8B 只从 16.0 涨到 19.2，提升有限。作者归因于 Llama 基座的代码/反思能力较弱，这暗示 AZR 的收益依赖基座底子，不是任何模型都能无脑套用。

06影响与意义

这篇论文的意义，可以分三层来读。

第一层，它给"post-training 数据墙"提供了一个被顶会盖章的可行解。当人工题库枯竭，只要存在一个可执行验证环境（这里是 Python），模型就能自生成无限课程。它把数据墙问题从"等人类出题"转移到了"设计可验证环境"——而环境的边界，理论上比人类题库宽得多。这一层最直接，也最容易被工业界抄走。

第二层，它把 AlphaZero 的范式从封闭游戏搬到了开放推理。AlphaZero 能赢，靠的是围棋有上帝定的胜负规则；AZR 之所以难，是因为开放推理没有那种现成规则。它的破局是把 Python 执行器当"地面真值"，用代码的可执行性近似出"胜负"。论文证明这个近似是够用的——这为后续所有"开放领域自博弈"工作（不只数学，还可延伸到形式化证明、web 交互、模拟器）铺了一块地基。

第三层，跨域泛化的证据。纯代码自对弈让数学大涨，暗示推理能力可以脱离具体域迁移。这呼应了上一篇 SSR 的同类发现，也指向一个更深的猜想：可计算任务里可能藏着某种"通用的推理本体论"，模型在学它而不是在背某个域的题。如果这个猜想成立，那"在哪个域自对弈"可能没那么重要——只要域足够可验证、足够丰富，学到的能力就能迁移。

同期定位上，AZR 和几个工作形成对照：和它最像的是 R-Zero（也是零数据自博弈），但 R-Zero 用两个独立模型（挑战者+解题者）分离优化，AZR 是单模型双角色联合更新；rStar-Math 用 MCTS 加小模型过程奖励做数学单域，仍依赖现成题；SPIN 这类自对齐微调目标是模仿人类分布，而 AZR 目标是超越人类题上限。AZR 站在"单模型、自出题、跨域"这个独特交叉点上。

07局限性与未来方向

论文自己很坦诚，几个明显的局限得说清楚：

  • 任务域受限。当前只能生成 Python 可执行代码任务，论文提出但未演示在 web、形式化数学、模拟器、物理世界的开放自改进。能不能搬出代码域，是它能不能真成"通用自博弈范式"的关键。
  • 确定性约束。只支持确定性程序，限制了可学任务范围——带随机性、状态依赖的任务它现在碰不了。
  • 验证器不够安全。禁用模块表加只跑 2 次执行，不等于安全沙箱和形式确定性。错误接受的提案会污染奖励；生产环境需要更强隔离（论文已集成 Sandbox-Fusion 作为更安全执行器，但离"绝对安全"还有距离）。
  • 基座依赖。Llama 3.1 8B 提升弱（16.0→19.2，反低于 SimpleRL 的 20.5），说明 AZR 受基座代码/反思能力制约。基座底子薄，自博弈也榨不出油水。
  • 规模与"超智能"动机的差距。审稿人 oKgA 指出，当前规模与论文摘要里"超对齐/超智能"的雄心之间仍有 gap——从 7B 到真超智能，路还长。

未来方向上，论文和后续社区工作指向几条：扩展到其他可验证环境（Lean/Isabelle 形式化证明、web 交互、物理模拟器）；对弱基座先做中间 SFT 再上 AZR（OctoThinker 思路）；探索对称或自适应的 proposer 奖励与熵正则。还有一条最值得追——也是最危险的——让模型不仅解题，还能自己提出全新的任务类型，从"在给定格式内自博弈"走向"自己发明新的博弈"。

08领域演进脉络

把 AZR 放回整条发展线上，脉络很清晰。第 001 篇 Transformer 立起"注意力即一切"，第 002–004 篇 BERT/GPT-2/GPT-3 把预训练范式跑通，第 005 篇 Chinchilla 定下算力最优配比——这一段都在回答"模型怎么练"。第 006 篇 InstructGPT 把对齐拉进来，第 024–028 篇 CoT/ToT/GoT 把推理范式种子埋下，到第 020 篇 o1 用 RL 训思维链、第 013 篇 DeepSeek-R1 证明纯 RL 能自发顿悟，推理范式正式起飞。

但 o1 和 R1 都有一个没明说的前提：题是人出的。第 021 篇 Scaling Test-Time Compute 把"测试时多想"的扩展定律立起来，第 022–023 篇过程奖励模型把"怎么打分"做细——这一支还在"人出题、模型学"的框架内。AZR 站在这个拐点上，把问题从"怎么用/训一个模型"翻到了"题从哪来"：它把题库来源也交给模型自己。

它和上一篇第 054 篇 Self-Play SWE-RL 几乎是同一时间、不同地点、各自把"自博弈"搬进了自己最熟的领域——SSR 搬进软件工程（裁判是测试执行器），AZR 搬进数学与代码推理（裁判是 Python 解释器）。这种"两个团队不约而同想到同一招"的巧合，往往意味着一个范式正在成型。下一篇，我们正好顺着这条线，去读 AZR 最直接的对照工作——R-Zero。

09趣味延伸

这篇论文的名字本身就是一个值得琢磨的梗。Absolute Zero（绝对零度）是个双关：物理学里绝对零度是分子运动降到最低的极限态，喻指 AZR 把外部依赖降到了最低；同时致敬 AlphaZero——从零开始自我对弈的那个传奇。所以这名字一口气点了两个题：既是"降到零外部数据"，又是"AlphaZero 的开放领域复刻"。有人通俗解释："这名字来自它从零外部数据起步——没有人写的题、没有数据集，只有 AI 和一个能检查它工作的工具。"

团队背景也值得一提。通讯作者 Gao Huang（黄高）是清华自动化系教授，Leap Lab（跃实验室）负责人——GitHub 组织名 LeapLabTHU 就来自这里。他是 DenseNet 的一作，在计算机视觉和高效网络设计上是知名人物，这两年把方向转到了推理与自进化。另一位通讯 Zilong Zheng（郑子龙）在 BIGAI（北京通用人工智能研究院）。所以这是一支清华系强推理组牵头的作品。

发表过程也挺有戏剧性。arXiv v1 在 2025 年 5 月 6 日挂上，第二天（5 月 7 日）就出了 v2，可见发布后迭代得飞快；v3 到 10 月 16 日。它最终被接收为 NeurIPS 2025 的 Spotlight（聚光灯论文，比普通录用更稀罕）。OpenReview 上还有个有意思的花絮：一位审稿人 oKgA 给了 5 分（满分录用），但末尾吐槽了一句"我不喜欢作者施压要更高评分的方式"——暗示作者在 rebuttal 里争取评分挺强势。但两位审稿人最后都因为 rebuttal 补充的 pass@512、MMLU-Pro、前沿难度实验主动提分。作者还很会做人，在 rebuttal 里专门点名感谢那位质疑的审稿人："正是审稿人的质疑引导我们发现 AZR 在高 pass@512 上也表现强劲"——把质疑转化成了亮点。

项目主页上还放了个出圈的 demo，叫"Spinning Hexagon Vibe Check"（旋转六边形氛围测试）：让 AZR-Coder-14B 写一个"旋转六边形里 10 个弹球碰撞"的 pygame 动画，并和 GPT-4o-mini、Qwen2.5-72B-Instruct、Qwen2.5-32B-Instruct 同台对比。结果 AZR 生成的代码物理碰撞最真实——一个零数据训练出来的 14B 模型，在这个"杂活"上压过了大它好几倍的指令模型。这种"小而精"的反差感，成了它在社区出圈的引子。

10个人解读与延伸思考

读完这篇，我最想提醒读者的一件事，和上一篇 SSR 一脉相承：别把"自博弈"当万能解药。AZR 能跑通，本质上是因为它恰好找到了一个"还算可靠的自动裁判"——Python 解释器。围棋的胜负是上帝定的，代码的对错是解释器定的；可一旦换到一个没有客观裁判的领域（开放式对话、创意写作、价值判断），自博弈就会撞上"谁来当裁判"的死结。AZR 的成功，有个不显眼但关键的前提：可验证环境存在。这个前提，不是所有领域都满足。

另一个值得琢磨的，是那个跨域泛化的谜。AZR 只在代码上自对弈，数学却大涨。一种猜想是：可计算任务里藏着某种"通用的推理骨架"——演绎、归溯、归纳这三种思维方向，本就是数学推理的底层操作。模型在代码上反复练"给规则推结果""给结果反推原因""从样例归纳规律"，等于把数学推理的"肌肉"也顺带练了。如果这个猜想成立，那 AZR 学到的就比"写代码"更广——它在学一种结构化的推理本体论。这跟 SWE-RL 当年发现的"软件训练让数学也涨"是同一个谜题的不同切面：可计算任务里到底藏着什么，让模型整体变聪明？这个问题，可能比"怎么训得更猛"更值得追。

最后留一个更远的联想。AZR 用 Python 当裁判，本质上是因为 Python 能"跑"——它有执行语义。那如果未来我们想要在"无法直接执行"的领域自博弈（比如科学假设的验证、策略的好坏），该怎么办？一种可能是：造一个"可执行的世界模型"当裁判——让 AI 自己学一个能模拟世界规律的模型，再用这个模型当裁判训练另一个 AI。这就从"自博弈"走向了"自建擂台"。听起来像科幻，但 AlphaZero 当年也是这么一步步从棋盘走到蛋白质折叠的。

留个问题给你 如果有一天，模型在所有"有客观裁判"的领域都自博弈到了极限，剩下的提升空间会不会全集中在"没有客观裁判"的领域？那时候，"谁来当裁判"会不会成为 AI 进化的下一个、也是最后一个瓶颈？欢迎你想一想，我们下一篇再见。
