大模型经典论文精读系列 #063

ReasoningBank: Scaling Agent Self-Evolving with Reasoning Memory ReasoningBank：把推理策略存进"记忆银行"——成功是存款，失败也是存款，agent 在测试时越用越聪明

作者：Siru Ouyang, Jun Yan, I-Hung Hsu, Yanfei Chen, et al. 机构：Google Cloud AI Research · UIUC · Yale 发表：2025-09 · arXiv 2509.25140 · ICLR 2026
arXiv GitHub

想象一位入职第一百天的员工：他知道打印室在负一层、知道给财务报销单前先找主管签"第三方审批"那一栏、知道上周那个"改个按钮颜色"的需求其实牵扯三个仓库。而隔壁那位 AI 助手，今天在购物网站上用了一个太宽泛的搜索词、被几百个无关商品淹死，明天遇到几乎一样的任务——又原样淹死一次。它入职了多少天，就"第一天"了多少天：不是它笨，是它没有"昨天"。

上一篇我们读完了 WikiSkill：agent 给自己写一本"维基"，把经验编译成知识、知识再长出技能。文末埋了一个悬念——Google 的另一支团队反其道而行：不写书，开银行。这一篇，我们就来兑现这场"维基 vs 银行"的对决。而比赛中最反直觉的发现是：这家银行里最值钱的存款，竟然是失败。

一句话总结 给 agent 开一家"记忆银行"：把每次任务（无论成败）的推理策略蒸馏成一张张"存单"，新任务来了按需检索、用完再存——不训练、不微调、不需要任何真实标签，agent 在纯测试阶段越用越聪明；再配上 MaTTS 缩放，"记忆"本身成为继参数、算力之后的第三条缩放曲线。

01领域定位

把本系列最近十篇连起来看，一条主线已经浮出水面：agent 如何不靠人喂数据、自己攒本事。Absolute Zero 让模型自博弈出题 (#55)，R-Zero 把出题人和解题人拆成两个模型 (#56)，OpenSkill、SkillAlchemy、MUSE-Autoskill 一路把"技能"从网上海选、证据准入、沉淀传承 (#59–#61)，直到 WikiSkill 把经验编译成一本永不回滚的维基 (#62)。

但这条线上的大部分工作都有一个共同前提：要有"训练"这一步——要么强化学习更新权重，要么 SFT 蒸馏新数据。ReasoningBank 把这个前提也扔掉了：权重一个字节都不动，全部发生在测试时（test-time）。任务像流水一样一件件到来，agent 一边干活一边把经验存进外挂的记忆库，干得越久越老练。它承接了"经验沉淀"的叙事，却又另辟一条零训练、纯检索的路线；更重要的是，它第一次把"记忆驱动的经验缩放"（memory-driven experience scaling）郑重其事地摆上台面——在大模型领域，一件东西被称为"新的缩放维度"，基本等同于拿到了一张长期饭票。

02研究背景

论文开篇戳破了一个行业默契的尴尬：agent 越来越多被部署在"持久岗位"上——长期挂机的客服、常年值守的运维助手、每天处理工单的编码 agent。它们天然会遇到一条源源不断的任务流。但现实是，绝大多数 agent 把每个新任务都当成孤岛处理，于是注定三件事：重复过去犯过的错、丢弃相关问题上攒下的洞察、永远无法随着时间变强。

"给它加个记忆不就行了？"——加记忆这件事，此前有两大门派。第一派存原始轨迹，代表作 Synapse：把整段交互历史原封不动塞回上下文，像新员工入职发一盘自己上周工作的完整录像带；第二派存成功例程，代表作 AWM（Agent Workflow Memory）：从成功轨迹里归纳出可复用的工作流，像把老师的操作步骤印成 SOP 合订本。作者毫不客气地指出这两派的两个死穴：

  • 提炼不出可迁移的"打法"：录像带和 SOP 都绑死了具体任务的具体步骤，换个网站、换个问法就对不上号；
  • 只存成功，不存失败：仿佛一家只进账不错账的账房——而 agent 自己踩过的坑，恰恰是它最了解、最不该浪费的信息。
类比 存原始轨迹，是给新司机发一箱行车记录仪硬盘；存成功工作流，是发一本《倒车入库九步法》。而老师傅带徒弟时真正传的，是那种一句顶一万句的心得："这个路口的左转道在右边，别信导航。"——高层的、可迁移的、带教训的推理策略，才是记忆该存的东西。ReasoningBank 这个名字起得也讲究：不叫 Memory Base，不叫 Knowledge Pool，偏偏叫 Bank（银行）——存款生息、越滚越多，取的时候还能挑最相关的一笔来花。

03核心问题

把背景压缩成一个问题：在任务流式到来、且没有任何真实标签的纯测试阶段，agent 如何从自己的成败轨迹中，自动蒸馏出可迁移的推理策略，并让这些策略真正被后续任务用上？

注意两个苛刻的约束。其一，"流式"：第 N 个任务来的时候，你不知道第 N+1 个是什么，记忆只能边干边攒；其二，"无标签"：不像训练数据有标准答案，测试时没人告诉你刚才那单干得对不对——agent 必须自己给自己发"绩效评定"。

思考一下 先别往下翻。一家记忆银行如果要接纳"失败轨迹"入库，第一个技术障碍是什么？——没有标签，agent 怎么知道某次交互算失败？就算判出来了，把"我是怎么错的"存起来，对下一个任务真的有正收益，还是只是往库里灌噪音？记住你的答案，我们到实验部分对账。

04方法详解

ReasoningBank 的整体设计有一种"刻意做减法"的美感：整个框架只有一张存单格式、三个闭环步骤、外加一个缩放开关。作者在脚注里专门声明——检索和巩固环节故意用最朴素的实现，好让所有增益都能归因于记忆内容本身。

第一步：定好存单格式（Memory Schema）

每条记忆项是一张三段式的"存单"：标题（title，一句话点破核心策略，相当于存单上的户名）、描述（description，一句话摘要，柜员扫一眼就知道这笔钱是什么来路）、内容（content，蒸馏出的推理步骤、决策依据或操作要点，即本金）。关键设计在于：存的是打法而不是过程——"这个网站的高级搜索藏在哪里"这种执行细节被刻意抽象掉，留下"先收窄搜索范围再动手"这类换一个网站也成立的策略。

第二步：跑通存取闭环（Retrieval → Extraction → Consolidation）

新任务到来时，agent 先用嵌入相似度在记忆库里检索最相关的经验（默认只取 top-1，对，就一条），把存单内容注入系统指令，并附上一句很有分寸感的话："这些是我过去积累的经验，你觉得相关就用，不相关就忽略。"

任务做完后，进入整个框架最精彩的一步——提取。首先，LLM-as-a-Judge 出场：同一个模型换上裁判的身份，只看任务描述、交互轨迹和最终状态，输出"成功/失败"的二值判定，全程不需要任何真实标签。然后按判定结果分两条提取路线：

  • 成功轨迹：追问"为什么会成"，把偶然踩中的好运和真实有效的策略区分开，提炼出验证过的打法；
  • 失败轨迹：追问"为什么栽了"，做反事实反思，提炼出预防性教训——"下次遇到类似情况，先别这么干"。

每条轨迹最多提取三条记忆项（防止存单泛滥），最后简单地追加进记忆库——不剪枝、不去重、不合并。用公式写出来，这个闭环朴素得近乎天真：

$$\mathcal{M}_{t+1} \;=\; \mathcal{M}_t \;\cup\; \text{Extract}\big(\text{Judge}(\tau_t),\,\tau_t\big), \qquad a_{t+1} \sim \pi_{\mathcal{L}}\big(\cdot \,\big|\, \text{TopK}(\mathcal{M},\,q),\, q\big)$$ (1)

左边是"干完活存钱"：第 $t$ 个任务的轨迹 $\tau_t$ 先过裁判，再按成败分路提取，并入记忆库 $\mathcal{M}$。右边是"接活先取钱"：新任务 $q$ 来了，检索最相关的几条记忆，作为额外指令喂给策略 $\pi_{\mathcal{L}}$。一存一取，就是 ReasoningBank 的全部。

第三步：给银行配一台"复利机"（MaTTS）

到这里，ReasoningBank 已经是一家能自我造血的银行了。但作者往前多推了一步：测试时缩放（test-time scaling）——就是 o1 那套"给更多算力多想一会儿"的思路（本系列 #20、#21）——能不能和记忆搭出化学反应？

直接组合的问题在于浪费：朴素做法（vanilla TTS）让同一道题跑 $k$ 条轨迹，每条独立入库，彼此老死不相往来。可"同一道题的五种解法"之间最宝贵的东西恰恰是对比信号——为什么路径 A 成了、路径 B 栽了？差在哪一步？于是作者提出 MaTTS（Memory-aware Test-Time Scaling），两种玩法：

  • 并行缩放：同一任务并行走 $k$ 条轨迹，然后让模型做"自我对比"（self-contrast）——多条轨迹摆在一起找共性、挑出偶发的侥幸解，再统一提炼入库。像棋手复盘时把五盘棋谱摊开对照着看。
  • 串行缩放：一条轨迹走完不打烊，迭代"自我精炼"（self-refine），而且精炼过程中写下的中间检查笔记也一并入库——那些没进最终答案的中间推理、半途的纠错，全是有价值的一手信号。

05实验结果

实验覆盖两大场景、三个基准：网页浏览（WebArena 684 个任务、Mind2Web 1341 个任务）和软件工程（SWE-Bench-Verified 500 个真实 GitHub issue），三个骨干模型（Gemini-2.5-Flash / Gemini-2.5-Pro / Claude-3.7-Sonnet）。先看总账：

基准 · 骨干模型无记忆最强基线ReasoningBank+MaTTS
WebArena 整体 · Flash40.544.1 (AWM)48.851.8
WebArena 整体 · Pro46.747.7 (Synapse)53.956.3
WebArena 整体 · Claude-3.741.742.6 (Synapse)46.348.8
SWE-Bench-Verified · Flash34.235.4 (Synapse)38.8—
SWE-Bench-Verified · Pro54.053.4 (Synapse)57.4—
WebArena-Shopping · Gemma-3-12B17.121.4 (AWM)24.1—

三个骨干模型上整体成功率最高提升 8.3 个百分点（相对提升约 20%），而且在需要跨网站迁移的 Multi 子集上，AWM 不仅没赚到还倒贴，ReasoningBank 却稳定增益——策略级记忆的迁移性肉眼可见。更有意思的是最后一行：换上区区 12B 的开源小模型 Gemma-3，成功率从 17.1 拉到 24.1（相对提升 41%）。模型越小，记忆越香——这对算力紧张的开发者是个大好消息。

但真正的重头戏，是回答开头思考题的两张"对账单"。

对账单一：失败存款到底值不值钱？

在 WebArena-Shopping 上做消融：只用成功轨迹建记忆 vs 成败兼收。结果相当戏剧化：

记忆方法只存成功成败兼收结论
Synapse（存原始轨迹）40.641.7失败基本是噪音
AWM（存成功工作流）44.442.2失败反而有毒 ↓
ReasoningBank46.549.7失败是正资产 ↑

同样一批失败轨迹，放进别人家记忆里是毒药，放进 ReasoningBank 里是补药。差别就在提取环节：Synapse 和 AWM 只会原样复读或归纳流程，失败轨迹里的错误操作也被当成"经验"复述出去；而 ReasoningBank 对失败走的是反事实反思路线，存进来的不是"我干了什么"，而是"下次别这么干"。失败存款的利息，取决于你怎么记账。

对账单二：记忆和缩放，谁放大谁？

MaTTS 的缩放实验（WebArena-Shopping，缩放因子 $k$ 从 1 到 5）给出了一个漂亮的双向验证。看 BoN（五条轨迹里挑最好）这一头：记忆越好，算力越不白花——无记忆时五条轨迹只把 39.0 抬到 42.2；配上 ReasoningBank，同样五条轨迹能抬到 55.1。再看 Pass@1（记忆巩固后随机抽一条的平均质量）这一头：缩放反过来也喂养记忆——Synapse 和 AWM 在缩放下几乎原地踏步（40.6→41.2、44.4→45.5），ReasoningBank 却从 49.7 涨到 53.0。弱记忆配多算力是收益递减，强记忆配多算力是复利循环。

还有三张让人踏实的补充账单

裁判判错了怎么办？实测 LLM-as-a-Judge 与真实标签的一致率只有 72.7%——接近三成的判定是错的。但把裁判准确率从 100% 一路人为压到 50%（瞎猜），ReasoningBank 的表现在 70%–90% 区间几乎纹丝不动。策略级的存单自带容错：一次误判混进来的坏经验，会被后续大量正确经验稀释掉。

记忆库越满越好吗？恰恰相反：检索 top-1 时成功率 49.7，top-2 掉到 46.0，top-4 只剩 44.4。记忆贵精不贵多——塞太多相关度不足的存单进上下文，反而互相打架。

要花多少钱？每任务的 token 开销只比无记忆基线多 4.3%（五万出头的 token），换来 20.5% 的性能提升；交互步数平均省 1.6 步，其中成功案例省得最多（购物场景 6.8 步 → 4.7 步，相对减少 26.9%）。也就是说，这钱主要不是靠"少走了弯路"省出来的，而是从一开始就走对了路。

06影响与意义

这篇论文被 ICLR 2026 接收，但它真正的影响在于立起了一块路牌。参数缩放（把模型变大）和算力缩放（让模型多想）之后，ReasoningBank 给出了第三条正交的增长曲线：经验缩放（让模型多攒）——前两条都要烧钱，这一条几乎免费：轨迹反正已经跑出来了，多蒸馏几条存单而已。

它同时给"测试时学习"（test-time learning）这个范式补上了关键一环：o1 证明了推理时多算有用，但它每次任务之间是失忆的；ReasoningBank 证明了跨任务的测试时积累同样有用，且不需要任何梯度更新。论文发表后短短半年，跟进工作已经排起队：Agent KB 把经验库扩成跨框架共享，TAME 研究记忆进化的安全护栏，EvoMemBench 专门给"自进化记忆"立了新基准。一个研究方向成熟的标志，是它开始有了自己的对照组和 benchmark。

07局限性与未来方向

作者在附录里罕见地坦诚，把家底亮了个干净。三个主要局限：

  • 只管"存什么"，不管"怎么管"：检索是最朴素的嵌入相似度，巩固是简单追加——没有合并、没有去重、更没有遗忘。库越来越大之后怎么办，论文没答案（但MaTTS 的对比信号和后续的去重工作指了方向）。
  • 裁判是软肋：整个闭环的地基是 LLM-as-a-Judge 的自我评定。虽然实验证明它对噪声鲁棒，但在真正模糊的任务上，系统性误判仍可能让错误经验滚雪球。
  • 存单之间不组合：每条记忆项独立检索、独立使用，没有"把几条小策略拼成一个大策略"的机制。作者在展望中自己给出了路线图：按 planning / tool-use / operational / user-centric 分类的模块化记忆、episodic + working + long-term 的分层记忆栈、会分解查询多跳检索的推理密集型检索器——这基本就是下一代记忆系统的招标书。

08领域演进脉络

借着图 1，把整个系列串一遍：Transformer 奠定了架构地基 (#001)，BERT 与 GPT-2 确立了预训练范式 (#002–003)，GPT-3 用规模化撞开了涌现之门 (#004)，Chinchilla 校准了"模型与数据的最优配比 (#005)，InstructGPT 用人类反馈完成对齐 (#006)，LLaMA 点燃开源燎原之火 (#007–012)。随后是推理范式时代：CoT 点火 (#024)，o1 引爆 (#020)，测试时算力缩放定型 (#021)。再往后，舞台交给 agent：从 ReAct 的推理-行动循环 (#035) 到 SWE 系列的工程化 (#047–052)，再到自进化主线——自博弈出题 (#055)、技能炼金 (#059–061)、知识编译 (#062)。

ReasoningBank 站在这条长河的当前位置，做的事情可以一句话概括：把"进化"从训练时搬到测试时，把"经验"从数据集变成银行账户。它之前的进化要动权重（贵、慢、危险），它之后的进化只需要动一份 JSON 文件（便宜、即时、可回滚）。 WikiSkill 用"维基"回答了"经验沉淀成什么"，ReasoningBank 用"银行"回答了"经验如何被使用"——静态编译对动态检索，这一组对偶将在 2026 年被反复讨论。而它抛出的"经验缩放"概念，大概率是接下来几年 agent 领域最热的关键词之一。

09趣味延伸

论文里最迷人的发现，藏在分析章节：一条记忆的一生。研究者追踪了名为 User-Specific Information Navigation（按用户信息导航）的记忆项在整个测试过程中的演化，发现它像生物一样逐级进化：最初只是一条呆板的程序性策略（"去找导航链接"）；几轮任务后长出自反思（"核对一遍用户 ID 再动手，免得搞错对象"）；再往后学会自适应检查（"动手前先系统性地用一遍搜索和过滤器，确认没有遗漏"）；最终成熟为组合策略（"交叉对照任务要求和当前选项，重新评估后再决策"）。作者特意指出，这种从低级动作到高级推理的演化曲线，像极了强化学习的学习动态——但全程没有一次梯度更新。进化不必写在权重里，也可以写在一份记忆清单上。

三个官方案例也各有味道。其一，用户问"我最早的一笔订单是哪天"，无记忆的 agent 只看了"最近订单"表格就作答，ReasoningBank 凭着"翻完整历史再回答"的存单找对了答案——它记得的不是这个网站，而是"别被表面入口骗了"这类元策略。其二，一个重度导航的购物任务，基线 agent 跌跌撞撞走了 29 步，ReasoningBank 靠着"分类过滤"的旧经验 10 步收官。其三最妙：某次失败的搜索（关键词太宽，返回一堆无关商品）被反思成两条新存单——"优化搜索词"和"善用功能过滤器"——同一个坑，再也没踩过第二次。

再看作者名单，也是一场小小的学术联谊：Google Cloud AI Research 领衔，UIUC 的韩家炜（Jiawei Han）——数据挖掘领域泰斗级人物——压阵，一作 Siru Ouyang 正是韩组博士生，Yale 的 Xiangru Tang 也在列（这位作者马上会在下一篇论文里以一作身份登场，此处按下不表）。致谢里还留了一句："感谢 Jiao Sun、Jing Nathan Yan 和 Google Cloud AI Research 的同事们"——一篇十八位作者的论文，致谢只有短短三行，倒是很有 Google 内部论文的极简风。

10个人解读与延伸思考

上一篇 WikiSkill 我们算过"知识复利"的账，这一篇的账更极端：token 开销 +4.3%，性能 +20.5%。参数缩放的边际成本以亿计，算力缩放按 token 收费，经验缩放几乎免费——因为它的原料（轨迹）本来就是生产过程的副产品，不捡白不捡。三家银行抢的不是你的存款，是你的废水：谁先建好回收管道，谁就有下一代的自来水。

"失败比成功更值钱"这个发现，也值得所有人（包括人类）重读一遍。Synapse 和 AWM 的失败证明了：失败经验的价值不在"记录"而在转译——把"我干了什么"翻译成"下次别这么干"，错误才从噪音变成护栏。这几乎就是人类教育学的老结论（负例划定概念边界），在 agent 身上重新验证了一次。顺带一提，如果你在自己的 agent 项目里做过 retry 日志、踩坑文档，恭喜，你早就手工运营着一家 ReasoningBank——只是你的"提取 prompt"还没写进系统罢了。

剩下的问题同样值得警惕：记忆银行开了，可谁来当银保监会？论文证明了它对裁判噪声鲁棒，但没回答——当错误记忆被 MaTTS 的复利飞轮放大时，上限在哪里？系统性的自我强化偏差，会不会让一家银行变成庞氏骗局？TAME 等后续工作已经开始给记忆进化加装安全审计，这个方向才刚刚开始。

留个问题给你 ReasoningBank 的记忆是"一个人"的银行：同一个 agent 自己存、自己取。那如果允许跨用户、跨 agent 共享记忆呢？一个用户深夜踩过的坑，能让千里之外另一个 agent 白天绕道走——这听起来像天堂。但当记忆可以流通，恶意的"错误经验"是不是也像假钞一样可以注资污染整家银行？如果未来出现"记忆市场"——高手 agent 的成功存单挂牌出售——定价该按成功率，还是按可迁移性？你会买谁的记忆？
