Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory Mem0：给 AI 记忆做减法——不造操作系统，把对话蒸馏成几条关键事实，LOCOMO 上领先 OpenAI Memory 约 26%

作者：Prateek Chhikara, Dev Khant, Saket Aryan, Taranjeet Singh, Deshraj Yadav 机构：Mem0, Inc. 发表：2025-04 · arXiv 2504.19413
arXiv GitHub Project

周一早上，你告诉自己的 AI 助手："我是素食主义者，不吃奶制品。"它礼貌地记下了。周三晚上，你问它："晚饭吃点什么好？"它兴冲冲地回答："推荐香煎鸡胸肉，高蛋白又低脂！"——这不是段子，这是 Mem0 论文开篇第一张插图里画的真实场景，也是几乎每个用过长对话 AI 的人都体验过的"AI 式失忆"。

民间流传一个梗：金鱼的记忆只有 7 秒。但跟大模型比起来，金鱼简直是记忆冠军——金鱼好歹能记住 7 秒，而 LLM 每开一个新会话，过去的一切直接归零，连"你叫什么"都要重新问。上一篇我们讲了 MemGPT：让 LLM 自己当操作系统，把全部对话历史像虚拟内存一样换页管理。今天这篇走的是截然相反的哲学：不造操作系统，直接做减法——把浩如烟海的对话蒸馏成几条关键事实，剩下的统统丢掉。而这篇论文的副标题里藏着一个刺眼的词：Production-Ready——学术圈谈记忆，第一次把"能不能上生产"当成了及格线。

一句话总结 把每轮对话"蒸馏"成几条关键事实，再让 LLM 自己当档案管理员，对记忆库执行 ADD / UPDATE / DELETE / NOOP 四种整理操作——用比全上下文低 91% 的 p95 延迟、省 90% 以上的 token 成本，在 LOCOMO 长对话基准上把 OpenAI 自家的 Memory 系统甩开约 26%。

01领域定位

在本系列的"记忆管理期"里，Mem0 是继 MemGPT 之后的第二篇，但它代表的路线几乎是 MemGPT 的镜像。MemGPT 是"全存派"：像操作系统一样把所有历史保留在"磁盘"上，用的时候再换页进上下文——信息不丢，但管理复杂、成本高昂。Mem0 是"提炼派"：像人类做笔记一样，只把对话中真正重要的事实留下来，并且持续整理——新卡片入库、旧卡片改写、过时卡片作废、重复卡片跳过。

这篇论文的位置感还体现在它的出身：Mem0 不是高校实验室的产出，而是一家创业公司（同名公司 Mem0, Inc.）的产品化论文。它要回答的问题不是"记忆能不能做"，而是"记忆能不能做成一个又准、又快、又便宜的基础设施层"。也正因为这个出身，它第一次把 p95 延迟和 token 成本放到了与准确率同等的地位——这直接改变了后来所有记忆系统的评测姿势。

02研究背景

论文要解决的困局，一句话就能说清：LLM 的上下文窗口是固定的，而人与 AI 的关系是无限的。用户与助手的信任往往要靠数周、数月的互动慢慢积累，而每一次重新打开会话，模型都是一张白纸——忘了你的饮食偏好、忘了上周定的计划、甚至忘了自己上周给过的承诺。

在 Mem0 之前，业界有三条主流应对路线，论文把它们逐一拆解：

  • 路线一：堆上下文。GPT-4 有 128K token，o1 有 200K，Gemini 号称冲到 10M。但窗口再大也只是"延缓死亡"：几周的历史必然撑爆窗口；而且人类对话不按话题排序——你的素食宣言可能埋在几小时的编程讨论中间，注意力机制对远距离 token 还会衰减（所谓 lost in the middle），塞进去不等于看得见。在 LOCOMO 基准上，全上下文方法的 p95 延迟高达 17.1 秒——一句话问出去，咖啡都凉了。
  • 路线二：RAG 存原文。把对话切块、向量化，需要时检索回大段原文。问题是检索回来的往往是一大坨带噪声的"历史现场"，模型还得从里面自己淘金——检索的是"原文"而不是"事实"，信噪比天然吃亏。
  • 路线三：MemGPT 式全存。上一篇讲过的操作系统隐喻，信息一条不丢。但要把全部历史管理起来，意味着持续的换页、摘要和自编辑负担，架构复杂度直接对齐一个真正的 OS。
类比 · 录音机 vs 笔记本 人类从不靠"记住每句话"来维持一段关系。你不会记得上周三 14:32 客户说的每一个字，但你牢牢记得"王总不喜欢周五开会""李姐对花生过敏"。人脑不是录音机，而是一边听、一边总结、一边改写笔记的记录员：重要的写下来，过时的划掉，重复的不记第二遍。Mem0 的全部思想就藏在这个类比里——既然 LLM 上下文有限，那就别让它背录音机，给它一个笔记本。

要在学术上验证这件事，需要一个足够"狠"的基准。论文选了 LOCOMO：多段超长多会话对话，用户随口聊旅行、美食、工作、健身，横跨数月；随后用四类问题拷问系统——单跳（"我的自行车是什么牌子？"，查一个事实）、多跳（"我去过的所有城市里哪个最靠南？"，串联多处信息）、时间（"我是什么时候搬的家？"，涉及先后顺序）、开放域（"描述一下我的饮食习惯"，归纳偏好）。每段对话约 2.6 万 token——正好是"上下文塞得下、但塞得很痛苦"的量级。

03核心问题

把背景压缩成一个问题：如何让 AI 记住该记的、更新过时的、忘掉作废的，同时把延迟和成本压到生产系统可以接受的水平？

这个问题前半句是认知科学（记忆的选择与整理），后半句是工程学（性能与成本）。Mem0 的答案是把两者焊成同一条流水线——这也解释了为什么这篇论文读起来一点都不"学院派"：它的每一个设计决策，都对应一次生产事故式的灵魂拷问。

思考一下 先做个思想实验：全上下文方法明明保留了 100% 的原始信息，Mem0 只保留了蒸馏后的一小撮事实——按理说"记得越多答得越准"才对。可为什么在 LOCOMO 上，信息更少的 Mem0 反而把全上下文和 RAG 都打赢了？先猜一猜，答案在实验部分揭晓。

04方法详解

Mem0 的处理单位不是"整段对话"，而是增量式的消息对：每当一轮新交互完成（用户消息 $m_{t-1}$ + 助手回复 $m_t$），系统就被叫醒一次，走一条两阶段流水线——提取（extraction）与更新（update）。

阶段一：提取——这轮对话里有什么值得记住的？

只看新消息对容易断章取义，所以 Mem0 给提取函数 $\phi$ 喂了三样东西：一份异步刷新的全局对话摘要 $S$（知道"我们整体在聊什么"）、最近 $m$ 条历史消息（保留细节的温度），再加上新的消息对本身：

$$P = \bigl(S,\ \{m_{t-m},\dots,m_{t-2}\},\ m_{t-1},\ m_t\bigr)$$ (1)

LLM 据此产出一组候选事实：

$$\Omega = \phi(P) = \{\omega_1, \omega_2, \dots, \omega_n\}$$ (2)

注意一个精巧的工程设计：摘要 $S$ 的刷新是异步模块，在后台周期性更新，完全不阻塞主管线——这是典型的"生产思维"，学术论文里很少为这种事专门花笔墨，但工程上它决定了系统会不会"卡壳"。

阶段二：更新——每条新事实，对旧记忆做什么？

候选事实不能直接入库，否则记忆库迟早变成垃圾场。对每条候选事实 $\omega_i$，系统先从向量数据库里捞回语义最相近的 top-$s$ 条既有记忆，然后把"新事实 + 相似旧记忆"一起打包、通过 function-calling 接口交给 LLM 裁决。LLM 不是被动的存储器，而是一个手持四枚印章的档案管理员：

  • ADD：库里没有相关内容——新卡片入档。比如"我下个月要去东京出差"。
  • UPDATE：旧卡片需要补写。库里写着"我住北京"，新消息说"我搬到上海了"——改卡片。
  • DELETE：新事实与旧记忆矛盾且旧记忆已作废。"我不再吃素了"——把"用户是素食者"撕掉。
  • NOOP：新事实是重复或无关紧要的——什么都不做，原样放回。

升级款：Mem0g——当记忆变成一张图

基础版 Mem0 把每条记忆当作独立的"卡片"。但现实对话里的信息是互相勾连的："用户 住在 上海""用户 偏好 素食""素食 属于 饮食习惯"——这类关系结构用扁平卡片表达不好。于是论文提出图变体 Mem0g：用实体抽取器找出对话中的人、物、偏好，用关系生成器为它们之间连上有标签的有向边，存进图数据库（Neo4j）。查询时双路并行——向量检索捞"相似事实"，图检索走"关系路径"，两路证据合起来回答。

直觉上，图结构对多跳问题（需要串起好几个事实）和时间问题（涉及事件先后）应该更友好——实验部分我们会看到，直觉只对了一半，这个"一半"恰恰是全文最有意思的发现之一。

05实验结果

主战场是 LOCOMO，主指标是 LLM-as-a-Judge（J 值，由强模型当裁判给回答打分），外加 F1；同时报告两类部署指标：p95 延迟与 token 成本。对手阵容豪华：既有 LOCOMO 榜上的老牌记忆系统（ReadAgent、MemoryBank、MemGPT、A-Mem），也有各种配置的 RAG，还有全上下文、开源记忆方案 LangMem、OpenAI 的 Memory 产品，以及平台型选手 Zep。

数字会说话，但有三个发现值得单独拎出来讲——

发现一：信息更少，答案更准

这就解开了开头的思考题：全上下文把约 2.6 万 token 的原始对话原封不动塞给模型，其中 99% 与当前问题无关，注意力被海量噪声稀释，关键事实反而"看不见"；RAG 检索回来的也是大段原文 chunk，噪声同样不小。Mem0 只把蒸馏好的高信噪比事实放进上下文，模型的每一次推理都在"纯净素材"上进行。记忆系统的胜负手不在"存了多少"，而在"检索回来的是什么质量的东西"。

发现二：图记忆不是全面碾压，而是各管一段

很多人（包括论文作者自己）预期 Mem0g 会全面超越基础版。结果很微妙：总分确实涨了 1.56（68.44 vs 66.88），但单跳和多跳反而略降——图结构引入了噪声和不相关实体；涨分来自时间推理（58.13 vs 55.51）和开放域（75.71 vs 72.93）。图的收益兑现了"关系推理"的承诺，代价是简单问题的干扰项变多了。这个诚实的发现比一味吹嘘"图更高级"有价值得多。

发现三：用你的剑，打败你

所有方法统一用 GPT-4o-mini 级别的模型做底座。也就是说，Mem0 用 OpenAI 自家的模型，在长对话记忆这个科目上把 OpenAI 的 Memory 产品甩开了约 26% 的相对分差（66.88 vs 约 53）——相当于在对手最引以为豪的科目上，用对手的剑赢了对手。这也侧面说明：产品里的记忆系统，瓶颈从来不是模型不够聪明，而是记忆管理这一层没做对。

06影响与意义

第一，"记忆层"由此成为一个独立品类。Mem0 之前，记忆功能大多内嵌在各家 agent 框架里，是一个"附带品"；Mem0 之后，记忆开始被当作像数据库一样的基础设施来讨论——独立的产品、独立的 API、独立的评测。今天"Memory for AI Agent"已经是一个有了专门创业赛道、专门开源项目、专门融资故事的领域。

第二，评测范式的改变。Mem0 把 p95 延迟和 token 成本放进了主结果表，等于宣告：只报准确率的记忆论文是不完整的。此后 LangMem、A-Mem、A-MAC 等几乎所有跟进工作，都开始同时报告"准确率 + 延迟 + 成本"三件套——这套今天看来的"标配"，很大程度上是 Mem0 定下的规矩。

第三，LOCOMO 成为记忆系统的竞技场。这篇论文把 LOCOMO 的四类问题拆解、复现、公开，后来者（包括对手 Zep）纷纷在同一基准上刷分、质疑、再刷分。2025 年下半年到 2026 年，围绕 LOCOMO 的记忆军备竞赛愈演愈烈，各家自报成绩从 67 一路卷到 90+——一个基准带火一个赛道，这在大模型史上并不新鲜，但由一篇创业公司论文完成，并不常见。

第四，开源生态。mem0 的开源库迅速成为 GitHub 上最流行的记忆框架之一，几行代码接入、可插拔的后端存储、平台化托管——"研究论文 + 生产可用开源库 + 商业化平台"三件套的组合，为"记忆即服务"这一商业模式跑通了从 0 到 1。

07局限性与未来方向

这篇论文的局限，和它的优点一样鲜明：

  • 抽取质量决定一切，但抽取可能出错。整条流水线的地基是"LLM 能正确蒸馏事实"。一旦模型抽错、漏抽、幻觉出一条"假事实"并通过了更新阶段，错误就会被永久写进记忆库，并在后续对话中被反复引用——记忆污染是所有提炼派系统的阿喀琉斯之踵。
  • 图构建的隐形成本。Mem0g 的每轮交互都要做实体抽取和关系生成，图越大维护越贵；论文报告的延迟未完全展开讨论大规模图下的检索退化。
  • 基准的局限。LOCOMO 的对话虽然长，但任务分布相对友好（多为偏好、日程类事实）；对真正的"多源冲突信息""跨年长期记忆"，基准的代表性有限。
  • 自报成绩的口径问题。论文由 Mem0 公司发表、在自选基准上对比商业化对手，天然有"既当运动员又当裁判"的嫌疑。2026 年各家在 LOCOMO 衍生榜单上的自报数字已经卷到 90%+，口径不一、互不认可——这是这条赛道甜蜜的烦恼，也是必须直视的信任赤字。

最有趣的后续反转来自 Mem0 自己：2026 年 4 月，公司发布的新一代平台算法砍掉了 UPDATE 和 DELETE，只保留 ADD——新事实一律新增，旧信息靠检索时的多信号混合排序来"盖过"，叠加内置的实体链接。某种意义上，论文里精心设计的"四印章档案管理员"被自家下一代产品简化成了"只进不出的仓库 + 聪明的检索员"。这不是自我否定，而是一个耐人寻味的行业信号：记忆管理没有银弹，每一代设计都是在"整理成本"与"检索成本"之间重新画线。

08领域演进脉络

把镜头拉远，AI 记忆这条线在本系列里已经走了很长：MemGPT（2023-10，第 66 篇）以操作系统隐喻开山，主张"全存 + 换页"；此后记忆方向一度沉寂——因为所有人的注意力都被推理范式吸走了；到了 2025 年初，A-Mem、Zep、LangMem 几乎同时冒头，记忆赛道重新拥挤；Mem0（本篇）以"提炼 + 四操作 + 生产指标"给这条路线立了标杆；再往后，MemOS（第 65 篇）试图把 OS 隐喻复兴成真正的"记忆操作系统"，而 2026 年的记忆层正在走向 MCP 式的标准化，并与我们在"经验复利期"讲过的技能库、经验银行（WikiSkill、ReasoningBank、Agent KB）逐渐合流——记住事实与积累经验，本就是同一枚硬币的两面。

本篇在这个脉络里的坐标非常明确：它是"减法路线"的宣言书。在它之前，讨论记忆默认讨论"怎么保留更多信息"；在它之后，讨论记忆默认讨论"怎么又准又轻又便宜"。一次视角的翻转，往往比一个新算法更能改变一个领域。

09趣味延伸

名字里的彩蛋。Mem0 读作 mem-zero——"memory" 的前四个字母加一个零，官方解释是"从零开始，给 AI 造记忆"。一个把"遗忘"写进名字（零）的记忆系统，起名就已经把哲学说完了。

两封创业剧本。创始人 Taranjeet Singh 原本是印度金融科技独角兽 Khatabook 的增长工程师，2022 年底 ChatGPT 浪潮初起时辞职，2023 年 6 月写下开源 RAG 框架 Embedchain，攒下 8000+ GitHub stars。为了推进项目，他给投资人发了 200 多封冷邮件。后来他与老友 Deshraj Yadav（两人更早一起维护过开源评测平台 EvalAI——一个"开源版 Kaggle"）创办 Mem0，2024 年 1 月进入 Y Combinator，次年完成由 Peak XV、Basis Set 等参投的 2400 万美元融资。从开源项目到独角兽赛道，这条路径本身就是大模型时代创业的标准剧本之一。

"用你的剑打败你"的名场面。论文实验里所有方法共用 OpenAI 的模型做底座——Mem0 用 GPT-4o-mini 的智力水平，在记忆科目上把 OpenAI 自家 Memory 产品甩开约 26%。这个故事后来在圈子里流传甚广，因为它戳破了一个隐含的傲慢：模型厂商自己做的记忆，未必比一个创业公司在"记忆管理层"下功夫做得好。隔行如隔山，模型能力和记忆架构是两门手艺。

10个人解读与延伸思考

读完全文，我最深的感受是：Mem0 表面上做的是减法，本质上做的是"选择"。它最大的贡献不是某个模块或某个指标，而是把一个认知科学的老命题摆上了工程台面——智能不在于记住多少，而在于知道该忘掉什么。人脑的遗忘曲线从来不是缺陷，而是检索效率的守护者：遗忘为重要的东西腾出了空间。LLM 的上下文窗口越大，业界越容易陷入"全都塞进去"的惰性，而 Mem0 证明了主动遗忘——而且是带整理的遗忘——才是真正可持续的答案。

另一个值得咀嚼的点是它的产品姿态。传统学术叙事里，"创业公司论文"常被默认为低严谨度；但 Mem0 反过来提醒学界：延迟和成本这些"工程俗物"，恰恰是学术评测长期缺席的关键维度。一个能改变行业评测规范的"俗"贡献，未必比一个漂亮的新算法分量轻。

往前看，记忆层与经验层正在合流：记住"用户是素食者"（事实记忆）与记住"先检索再回答效果更好"（经验记忆），最终可能由同一套基础设施承载。而 MCP 式的协议标准化，正在让"记忆"变成即插即用的服务——就像关系数据库从应用里独立出来那样，记忆即服务的基础设施之争，才刚刚开局。

留个问题给你 如果由你来设计一个给 AI 用的记忆系统：你会允许它删除用户的记忆吗？比如用户说"我不再吃素了"，系统该"撕掉"旧卡片，还是把两张卡片都留着、让检索时自己判断？如果一条记忆被错误地删掉了，谁该负责——抽取的模型、裁决的模型，还是平台的运维？欢迎带着这个问题，去读下一篇走"时间轴"路线的对手论文。
