Kimi k1.5: Scaling Reinforcement Learning with LLMs Kimi K1.5：把上下文当算力来"扩"——128K 长思考 RL + 长短蒸馏，推理的另一条路

作者：Kimi Team (Moonshot AI) 机构：Moonshot AI（月之暗面） 发表：2025-01 / arXiv 技术报告
arXiv Project

上回说到，2025 年 1 月 20 日，DeepSeek-R1 把 OpenAI o1 的推理黑箱砸开了一道缝：不用任何思维链示范，纯靠"答案对不对"的强化学习，模型自己就学会了反思与验证。故事到这里，似乎已经迎来了一个干脆利落的结局——RL，就是答案。

可仅仅两天后，1 月 22 日，北京另一支团队把第二份答卷拍上了 arXiv。他们做的是同一件事——追平 o1，但给出的回答几乎处处相反：他们认真做了 SFT 冷启动，认真设计了奖励，认真写了基础设施，并且抛出一个 R1 没怎么强调的论断——推理的瓶颈不是算法不够巧，而是模型"想"得不够久；把上下文窗口拉到 128K，问题就解决了一大半。这份报告叫 Kimi K1.5。两份答卷，两条路，同一个月，同一个对手。推理模型的拼图，至此才真正完整。

一句话总结 Kimi K1.5 把强化学习的上下文窗口扩到 128K，用"部分回放"让超长思考训练变得付得起，再用"长2短"蒸馏把长思考的本事塞回快答小模型——不靠搜索树、不靠价值函数、不靠过程奖励模型，就追平了 OpenAI o1。

01领域定位

这个系列走到第 13 篇时，推理范式的大门刚刚被 R1 推开。但一扇门被推开，往往意味着里面还有好几条岔路。R1 选的是"极简纯 RL"——能省则省，看涌现。Kimi K1.5 选的是另一条岔路：把上下文长度当成第一性的扩展轴，然后用工程把它做扎实。

它的位置很特殊。往上接，它继承的是 DeepSeek-V3 那条"开源高效基座"的性价比脉络，也接住了 o1 抛出的"test-time scaling"命题；往下开，它给后来的推理模型示范了一种可复制的工程范式——长上下文 RL 是可行的，只要你能把超长序列的训练成本压下来。它和 R1 一起，把 2025 年"推理范式期"的版图从"有没有人能复现 o1"推进到"复现有几条路、各有什么取舍"。

02研究背景

要理解 K1.5 为什么把宝押在"上下文长度"上，得先看清 2024 年底推理领域的两个心结。

第一个心结是 scaling law 的天花板。从 GPT-3 到 Chinchilla，预训练靠的是"模型更大、数据更多"，可这条路撞上了一堵墙：高质量预训练数据快被用完了。继续堆参数、堆 token，收益越来越钝。学界需要一条新的扩展轴——不是再多吃几本教科书，而是让模型学会自己"探索"出新的训练信号。强化学习看起来正是这条轴：模型靠奖励去试，试出来的轨迹本身就是新数据，不受静态数据集的限制。

第二个心结是 o1 复现的"复杂派"困境。o1 一出，研究界一窝蜂去试各种"显式搜索"方案——Monte Carlo Tree Search（蒙特卡洛树搜索）把推理展开成一棵树逐节点评估、过程奖励模型（PRM）给每一步打分、再配一个价值网络估计前景。这些方案理论上很美，工程上全是坑：搜索空间随步数爆炸、价值模型在超长序列上难训、PRM 又要海量人工标注的逐步数据。没有一个真正复现出 o1 级别的通用推理能力。复杂，反而成了包袱。

类比 把推理模型想成解题的考生。复杂派的做法是给他配一整套装备：草稿本分页索引、每写一步有个老师批改打分、还有个顾问估算"照这样写下去能得几分"。装备很全，可协调起来手忙脚乱。Kimi 团队的思路相反——别给人配老师顾问了，直接把考试时间从 1 小时拉到 8 小时，给他一沓够长的草稿纸，让他自己写、自己回头查、自己推翻重来。时间够长，"想清楚"就不再需要外挂。

这条思路把矛头指向一个被忽视的变量：上下文长度。o1 之所以能"想很久"，本质是它能在一次生成里塞下很长的思维链。可之前做 RL 的人，上下文窗口普遍只开到几千、一两万 token——模型"想"到一半就被截断，反思和回溯根本没空间展开。Kimi 团队赌的是：把 RL 的上下文扩到 128K，模型自己就会长出规划、反思、纠错的能力，根本不需要树搜索和价值函数来手把手教。

赌注很大，但拦路虎也很实在——128K token 的 RL 训练，贵得吓人。每条训练轨迹都要生成几万到十几万 token，光生成成本就够喝一壶，更别提反向传播。K1.5 真正的工程贡献，是发明了一个叫部分回放（partial rollout）的机制，把这头大象拆成了能一口口吃下去的小块。

03核心问题

把背景拧干，K1.5 要回答的核心问题可以拆成两句：

核心问题 能不能不用搜索树、不用价值函数、不用过程奖励模型，只靠"长上下文 + 结果奖励"的强化学习，就训出对标 o1 的推理能力？如果上下文长度真的是推理的扩展轴，那它训出来的"长思考"本事，能不能再迁移给答题更快的小模型？

前半句挑战的是"复杂派"的共识——那时几乎所有人都觉得，要追平 o1 至少得上一套 PRM 或 MCTS。后半句则埋着这篇论文最讨巧的一招：长2短。因为长思考模型推理起来太贵（一条数学题动辄几万 token），真要上线服务，得有办法把它"想得久"的本事，塞进一个"答得快"的模型里。

思考一下 假如你只能给模型一个奖励信号——"最终答案对不对"，却把它的思考空间限制在 4K token 内，你觉得它能学会反思吗？那把空间放到 128K 呢？同样是"对就奖励、错就不管"，窗口大小会带来本质差别吗？先凭直觉猜一个，再往下看实验给出的答案。

04方法详解

K1.5 的方法可以拆成四块来读：训练流水线（先做什么后做什么）、长上下文 RL（核心赌注）、部分回放（让 128K 付得起）、长2短（把贵本事变便宜）。我们一块块看。

四阶段训练流水线

和 R1"跳过 SFT 直接 RL"的莽撞不同，K1.5 走的是稳扎稳打的四阶段。先有一个多模态预训练基座，接着做一轮通用 SFT 让模型学会听指令，然后用一小批精选的长思维链（long-CoT）示范做 SFT 冷启动——这一步是给模型"打个样"，让它知道"答题前先长长地想一段"是什么格式。最后才进入真正的 RL 训练阶段。

这里有个微妙的设计选择值得停一下。R1 之所以敢跳过 SFT，是想验证"涌现"的纯粹性；K1.5 之所以老老实实做 long-CoT SFT，是因为它的目标不是验证哲学命题，而是把工程做扎实——冷启动让 RL 有个不错的起点，训练更稳，也更容易复现。两条路没有对错，只是诉求不同。

核心赌注：把上下文当算力来扩

RL 阶段是这篇论文的灵魂。它的"极简"体现在三不靠：不靠 MCTS、不靠价值函数、不靠过程奖励模型，只靠结果奖励——数学题对答案、代码题跑测试。奖励信号稀疏到只有最后一个 token，可 K1.5 赌的就是：只要上下文够长，模型自己会在中间把"怎么想"补齐。

道理是这样的。在短上下文里，模型生成一段推理就像在一张小草稿纸上算题——写满了就得交卷，没地方检查、没地方推翻重来。把窗口放到 128K，等于换了张无限续页的大草稿纸：模型可以先试一种解法，写到一半发现不对，回头重写；可以列个计划，再逐步验证；可以自己出几个反例试试。这些"规划、反思、纠错"的行为，不需要谁教，只要空间够大，它们就会在结果奖励的压力下自发长出来。

关键洞察 论文给出一句很硬的话：增加上下文长度，等同于增加搜索步数。别人靠显式搜索树去探索，K1.5 靠"一条长轨迹里的自我修正"去隐式搜索。搜索不是没有，只是被折叠进了上下文里。实验里他们观察到：上下文越长，性能持续提升，没有见顶——这成了"上下文是扩展轴"最直接的证据。

不过光有长上下文还不够稳。在几万 token 的序列上做策略梯度，梯度很容易乱窜、训练很容易崩。K1.5 用了一个在线镜像下降（online mirror descent）的变体来做策略优化，核心是给每步更新套一个 KL 约束，让新策略别离旧策略太远：

$$ \pi_{t+1} = \arg\min_{\pi}\left[ -\mathbb{E}_{\pi}[R] + \frac{1}{\eta}\, D_{\mathrm{KL}}\!\left(\pi \,\|\, \pi_t\right) \right] $$ (1)

左边是"把奖励拉高"，右边是"别跑偏太远"。这个 KL 项像一个安全带，让模型在长序列的崎岖奖励地形上敢迈步又不至于摔下悬崖，比朴素的策略梯度稳得多。再配上长度惩罚（鼓励该短则短，治"想太多病"）和精心筛过的数据配方，整套优化就齐活了。

部分回放：让 128K 训练付得起

到这里，方法在道理上已经通了，可工程上还是个无底洞。128K 的 RL，每条轨迹都要从头生成十几万 token，一个训练步里还要采好几条——这钱烧不起，时间也等不起。K1.5 最巧的工程贡献，就是部分回放（partial rollout）。

思路一句话：一条长轨迹不必每次从头生成，可以拆成"前缀 + 新后缀"。前缀是之前已经生成并缓存好的（KV 状态、logits 都在），直接复用；这次只新生成一小段后缀拼上去训练。要是某条轨迹太长、一轮生成不完，就把它暂停，存下来，下一轮接着续。这样一来，昂贵的长序列生成被切成了廉价的小块，128K 的训练才真正跑得动。

除了部分回放，K1.5 在基础设施上也下了功夫：用 Kubernetes 边车容器把训练框架（Megatron）和推理框架（vLLM）塞在同一组 GPU 上，让"生成"和"训练"交替复用算力，把闲置压到最低；代码题则配了一个安全沙箱，直接跑测试拿结果奖励。这些工程细节看着不性感，却是 128K RL 能跑通的地基。

长2短：把贵本事变便宜

RL 训出来的长 CoT 模型很强，但有个要命的缺点：用不起。解一道题动辄生成几万 token，按 token 计费的话，每道数学题都是一顿大餐。真要上线服务，必须有便宜版本。这就是长2短（long2short）要解决的——把长思考模型"想得久"的本事，迁移给"答得快"的短 CoT 模型。

具体两招。第一招是带长 CoT 激活的长度惩罚：在 RL 阶段加一个软惩罚，鼓励模型在保证正确的前提下尽量短，逼它把长思考里真正有用的步骤浓缩下来。第二招更简单粗暴——模型合并：把长 CoT 模型和一个短 CoT 模型直接揉到一起，让合并后的模型既有前者的推理深度，又有后者的简洁。两招都无需重新大规模训练，几乎是"白捡"一个快答版。

05实验结果

结果分两部分看：长 CoT 版对标 o1，短 CoT 版（长2短产物）反超一众前辈。

长 CoT 版用一套极简框架（没有 MCTS、没有价值函数、没有 PRM）追平了 o1——这本身就是对"复杂派"的一记反证：原来那些重型装备并非必需，把上下文拉长就够了。更亮眼的是短 CoT 版，它把长思考的本事浓缩进快答模型后，成绩依然漂亮得惊人：

论文里最抓眼球的数字是"在某些指标上比 GPT-4o、Claude 3.5 Sonnet 高出多达 +550%"。这个百分比来自 AIME 这类题上原本基数极低的对比（个位数对 60 分），数学上是相对提升，读者心里要有数——但即便换成绝对分差，K1.5 短 CoT 版把 AIME 从个位数拉到 60 分，这个跳跃本身就够震撼了。它说明长思考里学到的东西是真的可以迁移的，不是"想得久"模型独有的黑魔法。

还有一组结果格外有说服力——上下文长度的扩展曲线。论文展示：随着 RL 上下文从短拉到 128K，性能持续上升，没有出现"拉到某个点就饱和"的拐点。这正是"上下文是扩展轴"最直接的证据，也是这篇论文最想留给后续研究者的那个钩子。

06影响与意义

K1.5 的贡献可以浓缩成三句话。

第一，它给推理模型的复现指了一条可工程化的路线。R1 证明了"纯 RL 能涌现推理"，但它的极简让很多人怀疑可复现性；K1.5 则把"长上下文 RL"从理念落成了配方——partial rollout 怎么做、策略优化怎么稳、long2short 怎么蒸馏，都写得清清楚楚。后来的开源推理模型，或多或少都从这套工程范式里借过砖。

第二，它重新定义了"搜索"在推理里的位置。在它之前，"复现 o1"几乎等于"上 MCTS/PRM"；K1.5 之后，学界开始接受一个更省事的观念——显式搜索可以被折叠进长上下文里的隐式搜索。这个观念转变，让一大批没有搜索树基础设施的团队也能做出强力推理模型。

第三，long2short 把"推理能力可迁移"这件事摆上了台面。它意味着昂贵的长思考训练不必只在推理时变现，可以蒸馏成便宜资产反复使用——这直接影响了后来推理模型"训练用长、部署用短"的标准做法。

07局限性与未来方向

K1.5 不是没有软肋。最明显的一条：结果奖励依赖可验证的真值。数学题有标准答案、代码题有测试用例，可一旦遇到开放写作、伦理判断这类没有客观对错的任务，"答案对不对"这个奖励就失效了。论文的成果几乎都集中在可验证领域，泛化到不可验证领域仍是开放问题——后来的"奖励模型 + RL"路线正是在补这一块。

第二，长 CoT 推理真的很贵。即便有 long2short 救场，长模型本身的推理 token 成本依然远高于普通模型。"想太多病"——模型在简单题上也啰嗦几千字——也是推理模型普遍的副作用，K1.5 的长度惩罚只是缓解，没根治。

第三，"上下文是扩展轴"这个论断虽然在实验区间内成立，但它的尽头在哪没人知道。128K 之后是 256K、1M 继续涨，还是会撞墙？长上下文带来的 KV 缓存成本、训练稳定性会不会在某处反噬？这些问题 K1.5 没能回答，留给了后来的长上下文推理研究。

08领域演进脉络

把这条线串起来，能看清推理范式是怎么一步步冒出来的。早期是"模型该长多大"（GPT-3、Chinchilla）和"模型该怎样听人话"（InstructGPT、DPO）两条主线，它们在 2024 年底都走到了阶段性尽头——DeepSeek-V3 把"堆参数+对齐"的性价比做到了极致。可模型还是不会"思考"，回答时一口气说完，没有草稿、没有检查。

2024 年 9 月，o1 第一次把"思考时间"当成可扩展资源，但它是黑箱。学界两条复现路线几乎同时起步：一条是 DeepSeek-R1 的"极简纯 RL，看涌现"，赌的是奖励信号本身就够；另一条就是 Kimi K1.5 的"长上下文 RL + 工程化"，赌的是空间够大模型自己会长出推理。两条路在 2025 年 1 月先后交卷，一个偏哲学验证，一个偏工程落地，互为镜像。K1.5 之后，"长上下文 RL"成了可复制的范式，long2short 让"训长用短"成了标配，推理模型正式从"能不能复现 o1"进入"怎么把推理做便宜、做通用"的新阶段。

09趣味延伸

这篇论文背后最戏剧性的，是它和 R1 的"双响炮"剧本。2025 年 1 月，杭州的 DeepSeek 和北京的 Moonshot 两支中国团队，一前一后（差两天）把对标 o1 的答卷贴上 arXiv。一个走极简纯 RL，一个走长上下文工程，几乎覆盖了"复现 o1"的所有主流思路。业界戏称这是"中国推理模型双响炮"——OpenAI 那只黑箱，被两束探照灯从不同角度同时照亮。

轶事 K1.5 有个细节很"产品经理"。R1 是一份纯技术报告，K1.5 却是多模态的——能看图解题。这其实暴露了两家团队的性格差：DeepSeek 像个较真的学者，先把"纯 RL 能不能涌现推理"这个科学问题证干净；Moonshot 本就有 Kimi 这个面向消费者的产品，自然顺手把视觉能力塞了进去，让模型既能算数学题，也能看懂带图的几何题、读懂数据图表。一个追求纯粹，一个拥抱实用，人设鲜明。

还有个有意思的对照——两家对"长思考"的态度。R1 靠模型自己涌现出"Wait, let me reconsider"的反思，是被动长出来的；K1.5 则是主动把上下文拉到 128K，等于明确告诉模型"给你这么大空间，你尽管想"。一个像放养，一个像给足场地。殊途同归到 o1 级别，恰恰说明"想得久"才是那把钥匙，至于怎么让模型想得久，门道很多。

10个人解读与延伸思考

读完 K1.5，我最深的感受是它把"扩展轴"这个概念讲透了。预训练时代，大家只会沿"参数×数据"这一个方向扩；K1.5 之后，"上下文长度"成了第二个可扩的方向，"思考时间"成了可计量的资源。这件事的深远影响在于：它让推理能力从"玄学涌现"变成了"可工程化调参"——你要更强的推理？那就开更大的上下文、做更稳的长序列 RL、再蒸馏个短版上线。从玄学到工程，往往就是一门技术走向普及的临界点。

但我也想泼一点冷水。K1.5 的成功高度依赖"可验证奖励"这个前提，这让它的方法论在数学、代码这类有标准答案的领域如鱼得水，可一旦搬到科研、写作、决策这类"答案好不好全凭判断"的场景，整套奖励机制就失灵了。怎么把"长上下文 RL"扩展到不可验证领域，是下一个真正的大题。此外，"长2短"虽好，但它本质上仍是蒸馏，短模型的能力天花板被长模型锁死——能不能让短模型自己长出长思考的能力，而不是从长模型那里"借"？R1 的纯 RL 路线其实隐隐在回答这个相反的问题。

把 R1 和 K1.5 放一起看，会发现一个有趣的循环：R1 说"别管那么多，纯 RL 就行"，K1.5 说"不行，得长上下文加工程"。两份答卷都成立，恰恰说明推理这道题，解法从来不止一种。真正决定胜负的，不是哪条路更"对"，而是哪条路更"可复现、可扩展、可服务化"。从这个角度看，K1.5 的工程取向，也许比 R1 的哲学取向更接近产业落地的形态。

留个问题给你 K1.5 把"想得久"的能力蒸馏给了"答得快"的短模型，听起来两全其美。可如果一个短模型从没自己"想"过很久，它的推理能力算自己的，还是从长模型那里借来的？当蒸馏成了标配，我们会不会训出一批"只会抄长模型思路、自己不会深思"的短模型？这个问题，下一篇会从另一个极端给出回答。
