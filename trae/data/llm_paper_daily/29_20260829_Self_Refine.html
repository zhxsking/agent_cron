大模型经典论文精读系列 #029

Self-Refine: Iterative Refinement with Self-Feedback Self-Refine：让模型给自己当"导师"——生成、自我批评、再修改的迭代闭环，无需任何额外训练就能把答案打磨到位

作者：Aman Madaan, Niket Tandon, Prakhar Gupta, Skyler Hallinan, Luyu Gao, Sarah Wiegreffe, Uri Alon, Nouha Dziri, Shrimai Prabhumoye, Yiming Yang, Shashank Gupta, Bodhisattwa Prasad Majumder, Katherine Hermann, Sean Welleck, Amir Yazdanbakhsh, Peter Clark（共 16 位） 机构：Carnegie Mellon University / Allen Institute for AI / University of Washington / NVIDIA / UC San Diego / Google Research 发表：2023-03 / arXiv（NeurIPS 2023 收录）
arXiv GitHub Project

设想你给同事写了封邮件，张口就是"Send me the data ASAP"。写完你重读一遍，眉头一皱——这语气太冲了，于是改成了"Hi Ashley, could you please send me the data at your earliest convenience?"。再读一遍，又发现少了点上下文，补一句"for tomorrow's meeting"。前后三稿，一封邮件才定下来。

这恰恰是 2023 年以前大语言模型做不到的事：它一次生成、一锤定音，写完了就写完了，没有"重读、皱眉、改稿"这一环。哪怕你给它接上 RLHF，它也只是在训练时学过"哪种写法好"，推理时照样不回头。一个朴素到极点的问题被人提了出来——能不能不训练，就让模型自己给自己当导师，反复打磨自己的草稿？

一句话总结 用同一个冻结的 LLM同时扮演生成者、批评者、精炼者三个角色，靠几条 few-shot 提示把"草稿→反馈→改稿"循环跑起来，无需任何训练或强化学习，在 7 个任务上平均提升约 20 个百分点。

01领域定位

把镜头对准"提示范式"这条暗线，它的演化有两条腿在走：一条腿在扩搜索结构——从一条链（Chain-of-Thought），到一束平行链（Self-Consistency），到一棵树（Tree of Thoughts），再到一张图（Graph of Thoughts），结构越来越能"分叉、合流、回溯"。另一条腿在加深单条思路的精炼——这恰恰是 Self-Refine 站的位置。

有趣的是时间线：Self-Refine（2023-03）其实早于 Tree of Thoughts（2023-05）和 Graph of Thoughts（2023-08）出现在 arXiv 上。它和"扩结构"那一脉几乎同时破土，却走向了正交的另一个方向——不增加候选路径，而是把同一条草稿反复打磨。如果说 GoT 把"精炼"列为图上的一种变换，那 Self-Refine 干脆把整个推理压成一件事：精炼。它开启了"自反馈 / 自我批评"这一族，后来的 Reflexion（加环境反馈）、CRITIC（加外部工具验证）以及对推理自纠错可靠性的大讨论，都能追溯到它。

02研究背景

2023 年初，LLM 单步生成的局限越来越显眼。问题不在于"它写不出像样的句子"，而在于多目标、多约束的任务它一次写不到位：对话既要合人设又要礼貌又要推进话题；代码既要可读又要高效又要正确；缩写既要好念又要贴题又要正面。这些任务的"好"是多维度的，模型一口气满足不全。

那"迭代精炼"这条路以前没人走吗？走过，但都背着沉重的行囊：

  • PEER、Self-Correction（Welleck et al.）：要训练专门的 refiner 模型，或要监督数据里的"坏稿→好稿"对照对。
  • RLHF / InstructGPT：要人类标注 + 奖励模型 + PPO，重得像座山（参见本系列第 6 篇）。
  • 各种任务特定的精炼流水线：换任务就得重训，扩展性差。

换句话说，2023 年前的"迭代精炼"几乎都默认"改"这个动作需要学习——要么学一个 refiner，要么学一个奖励模型。问题是 GPT-3.5、GPT-4 这种闭源大模型根本动不了权重。于是论文的开场白直戳痛点：既然这些模型已经在人类语料里见过无数次"草稿→批评→修改"的过程，那它们为什么不能在推理时直接做这件事？

类比 把生成想成"写作文"，把精炼想成"改作文"。以前的路线是：你得先训一个"会改作文的老师"（训 refiner），或者训一个"能给作文打分的判官"（训奖励模型），才能让"学生"被改。Self-Refine 的洞察是——同一个学生，戴上一顶"老师帽"，对着自己的作文挑错，再戴回"学生帽"改。帽子是 prompt 换的，学生本身没变。

03核心问题

一句话：在不训练、不强化学习、不依赖人类标注的前提下，能否让一个冻结的 LLM 通过"自己生成反馈 → 自己改稿"的循环，在多种任务上把输出质量显著抬升？更进一步——这能不能对已经在 SOTA 上的 GPT-4也奏效？

思考一下 如果模型第一次没写好，凭什么它第二次就能看出自己哪里没写好？同样是这个模型、同样的权重，只是换了个 prompt，它能"扮批评者"扮得比"扮生成者"更好吗？换句话说——批评比生成容易这件事，在 LLM 身上也成立吗？

这正是论文背后最反直觉、也最关键的一个假设。后文会用"为什么这条路能成"给出答案，也会在局限性里诚实地说明：它在推理任务上未必成立——这恰好是下一篇要拆的台。

04方法详解

Self-Refine 的方法可以拆成三件事：一个三步循环、一个模型三个角色、四条让反馈有用的设计原则。

步骤一：FEEDBACK → REFINE 的循环

给定输入 $x$，先用生成提示 $p_{\text{gen}}$ 让模型写出第一稿 $y^{(0)}$。然后把这一稿连同反馈提示 $p_{\text{fb}}$ 喂回去，让模型输出一段自然语言反馈 $\text{fb}^{(t)}$；再把反馈连同精炼提示 $p_{\text{ref}}$ 喂回去，得到改稿 $y^{(t+1)}$。两步交替，直到停止。

$$ y^{(0)} = \mathrm{LLM}(p_{\text{gen}},\, x) $$ (1)
$$ \text{fb}^{(t)} = \mathrm{LLM}(p_{\text{fb}},\, x,\, y^{(t)}) $$ (2)
$$ y^{(t+1)} = \mathrm{LLM}(p_{\text{ref}},\, x,\, y^{(t)},\, \text{fb}^{(t)}) $$ (3)

停止条件有两种：要么跑固定轮数（论文实验里最多 4 轮），要么让反馈提示里包含一句"是否已经足够好？"，模型自己说"够了"就停。论文在代码里把它写得极其干净：

def self_refine(prompt):
    answer = ChatGPT(prompt)                  # 生成第一稿
    while True:
        feedback = ChatGPT(feedback_prompt, answer)   # 自己给反馈
        refined  = ChatGPT(refiner_prompt, feedback, answer)  # 自己改稿
        if is_refinement_sufficient(prompt, feedback, answer, refined):
            break
        answer = refined
    return refined

步骤二：一个模型三个角色

Self-Refine 最经济的设计是不引入第二个模型。生成者、反馈者、精炼者全是同一个 $M$，靠切换 few-shot prompt来"换帽子"。这三个 prompt 各带两三个示例（带反馈的草稿、带改动的草稿），告诉模型"在这种任务里，反馈长这样、改稿长这样"。

步骤三：让反馈"有用"的四条原则

循环骨架很简单，但论文强调：能不能跑出效果，几乎全看反馈提示怎么写。作者总结了四条经验，这也是它区别于"随便问一句好不好"的关键：

  • 具体不抽象：反馈提示要让模型沿多个明确维度评估，比如代码任务问"可读性 / 效率 / 正确性"各打几分，缩写任务问"好念 / 好拼 / 贴题 / 正面 / 知名"各打几分。"Is this good?" 这种泛问得到的反馈模糊无用。
  • 可定位：反馈要指出具体哪一处不达标，而不是"整体不好"。能定位，模型才知道改哪里。
  • 带改进指令：除了点出问题，还要给"该怎么改"的方向，让精炼步骤有 actionable 信号。
  • 留历史：把前几轮的草稿和反馈都留在 prompt 里，让模型"记住"自己改过哪里，避免反复横跳。
类比 反馈提示写得具体 vs 模糊，差别就像编辑给稿子的批注——一种编辑只写"这章不行，重写"，另一种写"第 3 段第 2 句的主语指代不清，把'他'改成角色名；末尾缺一句过渡到第 4 段"。前者让作者抓瞎，后者让作者知道下笔处。Self-Refine 干的事，就是用 prompt 把模型逼成第二种编辑。

05实验结果

论文在 7 个目标多维 / 约束多样的任务上对比"同模型单步生成"与"同模型 + Self-Refine"，主力是 GPT-3.5（text-davinci-003 / gpt-3.5-turbo）和 GPT-4，迭代最多 4 轮。结论一锤定音：所有任务上，Self-Refine 的输出在人工偏好和自动指标上都胜过同模型的第一稿，平均绝对提升约 20 个百分点。

任务（GPT-4）单步基线Self-Refine绝对提升
对话响应生成（偏好）25.474.6+49.2
情感反转（Yelp）3.836.2+32.4
代码可读性提升（偏好）27.456.2+28.8
代码优化（PIE，% 改进）27.336.0+8.7
缩写生成 / 约束生成较大提升（多维评分）显著
数学推理（GSM8K）增益有限小

读这组数据最关键的不是哪个绝对数字，而是它揭示的规律：

  • 评判标准越"明确可描述"，Self-Refine 增益越大。情感反转（要把差评改成好评，目标清晰）、缩写生成（多维评分维度清楚）增益最大；代码可读性、对话响应次之。
  • 评判标准越"需要逻辑验证"，增益越小。GSM8K 数学推理几乎不动——因为模型自己也判断不了自己算得对不对，反馈就跑了空转。这个"推理任务增益有限"的观察，是下一篇论文拆台的直接入口。
  • GPT-4 也吃这一套。哪怕已经是当时的 SOTA，Self-Refine 仍能把它再抬一截——这打破了"模型够强就不需要 test-time 改进"的迷思。

06影响与意义

Self-Refine 的贡献不止于"又一个 prompting 技巧"，它在三条线上留下了实在的痕迹：

  • 把"测试时改进"从"需要训练"中解放出来。它证明了一个足够强的指令遵循模型，光靠切换 prompt 就能当自己的批评者和精炼者——这把 test-time 改进的门槛从"训得动模型的人"降到了"会写 prompt 的人"。
  • 开启"自反馈 / 自我批评"一脉。Reflexion（同年的 Shinn et al.）把自反馈扩展到 agent 场景、加入环境反馈让反思更可靠；CRITIC（Gou et al.）更进一步，让模型用外部工具（解释器、检索）来校验自己的批评——都是 Self-Refine 思想的延伸。
  • 埋下"推理自纠错可靠性"这场辩论的火种。它声称 GSM8K 上有小幅提升，但同年的 "LLMs Cannot Self-Correct Reasoning Yet"（Huang et al.）用更严格的对照证明：没有外部反馈时，推理自纠错反而会降级。这场辩论直接催生了后来 o1/R1 走"用 RL 把反思训练进权重"的路线。

更有意思的是，它把一个直觉钉进了社区共识：批评比生成容易——同一个模型当"审稿人"往往比当"作者"更能发现问题。这个直觉后来被反复验证，也成为"为什么 test-time compute 值得花在反思上"的理论底座。

07局限性与未来方向

论文自己、NeurIPS 审稿人、以及后来的批判者，都很清醒地点出了它的边界：

  • 成本翻倍：每多一轮，LLM 调用次数线性增长，token 成本和延迟都翻几番。论文最多跑 4 轮，实际部署里这是真金白银的开销。
  • 弱模型不行：Self-Refine 强依赖模型"会批评"的能力。论文实测在 Vicuna-13B 这类较弱模型上效果崩——模型给不出有用的反馈，改稿自然越改越糟。
  • 推理任务存疑：这是被后续工作最猛烈质疑的一点。Huang et al. 2023 证明，没有外部反馈时，模型自我纠正推理会降级——因为模型对自己算错的地方没有"判别力"，反馈等于幻觉。
  • 反馈幻觉：模型可能"一本正经地"指出根本不存在的问题，或者反复坚持同一个错误。反馈质量没有保障机制。
  • 停止条件脆弱：让模型自己说"够了"，有时它会过早停手，有时又死循环——这是后来工作要补的工程坑。

未来方向也清晰：让反馈有外部锚点（CRITIC 走的路）、让反思进入训练阶段（o1/R1 走的路）、让循环能跨轮累积教训（Reflexion 走的路）——这三条后续都被接住了。

08领域演进脉络

把镜头拉远，提示范式有两条腿在并行：一条扩搜索结构——CoT 链 → CoT-SC 平行链 → ToT 树 → GoT 图；另一条加深精炼——Self-Refine 把"草稿→反馈→改稿"循环立成一等公民。两条腿在 2023 年同时破土，却几乎不互相引用，像两个独立发现"测试时还能这么玩"的团队。

但精炼这条腿后来分了叉：一叉走向"加外部锚点"（Reflexion、CRITIC），承认"自我批评不够可靠"；另一叉走向"把反思训练进权重"（o1、R1），让模型自发产生长思维链、自我验证。回头看，Self-Refine 是这条分叉的共同起点——它既证明了"自反馈有用"，也暴露了"自反馈对推理不可靠"，两面性都被后来者继承。再往后，"测试时算力扩展"被总结成统一框架（参见本系列第 21 篇 Scaling Test-Time Compute），Self-Refine 和 ToT/GoT 一起被收编为它的具体实例。

09趣味延伸

这篇论文最有意思的"出身"，是它的作者阵容。16 位作者横跨六家机构——CMU、Allen Institute for AI、华盛顿大学、NVIDIA、UC San Diego、Google Research，是一份典型的"跨海岸大合作"。第一作者 Aman Madaan 当时是 CMU 的博士生，资深作者 Peter Clark 来自 AI2（没错，就是本系列第 22 篇 "Let's Verify Step by Step" 那篇 OpenAI 过程奖励模型论文里反复出现的 AI2，Clark 本人是过程监督思路的早期推动者）。Madaan 后来去了 Google DeepMind，"自我反馈"这条线他一直没放下。

另一桩趣事是速度：2023 年 3 月 30 日上 arXiv，5 月 25 日出 v2，9 月就被 NeurIPS 2023 接收为 poster——从初稿到顶会收录只用了不到半年。配套的 demo 站 selfrefine.info 也极为贴心，可以让你在线试"草稿→反馈→改稿"的全过程。后来作者还搞了个 Visual Self-Refine——让 GPT-4V 反复改 TikZ 代码画图，连 Stokes 定理示意图、独角兽插图都能迭代着画好，把"自我精炼"从文本扩到了视觉。这种"用同一思路反复打磨产物"的延展性，本身就是 Self-Refine 哲学的最好注脚。

10个人解读与延伸思考

读 Self-Refine 我最深的感受是：它把"测试时改进"从一个重工程（训 refiner、训奖励模型、跑 PPO）压成了一个轻提示。一旦你接受"同一个模型可以靠切换 prompt 当批评者"，就再难满足于"模型一次写完就交付"——你会本能地想：这个输出能不能让模型自己再挑一遍刺？这套思维在今天几乎所有 LLM 应用里都成了默认姿势：写完代码让模型自审一遍、写完文档让模型自校一遍、答完题让模型自验一遍。

但也要清醒：Self-Refine 的收益强依赖评判标准的可描述性。它对"目标多维但可自然语言描述"的任务（写作、代码风格、对话）是降维打击；对"需要逻辑验证"的推理任务反而是镜花水月——这正是下一篇要戳破的。把它当成万能开关，不如把它当成一个任务适配器——先问"这个任务的'好'能不能用自然语言讲清楚"，再决定要不要上 Self-Refine。

留个问题给你 如果模型已经能用 RL 自发反思、自我验证（想想 o1、R1），那"用 prompt 让模型自我批评"还有必要吗？还是说，Self-Refine 的未来恰恰是把这套自反馈循环训练进模型权重，让"反思"成为模型的本能而非外加的提示？欢迎你带着这个问题，往下读下一篇——它正是 Self-Refine 在推理任务上的"翻车报告"。
