MemOS: A Memory OS for AI System MemOS：给 AI 装一个"记忆操作系统"——当记忆像内存一样被调度、被换页、被计价

1946 年的程序员要想在 ENIAC 上跑一个程序，得先排一整夜的队。轮到他时，抱着一摞接线图和打孔卡片坐进机房，亲手插线、搬开关、盯仪表——每个程序都必须自带关于这台机器的全部知识，因为机器自己什么都不管。改变这一切的不是更快的芯片，而是一个抽象：操作系统。当硬件被封装成"资源"，程序员不必知道磁道和扇区，只需 open() 一个文件；整个软件生态自此爆炸。

今天的 LLM 正站在同一扇门前。上一篇 Agent KB（#064）给所有 agent 开了"中央知识银行"，但结尾留了个问题：一家银行撑不起一整套金融体系——参数、KV 缓存、外挂文本是三种完全不同的"货币"，汇率谁来定？账谁来记？风控谁来做？MemOS 的答案激进又复古：给 AI 装一个操作系统。40 位作者、10 家机构、GitHub 11.7k star，这篇论文把"记忆"从各家自扫门前雪的 prompt 技巧，升格成了一门有调度器、有文件系统、有权限模型的系统工程——他们管它叫"LLM 的 Windows 时刻"。

一句话总结 把明文、KV 缓存、模型参数三种异构记忆统一封装成标准"记忆方块"MemCube，再像操作系统管理内存那样对它们调度、换页、计价与进化——让记忆第一次成为 AI 系统里可以被治理的一等资源。

01领域定位

把这个系列的记忆主线串起来看，一条"从技巧到系统"的路线已经走了很远：Self-RAG（#033）把"何时检索、何时反思"训进权重；Voyager（#036）给 agent 攒了一个技能库；ReasoningBank（#063）开出个人"记忆银行"；Agent KB（#064）把银行升级成跨框架的"中央银行"。但这一整条线，始终运行在应用层——记忆是 agent 框架里的一个模块、一个提示词技巧、一个外挂数据库。

MemOS 干的事是往下挖一层：它不问"agent 怎么记住"，而问"记忆这种资源，底层该怎么管"。就像数据库应用再繁荣，最终要靠文件系统和操作系统托底；记忆再花哨，最终也要有人回答调度、存储、权限、迁移这些"无聊但致命"的问题。这是"经验复利期"从应用创新沉到系统基建的关键一跳——而且这一跳是踩着巨人肩膀的：操作系统 fifty 年的工程智慧，被整体搬进了 LLM 时代。

02研究背景

论文开篇就列出四种让现有 LLM 露怯的典型场景，每一个都指向同一个病根：

  • 长程依赖：多轮任务越拉越长，用户在第一轮定下的代码规范、写作风格，到第十轮就悄悄"漂移"回模型的默认口味——上下文窗口有限、注意力开销平方级增长，指令跟着丢。
  • 知识演化：法规改了、论文发了、股价动了，静态参数一无所知；RAG 倒是能检索，却可能把旧版和新版法规同时塞进 prompt，因为它没有版本概念，更不知道该让谁退役。
  • 个性化：每次会话从白纸开始。ChatGPT 虽有记忆功能，但容量有限、更新机制不透明、用户几乎无法编辑。
  • 跨平台迁移：你在 ChatGPT 里聊熟的偏好、在 Cursor 里磨出来的工程习惯，互不相通——论文称之为"记忆孤岛"（memory silos）。

现有的三条路，各有各的残缺。参数记忆像刻在 ROM 里的知识：读取快、容量大，但更新要"重刻盘"（重训练或微调），昂贵且有灾难性遗忘的风险。RAG 是即席检索加瞬时拼装——论文的原话很刻薄："一个无状态的补丁机制，没有生命周期追踪，没有版本管理，没有权限感知的调度"。至于 Mem0、Zep、Letta 这些记忆工具，论文把它们归入"工具化记忆管理"阶段：有增删改查，但记忆仍不是被系统性治理的资源——就像有了一堆好用的文件，却没有文件系统。

类比 · 为什么需要操作系统 计算机里，寄存器、缓存、内存、磁盘的速度差着好几个数量级，但程序员写代码时几乎感觉不到——因为操作系统在暗处搬运数据：热数据提到缓存，冷数据换到磁盘，快满了就回收。LLM 的三种记忆同样差着数量级（改一个参数要重训练，改一段明文只要一次写库），但今天没有任何人为 LLM 做这件事。MemOS 说：让我来。

论文给三种记忆找到了精准的操作系统对应物，这张对照表是全文概念的基石：

记忆类型OS 对应物生命周期写成本典型形态
参数记忆 Parameter寄存器 / 微码长期极高（重训练）模型权重、LoRA
激活记忆 ActivationCache会话级中（预计算）KV 缓存、隐藏状态
明文记忆 PlaintextI/O 缓冲灵活低（写库即得）检索段落、偏好、图谱

问题也随之而来：三种"货币"的面额、汇率、结算周期完全不同，怎么统一管理？这就是 MemOS 要解决的核心问题。

03核心问题

一句话：如何把明文、激活、参数三种异构记忆统一表示、统一调度、统一治理，让 LLM 获得可控性（controllability）、可塑性（plasticity）与可进化性（evolvability）。换句话说——不是再发明一种更好的记忆格式，而是造那台管理所有记忆格式的机器。

思考一下 在动手设计之前，MemOS 团队先问了一个问题：三种记忆成本差这么远，为什么今天用户全都感觉不到"有人在管"？答案很扎心——因为今天根本没人管：想用明文，你自己拼 prompt；想用参数，你自己发起微调；想用 KV 缓存，抱歉，它只活在一次请求里，请求结束就被扔掉。那么下一个问题来了：如果要让"机器"来管，它管的最小单位应该是什么？一张卡片？一个向量？还是……先往下看，看 MemOS 怎么回答。

04方法详解

MemOS 的方案可以拆成三步棋：先发明一个统一的"记忆集装箱"，再搭一套管理集装箱的"操作系统架构"，最后让集装箱之间能"物态转换"。

第一步：MemCube——记忆世界的集装箱革命

1956 年，卡车司机出身的 Malcom McLean 发明了海运集装箱。在此之前，装卸费占海运成本近一半，码头工人要为形状千奇百怪的货物逐一定制搬运方案；集装箱一出，船、吊车、卡车、火车全部围绕这个标准箱子重组，全球贸易成本暴跌。MemCube 干的就是这件事：每个 MemCube = 记忆内容（payload）+ 三类元数据，无论里面装的是一段文本、一块 KV 缓存还是一组 LoRA 权重，外壳完全统一。

  • 描述性标识（Descriptive Identifiers）：时间戳、来源签名（推理提取 / 用户输入 / 外部检索 / 参数微调）、语义类型——相当于集装箱上的运单：这是什么货、从哪来、什么时候装的。
  • 治理属性（Governance Attributes）：访问控制、寿命策略（TTL）、优先级、合规与溯源标签——相当于海关封条：谁能开箱、能存放多久、过没过安检。
  • 行为使用指标（Behavioral Usage Indicators）：访问频率与新近度、上下文指纹、版本链——相当于物流记录：这箱子被谁用过几次、现在是热门货还是库存货、改过几版。

有了统一集装箱，剩下的系统才有可能围绕它生长。

第二步：三层架构——把操作系统装进 LLM

MemOS 的整体架构是教科书式的三层设计，每一层都能在经典 OS 里找到原型：

  • 接口层是前台窗口。MemReader 负责把"帮我查一下去年的体检报告"这种自然语言，解析成结构化的 MemoryCall——谁在问、问哪种记忆、时间窗口多大、访问意图是什么；Memory API 则提供创建、更新、查询日志等可组合的调用，全程版本感知。
  • 操作层是车间与调度塔，也是全系统的灵魂。MemOperator 做混合检索（符号规则过滤 + 向量语义匹配，可以组合出复杂查询）；MemScheduler 是中央调度器，决定每块记忆"以什么形态、什么时机、注入到哪里"；MemLifecycle 用有限状态机管理记忆的一生——Generated → Activated → Merged → Archived → Expired，外加一个 Frozen 冻结态（法律合同、诊疗指南这类不许改的记忆），还配了一台"时光机"（Time Machine），支持快照与回滚。
  • 基础设施层是金库与海关。MemGovernance 管权限三元组（用户身份 × 记忆对象 × 调用上下文）、TTL 执行、敏感内容脱敏、语义水印；MemVault 按命名空间存储（用户私有库、专家知识库、行业共享库）；MemLoader 与 MemDumper 是跨平台记忆迁移的双向通道；MemStore 则是一个"记忆应用商店"——支持记忆单元的发布、订阅与分发。

最妙的一步是第③步：MemScheduler 不只是"找到记忆"，还要决定记忆以哪种形态登场。最近一次会诊摘要属于高频热数据，预先编码成 KV 缓存直接注入注意力层，读取几乎零成本；诊断模板这类稳定的专业知识，早就蒸馏成了一个可加载的 LoRA 模块；临时性的生活建议，则以明文形式拼进 prompt。三种记忆，三种通道，一次提问同时用上。

点睛之笔：记忆的"物态变化"

MemCube 最有想象力的设计是跨类型转换：记忆可以在三种形态之间流转，就像水在冰、水、汽之间循环。

驱动转换的信号来自 MemCube 的行为指标——访问频率、新近度、版本链。被反复检索的明文会被提升为 KV 缓存（"抄成手边笔记"）；跨会话稳定使用的策略会被蒸馏进 LoRA 模块（"背下来，变成本能"）；利用率下降的 KV 会被降级为明文归档；过时的参数知识则被卸载到外部存储。其中"明文预编码为 KV"这一步尤其关键，它对应的数学很朴素——把前缀 token 的键值对一次算好、反复复用：

$$\mathrm{KV}(x_{1:n})=\bigl\{(k_i^{(l)},\,v_i^{(l)})\bigr\}_{i=1,\dots,n}^{\,l=1,\dots,L}$$ (1)

同一个前缀，每轮对话都要让模型重新"读一遍"并重算这堆键值对；MemOS 把它算一次、存成激活记忆，之后的每一次提问直接注入——省下的正是推理中最贵的预填充阶段。这不是什么新发明，KV 缓存本身是推理引擎的老技术；新的是把 KV 当成一种有身份、有权限、有生命周期的记忆资源来管理——这是所有记忆系统里的头一遭。

05实验结果

实验全部跑在单张 80GB H800 上，端到端对比统一使用 GPT-4o-mini 做骨干模型，对手囊括了 2025 年记忆赛道几乎全部热门选手。先看长对话记忆基准 LoCoMo 上的总体战果：

Memobase210273.1264.6581.2072.01
Mem0117273.3358.7552.3464.57
MIRIX—68.2254.2668.5464.33
Zep270166.2352.1254.8259.22
MemU61766.3463.1227.1056.55
Supermemory50067.3051.1231.7755.34

三个发现值得单独说。第一，不是靠堆 token 赢的：MemOS 每题只注入 1589 个 token，比 Zep 的 2701 少四成——这说明赢在治理（该记什么、该忘什么）而不是蛮力（全都塞进去）。第二，早期版本与 OpenAI 的对比更戏剧化：在 v1 实验里，MemOS 总分 73.31 对 GPT-4o 内置记忆的 52.75，其中时间推理一项 73.21 对 28.25——OpenAI 的记忆功能在"时间线"上几乎是盲的，而 MemOS 每题 token 用量还不到它的一半。第三，也是论文最硬核的一张表：压力测试。40 QPS 下，Mem0 的写入成功率跌到 41.7%、Zep 跌到 26.6%、MemU 只剩 7.5%，而 MemOS 在 100 QPS 下依然 100% 成功——毕竟人家是照着操作系统的标准造的。

其余三个基准同样全线第一：LongMemEval 77.8（六个子项五项第一）、个性化基准 PreFEval 在 0 轮与 10 轮干扰下分别拿到 77.2 与 71.9、人格记忆 PersonaMem 61.2。但有一处细节体现了论文的诚实（或者说藏不住）：LoCoMo 的 F1 值上 MemOS 是 45.27，低于 Memobase 的 50.18；时间推理一项也以 75.18 微弱输给 Memobase 的 81.20。总分第一，不等于项项第一。

最后是激活记忆的加速验证。把高频明文预编码为 KV 缓存注入，与把同样内容拼进 prompt 相比：

模型上下文prompt 注入 TTFTKV 注入 TTFT加速
Qwen2.5-72B6064 tok1.79 s0.15 s91.4%
Qwen3-32B6064 tok0.98 s0.26 s73.5%
Qwen3-8B2773 tok0.41 s0.20 s51.2%

模型越大、上下文越长，加速越狠；而且 KV 注入与 prompt 注入的输出逐字一致——语义没变，纯粹是把重复的预填充计算变成了可复用的记忆资源。72B 模型长上下文场景下首 token 延迟从 1.79 秒压到 0.15 秒，这已经是可以直接兑现的商业价值。

思考一下 KV 注入的输出与 prompt 注入"逐字一致"，这说明什么？说明 KV 缓存本质上就是模型"读过这段文字"后的内部状态——那问题来了：既然状态可以存，状态算不算知识？如果算，你存在云端的 KV 缓存里藏着模型对你说过的一切的"理解"，这份数据的隐私等级，该按明文算，还是按加密数据算？

06影响与意义

这篇论文的影响要分两层看。工程层，它开源即爆：GitHub 11.7k star、两千多次提交，衍生出 OmniMemEval、HaluMem 等评测基准，直接把"记忆管理"从各家闭门造车的插件，变成了一个有公开标准、可对表竞争的赛道——2026 年 Mem0、Zep、Letta 纷纷升级架构，很难说没有这篇论文的刺激。

概念层，它贡献了一整套新的话语体系：memory as a system resource（记忆是系统资源）、记忆的冷热分层（工作记忆 / 长期存储 / 冷归档）、paid memory（记忆作为可安装、可订阅的付费模块——医学生可以"安装"资深医生封装的罕见病诊断经验）、memory marketplace（记忆市场，论文展望中的去中心化记忆交易），以及 Mem-training——把"训练"从一次性的预训练/微调，扩展成运行时持续收集、重构、传播记忆的终身过程。资本也用真金白银投了票：背后的公司"记忆张量"从天使轮近亿元，一路融到华为哈勃领投的 Pre-A——"记忆"正式成了一级市场的独立赛道。

07局限性与未来方向

有意思的是，最狠的打脸来自团队自己。同一批人（中国电信研究院 + 记忆张量）后续发表的 HaluMem 基准做了一次"操作级"体检，结果相当扎眼：MemOS 的记忆召回率 81.90% 是六个系统里最高的，但虚假记忆抵抗力只有 28.85%——它会顺着模型的口嗨，把未经确认的幻觉细节也写进长期记忆；记忆更新的正确率 65.25% 虽然全场最高（Mem0 只有可怜的 1.45%），但仍有约三分之一的该更新之处被漏掉。一个擅长记东西的系统，同时也最擅长记错东西。

工程兑现度也有落差：第三方源码分析发现，开源实现里参数记忆（LoRA）的槽位基本是个占位符——论文里最宏大的"记忆蒸馏为参数"愿景，代码里只有骨架；KV 记忆也只支持本地部署的 HuggingFace / vLLM 模型，调 API 的用户用不上。完整自托管需要 Neo4j、Qdrant、Redis、MySQL 一整套，部署门槛显著高于"一个向量库走天下"的 Mem0。评测方面，所有端到端对比统一用 GPT-4o-mini 做骨干——架构对比公平了，但单一模型的结论外推要打折扣。论文本身也很有个性：36 页的正文没有独立的 Limitations 章节，未来方向（MIP 跨模型记忆协议、自进化 MemBlock、记忆市场）全都停在愿景档。

08领域演进脉络

把这个系列 65 篇连成一条线，会看到一条清晰的主干：Transformer 奠基（#001）→ 预训练范式（BERT #002、GPT-2 #003）→ 规模化（GPT-3 #004、Chinchilla #005）→ 对齐（InstructGPT #006、DPO #008）→ 推理范式（CoT #024、o1 #020、DeepSeek-R1 #013）→ agent 与多智能体（ReAct #035、MetaGPT #038）→ 软件工程智能体（SWE-agent #047 一线）→ 自博弈与自进化（Absolute Zero #055、OpenSkill #059）→ 经验复利（WikiSkill #062、ReasoningBank #063、Agent KB #064）。

而"记忆"始终是横贯这条主线的一条暗线：它先以 prompt 技巧的形态出现（CoT 里的草稿），再以工具形态分化（Self-RAG 的检索反思 #033、Toolformer 的工具调用 #034），然后以集体资产形态流通（Agent KB #064），最终在 MemOS 这里沉底为系统层。论文自己也把记忆研究划成了四个阶段：定义与探索 → 类人记忆 → 工具化管理 → 系统化治理，并把 MemOS 定位为第四阶段的开创者。这个定位是否成立尚可争论，但"记忆需要操作系统"这个命题本身，已经成了 2026 年行业默认的共识——真正的争议只剩：这台操作系统，是长在模型外面（MemOS 路线），还是长在模型里面。下一篇，我们就回到这个问题的源头。

09趣味延伸

这篇论文背后的团队本身就是一部微型创业史。公司"记忆张量"（MemTensor）2024 年 11 月才成立，名字把"记忆"和"张量"直接焊在一起——一个是认知科学的概念，一个是深度学习的数据结构，中英文名互为直译，堪称起名强迫症的胜利。创始人熊飞宇是华中科大毕业、美国 Drexel 博士，创业前是阿里巴巴业务中台数据智能负责人；CTO 李志宇是人大博士，辗转阿里和小红书之后押注记忆赛道；首席科学家杨泓康毕业于普林斯顿，师从鄂维南院士——他正是前作 Memory³（2024）的第一作者。团队的技术路线图野心清晰地写在时间线里：理论（Memory³）→ 系统（MemOS）→ 模型（记忆原生基模 Metis），三步走。

发表策略也很"老江湖"：2025 年 5 月底先放出一篇 23 位作者的短版论文占坑（提出 MAG：Memory-Augmented Generation 这个新词），一个多月后再放出 40 位作者、36 页的长版完整答卷——学术界管这叫占位，产业界管这叫占赛道。长版挂到 arXiv 后四个月连改四版，最新版把评测对手从 Mem0、Zep 扩到 MIRIX、Memobase、MemU、Supermemory，颇有一种"来一个打一个"的气势。

还有一桩乌龙值得一乐：几乎同一时期，人大与 BAAI 团队也发了一篇叫 MemoryOS 的论文（arXiv 2506.06326），两套完全不同的系统、几乎相同的名字，至今还在被媒体与社区张冠李戴——足见"记忆 + 操作系统"这个组合词在 2025 年夏天有多抢手。

10个人解读与延伸思考

我读这篇论文时最大的触动，不是那些 SOTA 分数，而是一个更冷静的判断：记忆操作系统的真正对手，可能根本不是其他记忆框架，而是不断膨胀的上下文窗口。当百万 token 的窗口逐渐普及、"把所有历史都塞进去"的暴力方案越来越便宜，谁还需要精细的记忆调度？我的答案是：经济学永远站在调度这一边——72B 模型读 6000 token 要 1.79 秒，读 100 万 token 的账单和延迟不会因为技术进步而归零，人类大脑也从未因为"能记住"就放弃遗忘机制。塞满上下文是暴发户的做法，调度记忆才是过日子的做法。

更长远看，"记忆即资产"是一把双刃剑。付费记忆、记忆市场这些愿景令人兴奋——顶尖医生的诊断直觉可以被千万医学生订阅；但也令人脊背发凉——如果记忆可以被注入，就一定可以被投毒；如果可以被交易，就一定存在记忆黑市。MemOS 把 MemGovernance（治理）放在与调度同等的位置，或许正是预见了这一点：在记忆成为资产之前，它得先成为受治理的资产。这也回答了上一篇 Agent KB 结尾的定价之问——定价的前提是产权清晰、质检可信、交易可审计，而这些恰恰是"操作系统"比"银行"多出来的东西。

留个问题给你 PC 时代，操作系统最终收敛成了 Windows 的垄断与 Linux 的分裂并存；移动时代，收敛成了 iOS 与安卓的双寡头。LLM 的"记忆操作系统"时代，会收敛成一家独大，还是像 Linux 一样开枝散叶？换个更切身的角度：你的记忆——偏好、习惯、人生轨迹——未来会运行在谁家的 OS 上？开放协议（论文设想的 MIP）来得及在巨头锁死之前出现吗？把你的判断留好，下一篇我们回到这一切的源头，看看两年前伯克利的团队是怎么用一段 system prompt，让 LLM 自己给自己当操作系统的。
下期预告

MemGPT: Towards LLMs as Operating Systems（MemGPT：让 LLM 自己当操作系统——上下文是内存，对话是中断，一段 system prompt 实现的虚拟内存管理）

MemOS 论文里有一句耐人寻味的判词："仅靠系统调用，建不成操作系统"——这句话是说给谁听的？答案是 MemGPT：2023 年伯克利团队的疯狂实验，比 MemOS 早了整整两年。他们不给 AI 外挂系统，而是让 LLM 自己扮演操作系统——上下文窗口是内存，工具调用是系统调用，模型一边回答你，一边给自己"换页"、给自己"写盘"。没有调度器进程，没有三层架构，所有内存管理逻辑全部塞进一段 system prompt，居然真的跑通了，还孵化出了记忆赛道最炙手可热的创业公司 Letta。MemOS 是给 AI 装的 Windows，MemGPT 是让 AI 自己当 CPU——下一篇，回到"记忆操作系统"这条线的真正源头，下期见。
