大模型经典论文精读系列 #044

Multi-Agent Collaboration via Evolving Orchestration puppeteer（木偶师）：把 MacNet 的静态 DAG 换成会学习的"木偶师"——用强化学习训练中央调度器，让多智能体协作从静态拓扑走向动态编排

作者：Yufan Dang, Chen Qian, Xueheng Luo, Jingru Fan, Zihao Xie, Ruijie Shi, Weize Chen, Cheng Yang, Xiaoyin Che, Ye Tian, Xuantang Xiong, Lei Han, Zhiyuan Liu, Maosong Sun 机构：Tsinghua University, Shanghai Jiao Tong University, BUPT, Siemens, Tencent Robotics X 发表：2025-05 / NeurIPS 2025
arXiv GitHub

上一回，MacNet 用一张预先画好的有向无环图（DAG），把 ChatDev 的"单链流水线"扩成了上千个 agent 的大规模协作网，还顺手发现了一条"协作缩放定律"。可这张图有个尴尬的毛病：它在任务开始前就定死了，不管题目是"1+1"还是"证明黎曼猜想"，agent 们都得沿着同一张图纸走。

于是 ChatDev 团队对自己抛出了一个有点狠的问题：既然加 agent 能变强，那为什么不让"谁来上场、按什么顺序上场"这件事，由模型自己学着决定？这篇论文给出的答案是——请一位会学习的"木偶师"上台，它会一边看戏一边学会该拉哪根线、该剪断哪根线。

一句话总结 把多智能体协作建模成一个序列决策过程，用一位经强化学习训练的"中央木偶师"动态决定每一步激活哪个 agent，结果不仅性能更强、算力反而更省——秘诀在于协作结构自发演化出了更紧凑的"环"。

01领域定位

在大模型智能体的发展谱系里，这篇论文正好卡在"从静态到动态"的转折点上。它承接的是 ChatDev → MacNet 这条"清华系"协作脉络：ChatDev 把多智能体焊成一条软件开发流水线（链），MacNet 把链升级成支持上千节点的有向无环图（DAG），却都还是任务开始前就把组织结构钉死的静态拓扑。

而它开启的，是让协作结构在推理过程中自己长出来、并随着训练不断进化的新范式。一句话：MacNet 回答了"能不能扩"，puppeteer 回答了"怎么动态地扩"。此后"编排（orchestration）"这个词，从人工画图变成了模型的一项可学习技能。

02研究背景

单个大模型（monolithic LLM）虽然强，但面对"工具调用 + 多步协作 + 开放环境"这类复杂任务时，它的"单大脑"结构开始捉襟见肘：上下文塞不下、专精能力不够、扩展性差。于是研究者们从人类团队合作里找灵感，造出了一批多智能体系统（MAS）——让各有专长的 LLM agent 分工合作。

可这些系统有个共同的"出生缺陷"：组织结构是静态的。无论 ChatDev 的链、Tree of Thoughts 的树，还是 MacNet 的 DAG，谁先发言、谁后发言、谁听谁的，都是在任务开始前就画好的固定图纸。论文里有个很扎心的脚注——一个 50 节点的网状多智能体系统，开发只有几百行代码的软件，可能要跑上 10 个小时。

类比 把静态多智能体系统想象成一家"按剧本演戏"的剧团：每个演员的出场顺序、台词对接，都在开演前写死在剧本里。哪怕今晚台下只有一个观众、演的是个一分钟的小品，全班人马也得按两小时大戏的流程走一遍——该出场的都出场，该等的都得等。结果是：协调开销巨大、算力大量浪费、人越多越乱。

更麻烦的是，静态拓扑不会随任务变。简单题用 100 个 agent 是浪费，难题用同一张图可能又不够用；而且 agent 一多，谁来跟谁说话就成了组合爆炸——穷举所有可能的协作结构根本不现实。作者们于是把问题收敛成一个关键追问：

"动态编排，能不能同时把协作效果和计算效率都拉满？"

03核心问题

这篇论文要解决的是一个看似矛盾的双目标：既要让多智能体协作更灵活、更聪明（能随任务进展动态决定谁上场），又要让它在变灵活的同时更省算力（少做无用功）。换句话说，它不想在"性能"和"效率"之间做二选一的妥协，而是想两个都要。

思考一下 如果你是这位"中央调度员"，面对一堆能力参差的 agent，你会怎么决定每一步派谁上场？如果只盯着"谁最强就派谁"，会出什么问题？先猜一猜，再往下看作者怎么设计。

04方法详解

作者的解法灵感来自木偶戏——幕后有一位木偶师（puppeteer），灵巧地牵动或剪断手中的线，让台前的木偶（puppet）各司其职地演完整场戏。把这套意象搬进多智能体：一个中央编排器每一步根据任务当前状态，动态决定该激活哪个 agent。整个框架由两块创新拼成：动态编排 + 自适应进化。

先把 agent 抽象清楚

作者先把每个 LLM agent 抽象成一个最小三元组：

$$ a = (m,\ r,\ t) $$ (1)

其中 m 是底层基座模型，r 是推理模式/提示策略（比如 CoT、ReAct），t 是它能调用的外部工具集合。所有这些三元组的组合，就构成了"agent 空间"$\mathcal{A}$。多智能体系统则被自然地写成一张有向图 $\mathcal{G}=(\mathcal{V},\mathcal{E})$：节点是 agent，边是信息流向，起点吃任务、终点吐产物。这套图的形式化，和 Graph of Thoughts 一脉相承。

动态编排之一：中央木偶师

以往的玩法是每个 agent 自己挑合作对象，结果是协调开销大、还不好扩展。作者反其道而行：让一个中央编排器统揽"派谁上场"的决策，agent 只管被选中后好好干活。这样把"选人"和"agent 内部行为"解耦，加新 agent 也不用大改参数，扩展性立马上来了。

动态编排之二：序列化编排（先展开再折叠）

第二个挑战是组合爆炸：可能的协作拓扑是天文数字，搜不动。作者的妙招是序列化——不直接在图空间里搜，而是把图"展开"成一条推理序列：编排器按拓扑顺序一步步挑 agent，串成一条链。看似是线性序列，但等推理跑完把它"折叠"回去，又能还原成一张带偏序的有向图。于是整件事被写成一个序列决策过程：

$$ a_t \sim \pi(S_t,\ \tau) = \mathbb{P}(a \mid S_t,\ \tau) $$ (2)

在每一步 $t$，编排器看着全局状态 $S_t$ 和任务描述 $\tau$，按策略 $\pi$ 选一个 agent $a_t$ 激活。被选中的 agent 拿到自己的局部状态后生成输出，系统状态随之更新：

$$ o_t = f_{a_t}\!\big(s_t(a_t),\ S_t\big),\qquad S_{t+1} = \Phi(S_t,\ o_t) $$ (3)

这个过程满足马尔可夫性——下一步选谁只依赖当前状态，和历史无关：

$$ \mathbb{P}(a_{t+1}\mid S_0,\dots,S_{t+1},\tau) = \mathbb{P}(a_{t+1}\mid S_{t+1},\tau) $$ (4)

满足马尔可夫性是关键：它意味着这个策略可以被强化学习优化。直到命中终止条件（选到终止符，或算力预算耗尽），再用聚合函数 $F_{\mathrm{agg}}$ 把所有步的输出拼成最终答案。

自适应进化：用强化学习让木偶师"学会演戏"

光能动态选 agent 还不够——naive 地选，很容易喊来一堆没用的 agent，算力爆炸。好在前面证明了过程满足马尔可夫性，于是策略 $\pi$ 可以被学习。作者用经典的 REINFORCE 算法来优化它，目标是最大化整条推理轨迹的期望回报：

$$ J(\theta)=\mathbb{E}_{\pi_\theta}\!\big[R(\tau)\big],\quad \nabla_\theta J \approx \frac{1}{N}\sum_{n=1}^{N}\Big(\sum_{t=1}^{T}\nabla_\theta\log\pi_\theta(a_t\mid S_t)\Big)\cdot R(\tau) $$ (5)

回报函数是全文最精巧的设计，它同时把"答案质量"和"算力成本"塞进同一条轨迹里：

$$ R_t=\begin{cases} r - \lambda\cdot C_T, & \text{若 } t=T \text{（终止）}\\[4pt] \gamma\cdot R_{t+1} - \lambda\cdot C_t, & \text{否则} \end{cases} $$ (6)

这里 $r$ 是解的质量（封闭域任务用 0/1，开放域用连续分），$C_t$ 是这一步的算力成本，定义为 $C_t = F\cdot\log(1 + t/\phi)$——把 FLOPs（$F$）和步数惩罚一起算进来，$\phi$ 是最大步数预算。而 $\lambda$ 是一个可调旋钮：越大越抠门（更看重省算力，但可能过早收手、欠思考）；越小越铺张（更看重精度，但可能磨蹭个没完）。这样一来，木偶师不仅学会编排，还学会剪枝——把贡献小的 agent 逐步踢出队伍，把推理链蒸馏到最精炼的样子。

05实验结果

作者在四个差异很大的基准上验这套框架，覆盖封闭域和开放域：GSM-Hard（数学多步推理）、MMLU-Pro（多领域知识）、CommonGen-Hard（创意生成）、SRDD（软件需求文档协作起草）。agent 池也分两档：Mimas（小模型：Qwen-2.5-7B、LLaMA-3.1-8B、Mistral-7B）和 Titan（大模型：GPT-4-Turbo、Gemini-1.5-Pro、LLaMA-3.1-405B）。还专门测了"异构"（Puppeteer，混用不同模型）和"同构"（Puppeteer-Mono，全用同一个基座）两种配置。

结果有几个挺反直觉的发现。第一，puppeteer 在所有任务和配置上都稳定碾压单 agent 和传统多 agent 基线。更妙的是，连"同构"的 Puppeteer-Mono 都显著超过了用同样模型的基线——这说明性能增益主要来自"组织设计"本身，而不是靠堆不同模型凑出来的多样性。

第二，性能和效率居然同向提升：token 消耗在训练过程中一路下降，而答案质量却一路上升。在 Titan 档，平均性能从 0.6893 涨到 0.7731，同时算力在降。这违反了"性能涨、算力也得涨"的常识，秘诀就在那个"质量−成本"的回报设计里。

第三，两档 agent 池进化出了不同的"省力策略"：Titan 档靠提前终止——答案够好了就早早收手；Mimas 档因为单兵能力弱，链长不减，但学会优先挑便宜的 agent来干活。同一个目标，因地制宜。

但作者最想讲的故事在更深一层。他们去分析"训练后的协作结构到底长成了什么样"，发现拓扑从简单的链，自发演化出了复杂的图——出现分支、并行轨迹、跨分支通信、回溯，甚至自环。其中两个趋势最关键：一是紧致化（compaction），图密度从 1.0829 涨到 1.4479，无效交互被剔除，交流集中在少数"枢纽 agent"身上；二是环形化（cyclicality），长度为 2 的环平均数从 0.52 涨到 0.62——也就是 agent 两两之间形成了"反复对话、互相打磨"的环路。作者据此下了结论：关键增益，始终来自更紧凑、更循环的推理结构的涌现。

06影响与意义

这篇论文的深远意义，是把多智能体协作的"组织设计"从人工画图变成了模型可学习的技能。此前无论链、树还是 DAG，拓扑都是研究者拍脑袋定的；puppeteer 之后，"谁跟谁说话、按什么顺序"成了一项可以被强化学习优化、并能随任务自适应的能力。

更值钱的是它揭示的那个机制性结论：协作变强，不是因为多喊了几个 agent，而是因为结构自发长出了环——这让"循环推理 + 互相验证"不再需要人去手写，而是从训练里自然涌现。它还为后续把"编排"当作统一接口的工作（把编排建模成函数调用级别的 RL 问题）铺好了路：同期的 STRMAC 状态感知路由、MAS-Orchestra 整体编排，都可以看作这条路线的延续。

它还顺手证明了一件让人安心的事：组织设计本身就有红利。同构的 Puppeteer-Mono 用同一个模型也能赢，意味着哪怕买不起一堆不同的大模型，把协作结构训好，照样能涨点——这对算力有限的团队是个好消息。

07局限性与未来方向

  • 奖励太粗：回报只在任务结束时给一个总体反馈，缺乏对单步的细粒度监督。更细的过程级奖励（像 PRM 那样给每一步打分）可能让进化更稳更快。
  • agent 与工具集固定：推理期间 agent 池和工具集合是锁死的，不能中途动态增减能力。未来若能在运行时按需"造"新 agent、挂新工具，弹性会更强。
  • 中央化的脆弱：一切决策压在一位木偶师身上，扩展到极大规模时它可能成为瓶颈与单点。去中心化、多层级编排是自然的下一步。
  • 环结构的可解释性：虽然观察到"环"在涌现，但这些环具体在做什么样的互相验证、哪些是有用的、哪些是空转，还需要更深入的结构化解读。

08领域演进脉络

把这条线拉远看，智能体协作的演化脉络相当清晰：

  • 奠基期（2017–2022）：Transformer → GPT 系列让单模型变强；ReAct 把"思考"和"行动"交织成循环，为 agent 时代埋下种子。
  • 静态拓扑期（2022–2024）：Generative Agents 让 agent 群居涌现；CAMEL/MetaGPT/ChatDev 用角色扮演和 SOP 把协作工程化；AutoGen 把它变成可编程对话；Graph of Thoughts/Tree of Thoughts 探索了树与图；MacNet 用 DAG 支持上千 agent，发现协作缩放定律——但图都是静态的。
  • 动态编排期（2025–）：puppeteer 登场，用 RL 训练中央木偶师，让协作结构在推理中动态生成、在训练中不断进化，并自发涌现出"环"。这一步标志着协作网络开始学会怎么组织自己。

puppeteer 正卡在"动态编排期"的起点——它回答了"能不能让结构自己长出来"，同时为"怎么更整体、更高效地编排"留下了入口。呼应图 1，它就是那个把虚线左侧的静态期，推向右侧动态期的转折节点。

09趣味延伸

这篇论文背后有个挺有戏剧性的"传承"故事。puppeteer 的一作 Yufan Dang（党宇帆）和共同一作 Chen Qian（钱辰），来自清华大学自然语言处理实验室——而这正是 ChatDev 的诞生地。还记得吗？MacNet 也是这个团队"亲手推翻"自己上一代 ChatDev 链式结构的自我革命。现在 puppeteer 又把 MacNet 的静态 DAG 给"革"了。同一支队伍，连着三代作品，每一代都在推翻上一代的核心设计——这大概是学术界最健康的"自我否定"了。

论文的核心比喻也选得很妙：木偶戏。幕后的木偶师看不见，但每一根线的牵动与剪断，决定了台前木偶的表演。作者甚至用"skillfully pull or cut strings"来描述木偶师的学习——该拉的线拉紧、该剪的线剪掉，正是"保留有效 agent、踢掉冗余 agent"的诗意化表达。比起冷冰冰的"动态调度器"，"木偶师"这个名字让整套机制瞬间有了画面感。

还有个挺有意思的细节：这套方法不只在纯文本任务上奏效，作者还把它搬到了具身环境 ALFWorld 里——agent 们要在交互式环境里协调感知、规划、执行，照样跑得动。这说明"动态编排"不是挑任务的花架子，而是一项能迁移的通用能力。再考虑到它能用小模型池（Mimas 档）跑出好成绩，对算力吃紧的团队而言，这几乎是用得起的多智能体的曙光。

10个人解读与延伸思考

我个人觉得这篇论文最值得咀嚼的，不是"动态比静态好"这个结论——这几乎是意料之中——而是它揭示的涌现机制：当编排被放进强化学习里，系统自发长出的不是更长的链，而是更密的环。这和人类团队的规律暗合：真正高效的小组，往往不是流水线，而是几个核心成员反复对焦、互相挑刺的"小圈子"。puppeteer 无意中用数学为"反复打磨"投了一票。

另一个值得想的点，是"编排即模型技能"的统一接口潜力。如果编排策略本身是可学习的，那未来 agent 系统的"架构搜索"就可能像神经架构搜索（NAS）一样自动化——不再是人去画 DAG，而是模型自己学出最优组织。再加上它把"成本"直接写进回报，这套范式天生适合"性价比优先"的落地场景，比如用一堆小模型去逼近一个大模型的能力。

留个问题给你 假如把 puppeteer 的"中央木偶师"换成一个"去中心化的会议"——每个 agent 都能投票选下一个发言者，会涌现出什么样的拓扑？会更民主高效，还是更混乱低效？欢迎想想看。
