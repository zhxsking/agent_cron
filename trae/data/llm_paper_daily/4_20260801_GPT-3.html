大模型经典论文精读系列 #004

Language Models are Few-Shot Learners GPT-3：当模型大到一定程度，看几个例子就能学会新任务

作者：Tom B. Brown, Benjamin Mann, Nick Ryder, Melanie Subbiah 等 31 位作者 机构：OpenAI（Jared Kaplan 来自 Johns Hopkins University） 发表：2020-05 / NeurIPS 2020 最佳论文
arXiv GitHub Project

上篇我们读完 GPT-2，它赌的是"规模够大就能 zero-shot"。结果呢？它在语言建模基准上横扫，但在翻译、摘要这些真任务上，离监督模型还差着一截——zero-shot 看着惊艳，却还不够好用。OpenAI 留了一句意味深长的话："GPT-2 还在欠拟合。"

2020 年 5 月，OpenAI 给出了那个赌注的终极加注版：把参数从 15 亿一口气拉到 1750 亿，整整放大一百倍。他们想验证一个近乎疯狂的猜想——模型大到某个临界点，它就不再只是"续写文本"，而是能看着你在提示词里贴的两三个例子，当场学会一个它从没见过的新任务。这份 75 页、31 位作者署名的论文，标题只用了六个词：Language Models are Few-Shot Learners。

一句话总结 GPT-3 把一个纯解码器语言模型放大到 1750 亿参数、训练 3000 亿 token，证明了足够大的模型不需要任何梯度更新，只在提示词里看几个示例，就能当场学会翻译、问答、算术等几十种任务——这就是"上下文学习"（in-context learning），也是今天所有提示工程和 ChatGPT 的真正起点。

01领域定位

如果给大模型的发展画一条河，Transformer 是源头，BERT 和 GPT-2 是两条初分叉的支流——一条奔向"理解"，一条奔向"生成"。GPT-3 干的事，是把"生成"那条支流炸开一个瀑布：它不再纠结架构创新，而是把规模推到当时难以想象的程度，然后蹲在瀑布底下，记录水花里究竟溅出了什么。

溅出的东西出乎所有人意料。GPT-2 时代的 zero-shot 是"给一句指令就开干"，效果参差；GPT-3 发现只要在提示词里再贴几个示例（few-shot），模型就能模仿这个格式完成新任务，而且规模越大，这种"看例子学习"的能力涨得越快。这个被称作"in-context learning"的现象，不是平滑改进，而是在大模型上才显著涌现的——它是后来"涌现能力"研究的第一个著名案例。GPT-3 承接了 GPT-2 的解码器路线和 Scaling Laws（缩放定律）的理论预言，开启了"大力出奇迹"的规模化时代，也为 InstructGPT、ChatGPT 埋下了直接的种子。

02研究背景

要理解 GPT-3 为什么必须出现，得回到 2020 年初 NLP 圈那个"微调税"的死结。彼时主流范式是 BERT 和 GPT-2 共同确立的预训练 + 微调：先在无标注文本上预训练一个大模型，再针对每个下游任务，收集几千到几万条标注数据，跑一轮梯度下降，得到一个专用模型。这套范式很强，但有三个绕不开的痛点：

  • 每个新任务都要交"数据税"。想做情感分析，标一批；想做法律问答，再标一批。标注成本是 NLP 的天花板，新任务永远等不起。
  • 一个任务一个模型。你养了一屋子专用模型，部署、维护、迭代都是负担，根本没有"通用模型"的影子。
  • 微调会过拟合窄分布。模型可能在基准上刷高分，靠的却是数据集里的统计捷径，换个分布就露馅——它学到的不是真本事，是应试技巧。

论文开篇就点出了人和机器的鸿沟：人类做一个新语言任务，通常只需要几句说明或几个示例——你告诉一个人"把这句话从英文翻成法文"，再举一个例子，他就会了。而 2020 年的 NLP 系统，哪怕只是判断一句话是喜是悲，都得先喂它成千上万条标注。GPT-2 曾暗示这条路可以走通（zero-shot），但能力还弱。OpenAI 想问的是：如果把规模再推高两个数量级，模型能不能像人一样，看几个例子就学会新任务？

类比 把语言模型想象成一个见多识广的考生。微调，相当于送他去培训班刷半年题——扎实，但每考一科就得重训一次。zero-shot，相当于只给他看考试说明就进考场——省事，但容易抓不住题意。few-shot 是中间那条更妙的路：进考场前，让他瞄两道带答案的样题，"哦，原来这科是这么个问法"，然后照葫芦画瓢。GPT-3 的赌注是——只要这个考生脑子够大（参数够多、见识够广），瞄两眼样题就能考过刷了半年题的选手。

给 OpenAI 这份信心的，是 2020 年 1 月自家发表的 Scaling Laws for Neural Language Models（缩放定律）。那篇论文发现：语言模型的损失（loss）和参数量、数据量、算力之间是幂律关系——每个量级放大，损失就按可预测的比例下降。这意味着"再加 scale 还能继续涨"不是玄学，是有数学规律的。GPT-3 本质上就是把这条规律外推两个数量级的实验：既然 GPT-2 的 15 亿还欠拟合，那就上 1750 亿，看看规律还成不成立、会不会撞墙。

03核心问题

一句话：能否在不更新任何参数、不做任何微调的情况下，仅靠在提示词里给出任务描述和少量示例，让语言模型完成它从没专门训练过的新任务？而且，这种能力是不是会随规模增长而非线性地"涌现"出来？

更技术地说，作者想验证一个假设：标准的自回归语言建模目标，在大规模下会隐式地学会一种"元学习"。模型在训练时见过的互联网文本里，本身就包含无数"任务示范"（一段文字后面跟着它的摘要、一个问题后面跟着答案），于是模型学会了"看着上下文里的模式，续写符合该模式的输出"。评估时只要把任务示例拼进上下文，模型就会把这个机制激活——这就是 in-context learning。它的形式可以写成：

$$ P(\text{output} \mid \text{task},\ \text{example}_1,\ \ldots,\ \text{example}_K,\ \text{input}) $$ (1)

整个过程中权重 θ 完全冻结，没有任何梯度回传。模型"学到"的东西，全发生在它读完提示词、吐出第一个答案之间的那一次前向传播里。

思考一下 如果一个模型在训练时只做过"预测下一个词"这一件事，它凭什么能"看几个例子就学会新任务"？换句话说，模型从训练数据里学到的，到底是一种"任务能力"，还是一种"看上下文模仿模式"的元能力？这两种解释，对"AI 是否真的在理解"意味着什么不同的东西？

04方法详解

GPT-3 的方法论可以用三个词概括：放大、换料、看戏。放大模型到 1750 亿、换更海量更清洗的数据、然后冷眼观察规模到底解锁了什么。我们分四步拆解。

4.1 模型规模：八级阶梯，只为一个对照

GPT-3 最被忽视的工程巧思是——它不只有一个 1750 亿的模型，而是同时训练了 8 个不同规模的模型，从 1.25 亿一路到 1750 亿。这不是浪费，而是为了画出"规模 vs 能力"的曲线。没有小模型做对照，你根本说不清 few-shot 能力到底是"大模型才有"还是"小模型也有只是没被发现"。

4.2 架构：仍是 GPT-2，只加了一种注意力

架构上 GPT-3 几乎没发明新东西，就是 GPT-2 那套纯解码器 Transformer（Pre-LN、残差缩放、字节级 BPE 全部沿用）。唯一的结构改动是：在 Transformer 各层里交替使用稠密注意力和局部带状稀疏注意力（alternating dense and locally banded sparse attention），思路借鉴自 Sparse Transformer。

为什么需要稀疏注意力 稠密注意力是"每个词都看所有词"，计算量随序列长度平方增长；稀疏注意力是"每个词只看附近一段窗口"，把平方降成近线性。GPT-3 把两者交替着用——既保留全局建模能力，又省下大笔显存，让 2048 的上下文窗口在 1750 亿参数的庞然大物上还能跑得动。这是当时把模型做到这个规模的工程前提之一。

4.3 训练数据：45TB 网页，过滤成 3000 亿 token

GPT-2 用的是 40GB 的 WebText，GPT-3 直接上了 45TB 的原始 Common Crawl，量级差了上千倍。但海量不等于高质量，OpenAI 在数据清洗上花的功夫比模型本身还多。他们用了一套聪明的"以 WebText 为锚"的过滤法：

  1. 拿 WebText2（高质量）作正样本、随机 Common Crawl 作负样本，训一个分类器；
  2. 用这个分类器给 45TB 的 Common Crawl 打分，只保留"看起来像高质量网页"的部分；
  3. 再做模糊去重（n-gram overlap），删掉大量重复和近重复内容；
  4. 混入 WebText2、Books1、Books2、Wikipedia，并按数据质量加权采样——越高质量的来源，训练时被抽中的概率越高（Common Crawl 虽然量大，但在训练里只占约 60% 的权重）。

这套加权采样透露了一个朴素但关键的洞察：数据质量比数据量更值钱。Wikipedia 只占 3% 的量却拿了 3% 的权重，Common Crawl 占了 96% 的量却只拿 60% 的权重——也就是说每一条 Wikipedia 文本被反复学习的次数，远多于一条普通网页。这个思路后来被 LLaMA、RefinedWeb 等开源工作继承并强化。

4.4 In-Context Learning：三种"看题"姿势

这是 GPT-3 最核心的概念贡献。论文把模型使用方式系统化成三种设置，区别只在提示词里给多少示例：

  • Zero-shot：只给一句任务描述，不给示例。"Translate English to French: cheese →"。模型得纯靠指令理解任务。
  • One-shot：给一个示例。"sea otter → loutre de mer; cheese →"。
  • Few-shot：给 K 个示例（论文里通常 K=10~100，受 2048 上下文窗口限制）。贴一堆翻译对，最后留一个"cheese →"让模型补。
Translate English to French:
  sea otter => loutre de mer
  cheese   => ?
  ↑ 模型在这里续写出 "fromage"
关键洞察 注意 few-shot 和微调的本质区别：微调是用数据改模型的权重，是"把知识焊进脑子里"；few-shot 是把示例塞进上下文窗口，权重一个数字都不动，是"开卷考试时临时翻到这一页"。模型在前向传播里"读取"这些示例，并在生成时模仿它们的格式。这意味着同一个模型、同一份权重，换一段提示词就是换一个"临时技能"——这是大模型从"研究工具"变成"通用平台"的接口革命。

论文用"元学习"框架解释这件事：模型在预训练时，见过的每一段文本都可以看作"给定上文、预测下文"的一个任务实例；于是它学到的不是某个具体任务，而是"根据上下文里的模式推断当前要做什么"这种更上位的能力。规模越大，这种元学习的能力越强——这正是下一节实验要验证的。

05实验结果

GPT-3 在 40 多个 NLP 基准上做了评测，横跨语言建模、问答、翻译、阅读理解、算术、新词造句等。结果可以用一句话概括：few-shot 的 GPT-3 在很多任务上追平甚至超过了专门微调过的模型，而它一个梯度都没更新过。

几个最戏剧性的发现：

  • few-shot 把 LAMBADA 准确率从 68% 顶到 86.4%，比此前 SOTA（一个 170 亿参数的专门模型）高了 18 个点。而 GPT-3 为这个任务做的全部准备，就是在提示词里贴几段"上文→末词"的示例。
  • 闭卷问答（TriviaQA）few-shot 达到 71.2%，和专门微调的模型打平。这意味着模型把训练时"读"到的知识，以参数形式记住了，还能在推理时按提示词格式调出来。
  • 它能做三位数加减法，准确率约 92%——但到四位数以上就崩了。这是个微妙信号：模型学到了某种"算法"的影子，但还不是真懂进位逻辑。
  • 生成的新闻文章，人类辨别真假只有约 52% 的准确率，最佳案例下甚至低到 12%——基本等于瞎猜。这是"机器写作难辨真伪"第一次被严肃量化。

但比这些数字更震撼的，是论文图 1.1 揭示的规律。三种设置的成绩确实都随规模上升，但真正惊人的是——规模越大，few-shot 相对 zero-shot 的优势就越明显。在 1.3B 的小模型上，贴不贴示例差别不大；到了 175B，同样的示例能换来几十个准确率点的提升。换句话说，"看例子学习"这件事本身，就是一种随规模涌现的能力。

令人不安的副产品 论文诚实地记录了模型能流畅生成"以假乱真"的新闻、能模仿风格写作、能被用来批量生成钓鱼邮件和虚假评论。这部分被单列为"Broader Impacts"（更广泛影响）一章，占了论文相当篇幅。OpenAI 因此没有开源权重，而是只通过 API 提供——这个决定直接塑造了之后三年"闭源大模型 + API 经济"的产业格局。

06影响与意义

GPT-3 的影响怎么高估都不过分，它至少改写了四件事：

  • 把"提示工程"推上了职业舞台。few-shot 证明"怎么写提示词"直接影响能力上限，prompt engineering 从此成为一个独立工种和研究方向，催生了后来的 chain-of-thought、思维树、in-context learning 理论整条线。今天你跟任何大模型对话时多打一句"请一步步思考"，源头就在 GPT-3。
  • 验证了 Scaling Laws 的外推有效。GPT-3 是缩放定律第一次被推到两个数量级外的工程验证——规律没撞墙，loss 继续降，能力继续涨。这给了整个行业"大力出奇迹"的信心，直接催生了 PaLM、LaMDA、Megatron-Turing NLG 等一堆千亿/万亿参数模型。
  • 开启了大模型的商业时代。2020 年 6 月 11 日，OpenAI 上线 GPT-3 API，这是通用语言模型第一次作为商业服务对外提供。"文本输入、文本输出"这个极简接口，让成千上万开发者不训练任何模型就能做产品——Copilot、Jasper、Notion AI 的雏形都建立在 GPT-3 API 之上。
  • 第一次清晰展示了"涌现能力"。few-shot 随规模非线性增强的现象，是后来"Emergent Abilities of Large Language Models"研究的经典案例。它让学界意识到：大模型不只是"小模型按比例放大"，某些能力是过了某个规模阈值才出现的。

更重要的是，GPT-3 划定了一条清晰的血脉：GPT-3 → InstructGPT（加 RLHF）→ ChatGPT → GPT-4。今天所有人用的 ChatGPT，其架构、目标函数、in-context 接口、自回归生成，全都在 GPT-3 这里定型。InstructGPT 只是在它上面加了对齐，ChatGPT 只是把对话包装成产品。某种意义上，今天所有对话式 LLM 都是"带对齐的 GPT-3"。

07局限性与未来方向

GPT-3 论文难得地用了整整一章（Section 5）自曝家丑，后来者一个个补上了这些洞：

  • 没做指令对齐，很难"对话"。原生 GPT-3 是个续写机器，你问它问题它可能接着续写一个问题而不是回答。这个洞要等 InstructGPT 用 RLHF 才真正补上，进而诞生 ChatGPT。
  • 上下文窗口只有 2048 token。约 1500 个英文单词，few-shot 的示例一多就塞不下。后来的 Longformer、GPT-4 32K/128K、Claude 200K 都在补这个洞。
  • 幻觉照旧。GPT-3 会一本正经地编造事实、编造参考文献、编造 API。这是自回归语言建模的固有副作用，后来用 RLHF、RAG、工具调用一层层缓解，至今未根除。
  • 对提示词极度敏感。示例的顺序、措辞、数量都会显著改变结果，换个同义说法性能可能暴跌。这个"脆弱性"催生了后来对 prompt 鲁棒性的大量研究。
  • 训练数据污染。论文坦承：过滤 Common Crawl 时有个 bug 导致部分基准数据漏进了训练集，而重训成本太高无法补救。这是大模型时代"数据污染"问题最早的高调案例，后来每家都把去污染当成标配流程。
  • 规模化路线本身被质疑。GPT-3 把钱都砸在"加参数"上，但数据只用了 3000 亿 token。后来的 Chinchilla 会指出：这个配比其实严重欠训练，同样算力下该多喂数据、少堆参数。这是下一篇要讲的故事。

08领域演进脉络

把镜头拉远，"生成式语言模型"这条线是一路这样走过来的：

  1. 2013 前后：word2vec 让词有了"语义坐标"，但每个词只有一个固定向量。
  2. 2017（系列第 1 篇）：Transformer 用纯注意力替换 RNN/CNN，奠定所有后续大模型的架构基础。
  3. 2018（系列第 2 篇）：BERT 用双向 Encoder + 掩码语言模型，在"理解"类任务上横扫，确立"预训练 + 微调"范式。
  4. 2019（系列第 3 篇）：GPT-2 把 Decoder 路线放大到 1.5B，第一次证明 zero-shot 多任务可行，把"任务"压缩成"提示词"。
  5. 2020.01：Scaling Laws 给出"规模与损失的幂律关系"，为"再加 scale 还能涨"提供理论依据。
  6. 2020.05（本篇）：GPT-3 把规模推到 1750 亿，发现 few-shot/in-context learning 随规模涌现，开启"大力出奇迹"时代。
  7. 2022：Chinchilla 修正规模化路线（算力该多投数据而非参数）；InstructGPT 用 RLHF 完成对齐。
  8. 2022 末及之后：ChatGPT 把对话式 LLM 推向大众，理解与生成在"超大规模 + 指令微调 + 人类反馈"中重新汇流。

本系列的 Transformer 锻了利刃，BERT 把它磨成理解工具，GPT-2 让人看到"这把刀还能自己挥"，本篇 GPT-3 则把刀挥到了一个前所未有的力度——并记录下水花里溅出的、连作者都没想到的东西。下一篇我们要看的，是一个敢说"GPT-3 这把刀其实挥错了方向"的研究。

09趣味延伸

GPT-3 论文本身比模型还"重"——75 页、31 位作者，是当时 AI 圈少见的长篇。它拿下 NeurIPS 2020 最佳论文奖，评审组给出了一句后来被反复引用的评价："一个预期会产生重大影响、且很可能经得起时间考验的惊人结果"。如今回头看，这句评价准得可怕。

最有趣的对比是 OpenAI 对待 GPT-2 和 GPT-3 的态度反转。一年多前，GPT-2 因为"太危险"被分阶段、磨蹭了九个月才放全模型；到了 GPT-3，能力强大了 116 倍，OpenAI 反而不开源了，只给 API。这看似矛盾，实则精明——不开源就没有"模型被恶意复现"的隐患，又能靠 API 计费把能力变成现金流。一场"安全顾虑"，悄悄变成了"商业模式"。

小八卦 GPT-3 的训练成本至今是业内津津乐道的话题。按 3640 petaflop/s-days 的算力和当时 V100 的价格估算，单次训练花费在数百万美元量级——这还不算前面 7 个小模型和无数失败实验的开销。有人算过，这笔钱够买一屋子顶配 GPU，也够一个小型 NLP 实验室运转十几年。但 OpenAI 赌赢了：GPT-3 API 上线后，开发者生态爆发，这笔投入很快被订阅费赚了回来。这是 AI 史上第一次"烧钱训练 → 卖 API 盈利"的闭环跑通。

还有两个鲜为人知的细节。其一，论文里那个经典的"cheese → fromage"翻译示例，其实暗藏玄机——GPT-3 的翻译能力在译入英语时远好于译出英语，因为训练数据绝大多数是英文。这个"语言不对称"后来成了所有英文中心大模型的通病。其二，论文诚实地承认训练数据过滤有 bug 导致基准污染，这种"自曝其短"在顶会论文里相当罕见——但它反而增强了论文的可信度，因为连作者都承认的数据问题，都没掩盖住模型的能力。

10个人解读与延伸思考

读 GPT-3，最让我震撼的不是 1750 亿这个数字，而是它揭示的一种研究范式转移。在 GPT-3 之前，做 NLP 的默认动作是"设计一个新方法"——新架构、新损失、新训练技巧；GPT-3 之后，默认动作变成了"把一个朴素方法推到极致，然后观察涌现了什么"。这种"先 scale、再观察"的哲学，把 AI 研究从"工程师手艺"推向了"实验科学"——你不再设计智能，你制造条件让智能自己长出来，然后记录它的长相。

另一个值得玩味的是 in-context learning 的"哲学暧昧"。GPT-3 看几个例子就能做新任务，但它真的"学会"了吗？严格说，它的权重一个数字都没变——它只是在前向传播里"读"了这些示例，然后在生成时模仿它们的统计模式。这更像"开卷抄格式"，而不是"把知识装进脑子"。这个区别不是抬杠：它决定了我们该如何理解大模型的"能力边界"。当你给它一个从未见过的、需要真正推理的任务，它的 few-shot 表现可能瞬间崩塌——因为它依赖的是模式匹配，不是符号推理。这恰恰解释了为什么 GPT-3 做三位数加法很溜、五位数就崩。

最后一点个人判断：GPT-3 是"参数规模派"的巅峰，但它也埋下了这条路被推翻的种子。它把算力几乎全砸在堆参数上，数据只喂了 3000 亿 token——这个配比后来被证明是低效的。下一篇我们要看的 Chinchilla，会用同样的算力、更小的模型、更多的数据，打得 GPT-3 满地找牙。大力能出奇迹，但怎么使力，比使多大力更重要——这是 GPT-3 留给后人的最大课题。

留个问题给你 GPT-3 证明了"看几个例子就能学"。但仔细想：模型在 few-shot 时"学到"的，和人类"学会"一个技能，是同一回事吗？如果你给 GPT-3 看三个"把数字倒着写"的例子，它能照做；但如果你问它"为什么要倒着写"，它会茫然。这种"会做但不懂为什么"的能力，算不算真正的智能？再想一步：人类有多少技能，其实也是这种"会做但说不清为什么"的模仿？

Training Compute-Optimal Large Language Models (Chinchilla)

GPT-3 把算力几乎全砸在堆参数上，喂的数据却相对寒酸。DeepMind 的研究者问了一个尖锐的问题：同样多的算力，到底是该堆参数、还是该喂数据？他们训练了一个 700 亿参数的"小"模型 Chinchilla，喂了 1.4 万亿 token——结果这个小家伙在几乎所有任务上反杀了 1750 亿的 GPT-3。下一篇，我们来看这场推翻"参数至上"的算力分配革命，以及它如何改写了对"怎样训练大模型"的根本认知。
