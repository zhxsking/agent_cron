大模型经典论文精读系列 #035

ReAct: Synergizing Reasoning and Acting in Language Models ReAct：把“思考”和“行动”交织成循环——Thought→Action→Observation 的推理-行动协同范式，让模型一边想一边调工具，agent 时代的奠基之作

作者：Shunyu Yao, Jeffrey Zhao, Dian Yu, Nan Du, Izhak Shafran, Karthik Narasimhan, Yuan Cao 机构：Princeton University / Google Research, Brain team 发表：2022-10 · arXiv，ICLR 2023 (Oral, Notable Top 5%)
arXiv GitHub Project

2022 年 10 月，普林斯顿的一间实验室里，一位博士生正在给大模型出题：“除了 Apple Remote，还有什么设备能控制 Apple Remote 原本设计的程序？”他让模型只用脑子想、不准查资料——模型自信满满地回答“iPhone、iPad、iPod”，可惜答案该是“iPod”。接着他换了个玩法：允许模型边想边去查维基百科。这一次，模型搜了 Apple Remote，发现“Front Row”程序，再搜 Front Row，读到它“由 Apple 键盘功能键控制”，于是写下结论，给出答案。

这不是更准了一点点的问题。前一种“只想不动手”的模型，有 56% 的错误来自一本正经地胡编乱造（学术上叫“幻觉”）；后一种“想一步、查一步”的模型，幻觉错误几乎归零。这篇让模型“一边想一边动手”的论文，就是今天 agent（智能体）浪潮真正的起点——它的名字叫 ReAct。

一句话总结 ReAct 把“推理（Thought）”和“行动（Action）”交织成一个循环，让大模型边想边调工具、边查边修正，用一个最朴素的“思考→行动→观察”循环，奠定了此后所有语言智能体的标准控制流程。

01领域定位

如果说本系列第 24 篇 Chain-of-Thought 解决了“模型会不会分步想”，第 34 篇 Toolformer 解决了“模型会不会用工具”，那么 ReAct 解决的是一个更根本的问题：“想”和“用”能不能在同一根思维线上来回穿插？

在 ReAct 之前，这两条路线是分裂的。推理派（CoT、Self-Consistency、Tree of Thoughts）让模型在脑子里画推理链，但模型的“脑子”是闭卷的，知识冻在训练权重里，一旦记错就会一路错到底；行动派（WebGPT、SayCan）让模型去调搜索引擎、操控机器人，但模型只管“做”不解释“为什么做”，遇到意外就抓瞎。ReAct 把这两半焊在一起：用思考去规划行动，用行动去给思考补充外部事实。它既是 CoT 思维链的“接地”版，也是工具调用的“会思考”版。

它开启的不是一项技术，而是一整个时代——后来所有“agent”框架的控制流，几乎都能在 ReAct 的循环里找到原型。LangChain 的作者 Harrison Chase 公开说过，ReAct 是他创办 LangChain 时最早看到的、最启发他的论文之一。

02研究背景

2022 年的 LLM 研究者面前摆着两个看起来都很强、却互不来往的“半身人”。

一个是推理派。代表是思维链（CoT）：给模型看几个带推理草稿的例子，它就能分步想出数学题、常识题的答案。但 CoT 是个“闭卷考生”——它只能翻自己脑子里的记忆，而记忆是训练时冻结的、会记错的。论文里有个残酷的统计：在 HotpotQA 上，纯 CoT 的错误里有 56% 是幻觉，也就是模型把不存在的事编得头头是道，还一路错传下去（这叫“错误传播”）。

另一个是行动派。代表是 WebGPT、SayCan 这类工作：让模型去调浏览器查网页、给机器人下动作指令。它能接触真实世界，但模型只输出“干什么”，不输出“为什么这么干”，没有计划、没有工作记忆，环境一变就懵。

类比 把任务想象成在陌生厨房里做一道菜。CoT 像一个全程闭眼、只凭记忆炒菜的厨师——他记得很多菜谱，但记混了盐和糖你拦不住；行动派像一个只会按菜谱机械操作、从不思考的帮工——菜谱说放盐、可盐罐空了，他就卡在那儿不动了。真正会做菜的人是第三种：边切菜边嘀咕“现在该烧水了”，发现没盐就嘀咕“那用酱油和胡椒替”，忘了和面步骤就嘀咕“我上网查一下”——思考指导行动，行动反哺思考，这正是人类认知里的“内部言语”。

ReAct 的作者们注意到，这种“边想边做”的能力，在心理学里早有名字：维果茨基称之为“内部言语”（inner speech），被认为负责自我调节、策略制定和工作记忆。他们提出一个朴素的疑问：既然人脑是这么干活的，为什么不让语言模型也这么干？

03核心问题

一句话：能不能让大模型把“自由形式的语言推理”和“面向任务的具体行动”交织在同一条轨迹里，并且让两者互相增益——推理用来规划、跟踪、纠正行动，行动用来从外部世界（知识库、环境）取回信息喂给推理？

思考一下 如果你是模型，面对“Jason Statham 主演的《敢死队》系列导演是谁”这种要查两跳的问题，你会怎么安排“想”和“查”的顺序？是一口气全想完再查，还是想一步查一步？哪种更容易出错、为什么？

04方法详解

ReAct 的方法简洁到让人怀疑“这就完了？”——但正是这种简洁让它成了后来所有 agent 的母模板。

核心一招：把“想”也变成一种行动

标准 agent 的设定是：每一步接收一个观察 $o_t$，按策略输出一个动作 $a_t$。ReAct 做的事情，是把动作空间从 $\mathcal{A}$ 扩成 $\hat{\mathcal{A}} = \mathcal{A} \cup \mathcal{L}$——其中 $\mathcal{L}$ 是语言空间。落到语言空间里的那个动作，就叫一个“思考”（Thought）。

$$ \hat{\mathcal{A}} = \mathcal{A} \cup \mathcal{L}, \qquad a_t \in \mathcal{L} \text{ 称为 Thought} $$ (1)

关键在于：Thought 不改变外部环境，所以不会产生新的观察。它唯一的作用，是把“对当前上下文推理一番”的结论写回上下文，让后面的行动或推理更靠谱。论文列举了 Thought 能干的好几件事：拆解目标、制定计划、注入常识、从观察里摘出要点、跟踪进度、处理异常、调整计划。

核心二招：让“想”和“做”按任务密度自适应交织

ReAct 没有规定死板的格式，而是按任务类型给两种织法：

  • 推理密集型任务（问答、事实验证）：Thought 和 Action 密集交替，形成 Thought → Action → Observation 的多轮循环。
  • 决策型任务（文本游戏、网页操作）：动作往往很多，Thought 只需稀疏地出现在关键位置——并且由模型自己决定何时插入。

工具与少样本：一个极简的维基百科 API

ReAct 没有搞复杂的检索器，而是给模型一个故意做“弱”的维基百科接口，逼它用语言显式推理来检索。接口只有三个动作：

  • Search[entity]：返回该实体词条页的前 5 句；找不到就返回搜索引擎推荐的 5 个近似实体。
  • Lookup[string]：在当前页里找下一个包含该字符串的句子，模拟浏览器的 Ctrl+F。
  • Finish[answer]：给出答案，结束任务。

作者强调，这个接口比主流检索器弱得多——只能按词条精确名取一小段。目的是模拟“人怎么查维基”，并强迫模型靠显式语言推理来导航。模型是冻结的 PaLM-540B，只靠 6 个（HotpotQA）或 3 个（FEVER）手写的人例做少样本提示，没有微调。

05实验结果

论文在四个差异极大的基准上检验 ReAct：两个偏知识推理（HotpotQA 多跳问答、FEVER 事实验证），两个偏交互决策（ALFWorld 文本游戏、WebShop 网页购物）。

知识推理：接地让幻觉几乎归零

在 FEVER 事实验证上，ReAct（60.9）直接超过 CoT（56.3）和纯行动（58.9）。在 HotpotQA 上 ReAct（27.4 EM）略逊于 CoT（29.4）——但论文给出一个关键洞察：这并非“想+做”输了，而是那个故意做弱的维基 API 拖了后腿，检索不到时模型宁可说“查不到”。更猛的组合是 ReAct + CoT 自洽（self-consistency）：先用 ReAct 取回外部证据，再让 CoT-SC 在内部知识与外部证据间投票，HotpotQA 拿到 35.1，FEVER 拿到 64.6，全面登顶。

人工分析揭示了“为什么”：CoT 的失败有 56% 是幻觉，ReAct 的幻觉失败几乎是 0%。ReAct 的主要失败模式不是胡编，而是“检索受限/搜索词没找对”——这是一种更诚实、可诊断的错误，而非难辨真伪的胡说。

交互决策：两个例子反杀十万级训练数据

真正的震撼来自决策任务。ALFWorld（文本家务游戏）上，ReAct 只用 1–2 个少样本例子，就比用 10⁵ 个回合训练的模仿/强化学习方法高出 34 个百分点的绝对成功率。WebShop（模拟网购）上，ReAct 同样用极少的例子，把成功率拉到 40%，比 imitation learning 的 29.1% 高出约 10 个绝对点。

还有个“量变到质变”的发现：当允许微调时，只需 3000 个例子，ReAct 就成为四种方法里最强的——PaLM-8B 微调 ReAct 反超所有 PaLM-62B 提示方法，PaLM-62B 微调 ReAct 反超所有 540B 提示方法。这暗示：教会模型“怎么推理+行动”去获取信息，远比让它“记住事实”高效。

06影响与意义

ReAct 的真正遗产不是那几个百分点的提升，而是它给整个行业提供了一套控制流的原语。Thought-Action-Observation 这个三段循环，后来成了 LangChain、LangGraph、LlamaIndex、Hugging Face transformers agents 等几乎所有 agent 框架的默认骨架。今天你听到的“function calling”“tool use”“agentic workflow”，骨子里大都能追到 ReAct。

它还顺手把“可解释性”重新拉回 agent 设计的中心：因为每一步行动前都有显式的 Thought，人能一眼看懂模型为什么这么干、信息是从内部来的还是查来的，甚至可以中途编辑 Thought 来纠正模型。这把 agent 从“黑箱执行器”变成了“可审查的协作者”。

07局限性与未来方向

ReAct 也并非银弹，论文自己大方承认了几处短板：

  • HotpotQA 上略输 CoT：根源在那个故意做弱的检索接口，检索失败时模型“老实”地说查不到，反倒拉低了分数——这其实暴露了“推理能力 vs 工具能力”的失衡。
  • 长轨迹撞上下文长度：行动越多，轨迹越长，少样本示例容易撑爆 in-context 的输入上限，作者已开始尝试微调缓解。
  • 单线推理、不会回溯：ReAct 是一条道走到黑的循环，错了难回头——这恰恰是后来 Reflexion（本系列第 31 篇）、Tree of Thoughts（第 27 篇）、LATS 等要补的课。

后来者的“判决”也印证了这点：2025 年 11 月 LangGraph v1.0 把 create_react_agent 标记为非推荐，转向带 hook 与持久化状态（Durable State）的中间件架构——行业在说“光有裸 ReAct 循环不够，还得能回滚、能并行、能容错”。但这恰恰证明 ReAct 是个足够结实的底座，值得被反复改造而非推倒重来。

08领域演进脉络

把 ReAct 放回本系列已走过的路上看，脉络格外清晰：

Transformer（第 1 篇）打下模型底座 → BERT/GPT 系列（2–4 篇）确立预训练范式 → Chinchilla/InstructGPT（5–6 篇）解决“训得对、听人话” → 进而对齐与应用期，推理派与行动派分头开花：CoT（24）、Self-Consistency（26）、Tree/Graph of Thoughts（27、28）让模型在脑内越想越深；Self-Refine、Reflexion、CRITIC、Self-RAG、Toolformer（29–34）让模型学会自我纠正与调工具。ReAct 正是这两条支流在此汇合的河口——它把“脑内推理”和“外部行动”焊成一根循环，agent 范式由此立柱。再往后，推理范式期（2025–）的 o1、DeepSeek-R1 把“思考”本身变成可训练的算力消耗，但那已是把 ReAct 的“想”推到极致的另一条故事线了。

09趣味延伸

ReAct 背后有个很有意思的人：一作姚顺雨（Shunyu Yao）。他 2015 年以全省第三、704 分的成绩考入清华姚班，在校期间还是清华学生说唱社的联合创始人——一个能写代码也能写 flow 的硬核跨界选手。2019 年他到普林斯顿读博，导师 Karthik Narasimhan 来头也不小：当年在 OpenAI 做访问学者时，正是 GPT-1 的第二作者。姚顺雨自己回忆，第一次见面导师问“你想做什么”，他答“你做过的那些 text game，能不能用语言模型重做一遍”——整个 agent 之旅，就从这句闲聊开始。ReAct 这项工作，正是他在 Google 实习期间完成的。

命运的伏笔在后面：ReAct 之后姚顺雨又写了 Tree of Thoughts、CoALA，2024 年加入 OpenAI 做 Operator、Deep research 等智能体产品，2025 年末出任腾讯首席 AI 科学家。一个博士期间的开山之作，最后长成了他整个人生的事业线。论文本身也争气：被 ICLR 2023 选为 Oral（Notable Top 5%），如今引用过万，GitHub 星标近四千——一篇“就想看看能不能让模型边想边查”的小文章，意外地成了 agent 时代的奠基礼。

10个人解读与延伸思考

ReAct 给我最大的启发，是一种研究哲学：把人脑里理所当然的机制，老老实实地复刻给模型。它没有发明任何花哨的新结构，只是承认了“思考”和“行动”本就该交织，然后给模型一个能容纳“想”的动作空间。这种“向人类认知借图纸”的朴素，恰恰是它能成为母范式的原因——简单到所有人都能用、能改、能扩展。

但 ReAct 也提醒我们一件事：智能体的瓶颈，从来不只是“会不会想”或“会不会用工具”，而是两者能否动态平衡。HotpotQA 上 ReAct 输给 CoT，本质是工具太弱拖累了思考；后来 agent 框架不断加 hook、加回滚、加并行，本质上都在补“单一循环太脆”的课。今天我们谈论 agent，很容易被各种新框架晃花眼，但回到 ReAct 这篇 2022 年的小文章，你会发现所有问题它都预言过、所有方向它都指过路。

留个问题给你 如果今天让你重新设计一个 ReAct 循环，面对“单线推理不会回溯”这个老毛病，你会给 Thought-Action-Observation 加一个什么机制，让模型在走错时能“撤回重来”而不只是硬着头皮往下走？（提示：本系列第 27、31 篇给过两种截然不同的答案。）
