OpenSkill: Open-World Self-Evolution for LLM Agents OpenSkill：开放世界自进化——没有标准答案时，agent 如何从零给自己搭一个“验证器”

作者：Zhiling Yan*, Dingjie Song*, Hanrong Zhang 等 11 人（* 共同一作） 机构：Lehigh · UIC · UBC/Vector · Salesforce AI Research · MGH/Harvard 发表：2026-06 · arXiv 2606.06741 · EMNLP 2026
arXiv GitHub Project

想象你刚入职一家公司，主管把一个文件夹拍在你桌上：“把这批医疗数据算出骨密度指标，出一份分析报告。”说完人就走了。没有培训手册，没有前辈带教，甚至没有“交作业标准”——你不知道报告该长什么样，更不知道交上去之后，谁来判断你做得对不对。公司只有一句要求：在岗自我提升。

过去几篇我们一路追着“自进化”这条主线：Self-play SWE-RL 让 agent 自己给自己出软件任务（第 54 篇），Absolute Zero 让模型自己出题自己解（第 55 篇），R-Zero 把出题人和解题人拆成两个模型（第 56 篇），R-Few 给自博弈掺了一丁点人类示例当锚（第 57 篇），上一篇 Self-aware RL 又教会模型“知难而退”、主动求助（第 58 篇）。但不知道你注意到没有，这些方法都有一个共同的“暗桩”：背后总站着一个能判对错的裁判——代码跑测试、数学对答案。可主管拍在你桌上的这种活儿，裁判在哪？报告写得对不对，没有任何标准答案可对。上一篇结尾我们留下的正是这个问题：裁判不在场，自进化的飞轮还转得起来吗？

2026 年 6 月，一支来自理海大学、UIC、Salesforce 等机构的团队交出了他们的回答：裁判不在场，那就自己“请”一个——从开放世界里请。他们给系统起名 OpenSkill：让 agent 在没有标准答案的世界里，自己查资料写“技能小抄”，再自己出一份“模拟考”来批改小抄，改到满意才带进考场。听起来像自欺欺人？可它最后在三个基准上拿下了所有自动化方法里的最好成绩，离人类专家亲手写的技能只差一步之遥。

一句话总结 把 agent 扔进“没有标准答案、没有裁判、没有前辈笔记”的开放世界，OpenSkill 让它自己检索资料写出可复用的技能小抄，再用从开放世界锚定的自建虚拟测试批改、迭代小抄——全程不偷看任何标准答案，最终成为三个基准、两套目标模型上的最强自动化方法，与人类专家技能只差 1–3 个百分点。

01领域定位

如果把“自进化 agent”这条线看成一部长剧，前几季的主角们各有各的靠山：Voyager 有《我的世界》这个“自带说明书”的环境（第 36 篇），Reflexion 有环境反馈当镜子（第 31 篇），自博弈系列有代码和数学这种“天生可验证”的领域（第 54–55 篇）。而 OpenSkill 是那个把所有靠山都撤掉的剧组：只发一句任务描述，其余全靠你自己。

它站在两条线索的交汇点上。一条是技能线：从 Voyager 的技能库，到 AgentFactory、AutoSkill、Memento 这些从自身轨迹里攒技能的框架，再到 SkillsBench 这个专门证明“技能质量才是瓶颈”的基准；另一条是验证线：从 Let’s Verify Step by Step 的过程监督（第 22 篇），到自博弈 RL 的自产验证信号。OpenSkill 把两条线拧在一起，提出了一个此前没人正面回答的问题：当环境不给验证信号时，验证信号能不能也从开放世界里自己长出来？这一问，直接开启了“开放世界自进化”这个新的研究方向——两个月后的 SkillAlchemy 等后续工作，都在它趟出的这条河里继续划桨。

02研究背景

论文开头有一句大实话：现有的自进化 agent，都默认自己站在一个“能用的学习闭环”里——要么有人工整理好的技能，要么有成功轨迹可以蒸馏，要么有验证器告诉你对错。可真实的部署现场呢？可能什么都没有，只有一句任务提示语。作者把这种最严苛的处境单独拎出来，命名为开放世界自进化：从零开始，既要自己造技能，又要自己造验证技能的信号。

具体来说，此前的方案各有一个致命的“暗桩”：

  • 技能从哪来？人工写技能，贵且慢，还未必覆盖新领域；让模型凭参数记忆自己写，写出来的只能是它本来就懂的东西——遇到最新的 API、项目专属的规范、冷门的领域规则就抓瞎；从成功轨迹里蒸馏，前提是你得先成功一次，可开放世界里第一次往往就是失败的。
  • 验证信号从哪来？Reflexion 靠环境反馈，PRM 靠人工标注或模型打分（第 22–23 篇），自博弈 RL 靠“代码能跑通、数学能对答案”。可在“写一份医疗分析报告”这种任务里，没有任何东西会告诉你对不对。

更扎心的是一个基准测试的发现：SkillsBench 专门测“技能质量是不是瓶颈”，结果显示让 Opus 4.6 自己给自己写技能，通过率 23.9%——还不如不写（不用技能是 25.5%）。小抄写错了，比没有小抄更害人。这个反直觉的数据点，几乎是对整个“模型自产技能”路线的一次公开处刑。

类比 · 考一门没有真题的新证 想象你要考一门刚开设的证书，市面上一没有学霸笔记，二没有历年真题，三没有考纲。老三条路全断了：买笔记（人工技能，不存在）、凭记忆默小抄（模型自产，只会写你已经会的）、刷真题总结错题（轨迹蒸馏，没有题可刷）。OpenSkill 的主意乍听很“土”：去图书馆，把公开教材、官方文档、数据集说明书全部翻出来，自己编小抄；再照着教材里白纸黑字、可以独立核对的事实——某个公开数据集有多少行、某个指标必须落在什么区间、输出该是什么格式——给自己出一份模拟卷。模拟卷不是真题，但考点全部锚定在可验证的事实上，而不是“我觉得考这个”。

03核心问题

把背景压缩成一句话，这篇论文要解的问题是：在没有任何目标监督（没有标准答案、没有奖励、没有验证器）的开放世界里，agent 仅凭一句任务描述和可自由访问的开放世界资源，能否从零同时构造出“技能”与“验证信号”，并靠这套自建闭环真正提升目标任务的表现？

论文里有一段很较真的概念辨析，值得单独说：什么才算“监督”？作者划的边界是——看任务输入不算监督：任务描述和执行环境本来就该给你看；只有当你依赖了隐藏的标准答案、奖励或验证器输出，才算偷看。而整套流程必须做到：不仅自己不看答案，也不许反向工程标准测试来造自己的模拟题。

用数学语言说，agent 通过上下文里的技能集 $\mathcal{S}_i$ 来条件化自己的行为，全程不改权重；技能构造函数必须满足“监督自由”：

$$\hat{\mathcal{S}}_i = f(\mathcal{I}_i, \mathcal{E}_i, \mathcal{K})$$ (1)

其中 $\mathcal{I}_i$ 是任务指令，$\mathcal{E}_i$ 是执行环境，$\mathcal{K}$ 是开放世界知识——公开文档、代码库、论文、教程、网页，唯独不包括隐藏的测试 $\mathcal{T}^{\text{GT}}_i$。

思考一下 先别往下看。如果让你给自己的技能“出模拟考”，你怎么保证这份卷子不是自欺欺人？——提示：问题不在“出题的水平和做题的水平一样”吗？注意，出题用的知识来源，可以和做题用的知识来源不是同一份。想想这会有什么效果。

04方法详解

OpenSkill 的答案是“三阶段流水线 + 一道泄漏屏障”：阶段一从开放世界取知识和“锚”，阶段二在沙盒里起草技能、自建模拟考、按诊断迭代，阶段三把冻结的技能零样本交给目标 agent 上考场。隐藏的标准测试被屏障锁在门外，直到最终评估那一刻才解锁。

阶段一：两路检索——一路学知识，一路找“锚”

第一路是主检索 $\mathcal{D}$：把任务指令、元数据和环境文件预览交给一个“深度调研 agent”（用的是 Gemini Deep Research），它满网检索，产出一份背景文档 $k_i$——需要哪些库的哪些 API、函数签名长什么样、参数默认值是什么、有哪些常见坑——再据此合成一份结构化的技能计划 $p_i$，把要写的技能拆成 1–4 份。有个细节很妙：查询合成时被明确要求“只查知识，不要包含解题方法”——查教材可以，搜答案不行。

第二路是论文的得意之笔：验证知识检索 $\mathcal{D}^v$。这一路不要 API 用法，只要四类“独立可验证的锚”：（一）官方文档里的参考值；（二）知名数据集的统计不变量——多少行、和是否为一、取值范围；（三）可以用别的工具交叉验证的程序；（四）已知的输入输出对。为了两路不重复，第一路已查到的前 4000 字符会作为“已知内容，勿重复”塞进第二路的提示词。

还有一道“除名过滤”：所有查询发出去之前，先要把基准测试的名字及其变体从查询里洗掉——防止搜索引擎顺藤摸瓜找到题库本身的答案页。防漏题，防到了搜索框里。

$$\tilde{\mathcal{T}}_i = g(\mathcal{I}_i, \mathcal{E}_i, k_i^{v})$$ (2)

公式 (2) 是阶段二的灵魂：虚拟测试套件 $\tilde{\mathcal{T}}_i$ 由验证锚 $k_i^v$ 锚定生成，是隐藏测试 $\mathcal{T}^{\text{GT}}_i$ 的“影子替身”——等下细说。

阶段二：自建模拟考，外加一个“双盲阅卷官”

技能初稿写好后，谁来批改？OpenSkill 的做法是请一位独立验证器：一个全新的 LLM 会话。关键在于“独立”二字——它和技能创作者共享同一个 Docker 容器（所以看得到产出的文件），却不共享对话：创作者的推理过程、草稿、实现代码，阅卷官一概看不到。这是刻意为之的防确认偏误设计：考官能看你的答卷，但不许看你的草稿纸。

这位阅卷官依据两样东西出题：任务环境里可独立复算的规则，以及阶段一找来的验证锚 $k_i^v$。它输出的是一份确定性 pytest 脚本——每条断言都是能直接执行、非对即错的硬检查，比如“该公开数据集的行数应精确等于某个已知值”“这个指标必须落在 [0, 1] 区间”“输出 JSON 必须包含指定字段”。断言数量上限 60 条，宁缺毋滥。

$$\tilde{r}^{(j)}=\frac{1}{|\tilde{\mathcal{T}}_i|}\sum_{k=1}^{K}\tilde{t}_{i,k}\!\bigl(\pi_\theta(\mathcal{I}_i, \hat{\mathcal{S}}_i^{(j)}, \mathcal{E}_i)\bigr)$$ (3)

一个不含任何 LLM 的解析器跑一遍 pytest，算出虚拟通过率 $\tilde{r}^{(j)}$，作为这一轮技能的质量信号。等于 1 就放行；不等于 1，就进入全论文最有“学习方法论”味道的一步——诊断驱动迭代：

  • 阅卷官产出一份结构化失败报告：每条断言的结果、根因分析、修改建议。
  • 一个轻量分类器读报告，判断失败属于哪一类：SELF-FIXABLE（实现 bug——变量名写错、差一错误、格式不匹配，自己能修）还是 NEEDS-DR（知识 gap——某个正确值不知道、某个库用法没学过，需要回去查资料）。前者直接把报告退还给创作者自己修；后者触发一次定向检索，把补到的知识追加进上下文——每个任务最多补 3 次，防止无限查资料。
  • 循环最多 3 轮。分类器要是失效了，系统保守地默认“自己能修”——绝不多花一次检索的钱。这是很典型的工程保守主义。

阶段三：冻结技能，零样本上考场

迭代结束，技能被“原样冻结”——注意不是挑一个虚拟通过率最高的快照，而是取循环终止时的最新版本，防止在自建模拟卷上刷分刷出来的“应试版”反而中选。冻结的技能被原样复制进目标 agent 的工作区，agent 带着它零样本地执行任务，隐藏测试此刻才第一次登场：

$$\text{PassRate}=\frac{1}{n}\sum_{i=1}^{n}\mathcal{T}^{\text{GT}}_{i}\!\bigl(\pi_{\theta'}(\mathcal{I}_i, \hat{\mathcal{S}}^{*}_i, \mathcal{E}_i)\bigr)$$ (4)

注意 $\pi_{\theta'}$ 这个记号：目标 agent 不必是造技能的那个模型。技能是一份显式的、可打开看的文件，不是焊死在权重里的暗物质——谁拿到都能用。这个选择事后被证明是神来之笔。

最后必须说说那道“泄漏屏障”，因为它是全文最较真的部分。作者做了四层隔离审计：代码层，基座 agent 的函数签名根本不接收任何测试路径；容器层，隐藏测试目录和答案目录压根没有挂载进 Docker 容器——不是“不许看”，是“想看也找不到”；Oracle 层，进化循环覆写了父类的判分调用，构造期间永远走不到标准答案的代码路径；日志层，逐条审计执行轨迹，零条引用。外加提示层明文告知验证器：“你只能用任务指令和环境文件，你没有任何权限访问答案。”

05实验结果

战场布置：三个基准——主战场 SkillsBench（11 个领域、84 个任务，专门考察“技能是否是短板”），外加 SocialMaze（社会推理）和 ScienceWorld（交互式科学实验）；两套目标 agent——Claude Code 里的 Opus 4.6 和 Codex 里的 GPT 5.2，来自两个互相较劲的模型家族。对手是七个自动化基线：不用技能的裸 agent、一次性自写技能的 Self-Gen 和 CoT、Anthropic 官方的 Skill Creator、从经验轨迹攒技能的 AutoSkill 和 Memento，外加 ScienceWorld 专用的 SkillNet。人类专家手写的技能作为参考上界，不参与排名。所有方法同一铁律：构建期间谁也不许碰隐藏测试。

发现一：追平人类，全程没看过标准答案

SkillsBench 上，OpenSkill 拿到 43.6%（Opus 4.6）和 42.1%（GPT 5.2），分别比各自的最强基线高出 +8.9 和 +8.8 个百分点，比裸 agent 高出 +18.1 / +17.1。而人类专家技能是 44.5% / 44.8%——差距被压到了 1–3 个百分点以内。要知道，人类专家是带着完整的领域知识、对照着任务亲手写的技能；而这个 agent 从始至终没有见过任何一道标准测试题。

发现二：它是唯一“换个模型不翻车”的方法

细看表格会发现一个有意思的分裂现象：一次性生成派（Self-Gen、CoT）能帮 GPT 5.2 涨分，在 Opus 4.6 上却双双跌破裸基线；迭代派正好相反——AutoSkill 和 Memento 在 Opus 上还行，一换到 GPT 5.2 直接崩盘：AutoSkill 从 24.7% 跌到 11.2%，Memento 从 30.1% 跌到 15.6%，双双低于“什么都不用”的 25.0%。换句话说，这些从模型自身经验里长出来的技能，与“生它的那个模型”深度耦合，换个宿主就成了毒药。OpenSkill 是唯一在两边都稳定大涨 17 个点以上的方法——开放世界来的知识本就不属于任何模型，自然谁都能用。

发现三：知识密集领域大爆发，部分反超人类

按领域拆开看，OpenSkill 在 Opus 上 11 个领域里 8 个最佳或并列最佳。涨幅最猛的恰恰是最吃“新知识”的领域：Health 领域从 24.8% 拉到 69.6%；GPT 5.2 上 Energy 领域从 0.0% 拉到 80.0%——而人类技能在这个领域也只有 53.3%；Cybersecurity 从 25.0% 到 52.5%，同样反超人类的 42.5%。道理不复杂：医疗、能源、网络安全这些领域拼的是最新的 API、领域专属规范、冷门数据集说明书——正是模型参数里没有或早已过时、而开放世界检索最擅长补给的东西。

发现四：诚实时刻——Manufacturing 全军覆没

值得一提的是论文里的一个“零”：Manufacturing（制造业）领域，所有自动化方法——包括 OpenSkill——全部 0.0%，而人类技能有 46.7%。开放世界检索不是万能钥匙，有些知识可能就是没被好好写到网上，或者任务要求远超任务描述所能提供的信息。作者把这个刺眼的零原样写进了主表，这种诚实值得一个好评。

发现五：技能是资产——Opus 写的小抄，四个“学弟”白嫖

既然技能是显式文件，那换模型用呢？作者把 Opus 4.6 生成的技能原封不动地塞给四个弱得多的模型：Haiku 4.5、Qwen 3 Coder、DeepSeek V3、Mistral Large 3。结果四个“学弟”全线涨分，比各自裸跑高出 5.5 到 14.8 个百分点，且零适应性修改、零额外创造成本。对照组里，AutoSkill 的技能迁移过去之后反而低于裸跑——技能本身把模型“带沟里”了。一次创造、处处复用，这才是“技能资产”该有的样子。

一致率 60.7%，谈不上完美，但统计检验显著——一张“从没见过真题的模拟卷”能做到与真实成绩显著正相关，已经超出很多人的预期。更有意思的是覆盖面：抽 15 个任务，让 LLM 裁判逐条比对模拟卷是否覆盖了人类出题意图，结果覆盖了 88.9%（120/135）的测试意图。没盖住的 11.1% 集中在两类：基准自带的反作弊元检查，以及“分类学一致性、词形还原正确性”这类需要超出任务描述的专业知识才能出的深语义题。还有一个可爱的细节：模拟卷的题量中位数是官方真题的 3.4 倍，平均每个任务多出 15.3 条断言——自己给自己出题，比出题老师还较真，主要多在输出格式、类型合法性、边界条件这些防御性检查上。

发现七：练三遍刚好，练十遍反而退步

消融实验给了两条朴素但珍贵的经验。其一是迭代次数：3 轮最优（82.7%），5 轮掉到 79.9%，10 轮掉到 78.0%——在自己的模拟卷上无限制地“刷题”，会过拟合到模拟卷，反而忘了真题长什么样。其二是组件拆解：把开放世界查询和虚拟验证器都拆掉，只剩参数知识，成绩 74.5%；只装开放世界查询，80.6%；只装虚拟验证器，80.8%；两个都装，82.7%。两个组件各自贡献 +6.1 和 +6.3 个点，合体后再涨 2.1 个点——互补，但纠错有重叠，说明两者都在补“模型不知道自己错在哪”这块短板。

这笔账怎么算 每个任务的技能创造约花费 74.9 万 token、39 分钟；全基准 84 个任务跑完整个流水线约 140 小时、9700 万 token，按牌价折合约 1800 美元。听起来不便宜？别忘了技能是一次性资产：给四个弱模型复用时分文未花；部署时每个任务的推理耗时中位数 368.2 秒，对比裸 agent 的 347.6 秒，几乎零负担。贵在造资产，不在用资产。

06影响与意义

这篇论文的第一重贡献，是把“问题”本身立住了。“开放世界自进化”这个设定，加上“看输入不算监督、依赖隐藏答案才算监督”这条边界，等于给后续研究立了规矩——以后谁自称 supervision-free，都得过这道审计。定义问题的人，往往比解决问题的人影响更持久。

第二重贡献，是证明了一个反直觉的命题：监督可以外包给世界。此前所有人都默认“判对错的信号必须来自任务本身”——要么环境给，要么人工标，要么模型自评。OpenSkill 拿出了第四种可能：公开文档里的参考值、知名数据集的统计不变量、交叉验证的程序，这些本来就存在于世界里的“可验证事实”，足以撑起一个像样的练习场。真值不必藏在测试集里，它散落在开放世界里。

第三重贡献，是给“技能即外挂文物”这条技术路线补上了最硬的证据：可检查（打开文件就能审）、可迁移（四个异构模型零成本复用）、可审计（谁也没偷看答案）。与把技能烧进权重的 RL 路线相比，这条路便宜、透明、不锁死在单一模型上——对于要在真实生产环境里部署 agent 的团队，这不是学术趣味，是真金白银的工程账。

论文已被 EMNLP 2026 接收，并且开源了全部 84 个任务上演化出的技能和检索到的知识文档——等于把“考场、小抄、复习资料”整套公开，后来者可以直接在这上面做对照实验。果不其然，两个月后的 SkillAlchemy 就在同一个基准上接了下一棒。

07局限性与未来方向

论文自己的“自我检讨”列了三条：开放世界的来源可能嘈杂、过时、自相矛盾，需要溯源与校验机制；虚拟任务可能高估技能质量，而如果有人从隐藏答案反推虚拟测试，“无监督”就成了假标签；开放世界检索增加了成本与延迟。都是实话。

但我觉得更值得咀嚼的是验证器的精度账：56.9% 的精确率意味着——自评“通过了”的技能里，将近一半其实没通过真题。拆开假阳性看，有三类很有代表性：12 个任务平均真实正确率高达 0.81，只差一口气，却因为“全对才给分”的一票否决制拿零分——模拟卷判它“大体不错”，严格来说不算冤枉它；11 个任务则是“格式全对、数值全错”，结构合格不等于语义正确，这是确定性断言天然的天花板；还有 2 个任务（化学相似性检索、代码翻译）虚拟验证器压根缺乏出题所需的专业知识，出了等于白出。

假阴性同样有故事：8 个里 5 个是 pytest 框架本身不适合任务类型（CVE 补丁、构建系统修复、证明助手）——不是题出错了，是这种题型根本没法用 pytest 判卷。这提示虚拟验证器的“题型库”还有很大的扩展空间。

往远处看，至少有三个方向值得追：技能的资产管理（检索、压缩、多目标选择，论文相关工作里已经冒出 SkillReducer、SkillMOO、Graph of Skills 一整排）；技能安全（技能文件是 agent 的上下文入口，天然是攻击面——一份被投毒的“技能”可比一个错答案危险得多）；以及本文留下的最大悬念——外挂技能 vs 内化权重，SKILL0、SIRI 等正在走“把技能烧进参数”的反向路线，两条路线的对决远未到终局。

08领域演进脉络

把镜头拉远，OpenSkill 处在两条大线索的交汇处，而它真正的历史地位，是完成了“验证信号来源”的第三次搬家：

  • 第一代：环境给。Reflexion 靠环境反馈当镜子（第 31 篇），代码任务靠单元测试判对错，Math-Shepherd 靠自动打分当牧羊人（第 23 篇）——验证信号是环境自带的，换到没有反馈机制的环境就失灵。
  • 第二代：自己算。自博弈系列把验证信号的生成也自动化了：Absolute Zero 用代码执行器出题、验证（第 55 篇），SWE-RL 用测试通过率当奖励（第 54 篇）。但它们仍然只在“天生可验证”的领域（数学、代码）里转，因为那里验证器免费。
  • 第三代：从世界锚定。OpenSkill 把“什么算对”锚定在公开文档的参考值、数据集的统计不变量、可交叉验证的程序上——验证信号第一次不再依赖任务自身，开放世界既是教材又是监考。

与之并行的“技能”线索同样三级跳：Voyager 在《我的世界》里攒技能库（第 36 篇）→ AgentFactory、AutoSkill、Memento 从自身轨迹里攒技能 → OpenSkill 直接从开放世界攒技能。两条线在本文交汇：技能从世界来，验证也从世界来。下一站的悬念则写在论文的引用列表里——技能造出来之后怎么管、怎么防投毒、该不该烧进权重，整个“技能工程学”的框架才刚刚搭起第一层。

09趣味延伸

先看作者名单，堪称一次“多国部队”集结：通讯作者孙立策（Lichao Sun）所在的理海大学 OpenLAIR 实验室出两位共同一作（闫梓玲与宋定杰——注意论文里“同等贡献”的双星号，写论文的行话就是“谁也别抢功”），合作方横跨 UIC、UBC、Vector 研究所、Salesforce AI Research，还有哈佛医学院与麻省总医院的向力（Xiang Li）——所以 Health 领域成了实验里的重头戏，也就不奇怪了。名单里还有一位数据挖掘界的传奇：俞士纶（Philip S. Yu），这位发表了上千篇论文、引用数以十万计的 UIC 老教授，退休年纪仍活跃在 LLM 一线，而且同实验室更早的 CoEvoSkills（技能与验证器共同进化）正是这篇论文的“前作”——同门师兄弟先证明了“技能和裁判可以一起进化”，这一篇再把裁判的锚从任务本身换到开放世界。

代码仓库里还埋着一个小彩蛋：附录 B.3 里不小心泄露了系统的内部代号——SkillWeaver loop，“技能编织机”。想想还挺贴切：把散落世界各地的知识线索，一梭一梭织成一张能用的技能之网。

工程细节里最有画面感的是那个“双盲阅卷”设计：阅卷官和考生住在同一个 Docker 容器里，低头不见抬头见，能翻到彼此的产出文件，却被硬性规定不许看对方的对话记录——像极了阅卷老师能看你的答卷、但不能偷听你脑子里的解题独白。而那个 gap-vs-bug 分类器则是个彻头彻尾的“保守派”：一旦自己出故障，立刻退到“这 bug 你自己能修”，绝不多花一次检索的钱——典型的工程最小惊讶原则。

最幽默的对照来自 AutoSkill：在 Opus 上还能打 24.7%，换个 GPT 5.2 直接腰斩到 11.2%——技能不但没能迁移，还把宿主模型“带沟里”了；而 OpenSkill 的技能原样塞给弱好几个档次的 Haiku 4.5，还能再涨十几个点。同一个基准，两种命运，自己写的小抄和世界写的小抄，含金量高下立判。

10个人解读与延伸思考

读完全文，最让我久久回味的，是论文在“上下文 vs 权重”这道选择题上表现出的清醒。作者明说了为什么不选改权重：贵、模型绑定、不可检查。OpenSkill 的技能像一本摊开的笔记本，任何模型翻开就能用，审计员逐行就能查；而烧进权重的技能像一块黑巧克力，咬开也不知道里面是什么。四个弱模型零成本白嫖 Opus 的技能这个实验，几乎是给“笔记型学习者”投了一张赞成票。但我并不觉得这是终局——SKILL0、SIRI 那边的“刷题型学习者”也在进步，或许最终的形态是先外挂攒技能、再挑高频技能内化，“先抄笔记、再练成条件反射”，两头的好处都占。

另一层启发在于这个设定本身的现实感。企业里真正想让 agent 干的活，恰恰是那种没有标注数据、没有评估体系、没有标准答案的“主管拍文件夹”式任务。学术界最爱的“可验证环境”在真实世界里是奢侈品。从这个角度说，OpenSkill 最有价值的不是那 43.6%，而是它把研究者的注意力拽回了真实部署的默认处境：没有裁判，才是常态。

而它最大的软肋，我以为是“验证器的单点故障”。整条流水线的信任链条，最终都压在那份自建模拟卷上——模拟卷的锚从世界来，这解决了“出题人瞎出”的问题，却没解决“出题人系统性出偏”的问题。消融实验里“练十遍反而退步”已经是个微缩预告：模拟卷和真题之间存在系统性缝隙，练得越狠，缝隙越大。

留个问题给你 如果 agent 自建的验证器本身出了系统性偏差——比如它总在格式上较真，从不检查数值对错——技能会不会在这份“跑偏的模拟卷”上越练越偏？更关键的是：agent 自己能发现自己“练偏了”吗？它需要什么样的机制才能发现“裁判错了”？下一篇要讲的“证据准入”思路，恰好是对这个问题的另一种回应——出题之前，先审题。

SkillAlchemy: Open-World Agent Skill Creation（SkillAlchemy：开放世界的技能炼金术）

OpenSkill 证明了开放世界的材料能炼出好技能，但它对搜回来的知识几乎“照单全收”——虚拟测试通过就收编入库。可网上的文档会过时、会互相打架，两份“权威资料”观点相反时，该听谁的？两个月后出现的 SkillAlchemy 把战场推进到“准入”环节：它用“对比证据”挖掘出任务简报里没写明的隐性要求，再按“证据支持的适用范围”决定哪些操作程序有资格写进技能包——同样在 SkillsBench 上，把无技能基线拉高 19.9 个百分点，比最强自动化基线再高出 8.6 个百分点。搜回来的知识，凭什么标准判断谁配进技能？“炼金术”的炉子，下期开炉。
