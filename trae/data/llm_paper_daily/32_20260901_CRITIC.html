大模型经典论文精读系列 #032

CRITIC: Large Language Models Can Self-Correct with Tool-Interactive Critiquing CRITIC：自我纠正的"工具派"解法——让模型像人一样调搜索引擎查事实、调代码解释器查 bug，把"外部反馈"从环境奖励升级成"主动工具批判"

作者：Zhibin Gou, Zhihong Shao, Yeyun Gong, Yelong Shen, Yujiu Yang, Nan Duan, Weizhu Chen 机构：Tsinghua University · Microsoft Research Asia · Microsoft Azure AI 发表：2023-05 / ICLR 2024
arXiv GitHub

上一篇 Reflexion 给自我纠正留了条活路：只要把环境的标量奖励翻译成一段语言反思、塞进记忆，下一回合就能涨点。但它有个隐含的瓶颈——Evaluator 还是只能输出"通没通过、对没对"，至多告诉你结果错了，却没法告诉你哪句话错了、哪个数字错了。换句话说，Reflexion 的反馈仍然粗糙、仍然只能事后追责。

那人类是怎么"自我纠正"的？一个真正有经验的写作者，写完一段不会立刻自我陶醉——他会去打开 Google 查一下那个数字、去 Stack Overflow 跑一下那段代码、去问一句"这话会不会冒犯谁"。他从不靠"我自己的感觉"，他靠的是外部工具给他的客观信号。CRITIC 的作者们就盯住了这一点：既然人靠工具纠正自己，那大模型为什么不能？这就是 CRITIC——让一个不调权重的黑盒 LLM，像人一样主动调搜索引擎、调代码解释器、调毒性 API 来批判自己的初稿，再据此改写。它在 ChatGPT 上把 QA 涨 7.7 F1、数学涨 7.0%、毒性降 79.2%——顺便又狠狠证了一遍上一篇的结论：把工具一撤，自我纠正立刻又瘪回去。

一句话总结 不调一个权重的自我纠正？CRITIC 让 ChatGPT 自己调搜索引擎查事实、调 Python 跑代码、调毒性 API 评分，再用这些工具反馈挑自己的错、改自己的答案——QA +7.7 F1、数学 +7.0%、毒性 -79.2%；同时戳穿：把工具一撤，自我纠正立刻又瘪回去。

01领域定位

把 CRITIC 放回我们这条"自我纠正四部曲"里看，位置清晰得不能再清晰——

  • 第 29 篇 Self-Refine：自我批评当成提示工程法宝，立论"自己改自己"。
  • 第 30 篇 Cannot Self-Correct Reasoning Yet：把招牌砸了——纯内在自我纠正其实是作弊。
  • 第 31 篇 Reflexion：救回来——加上外部环境反馈 + 语言记忆，自我纠正活过来。
  • 第 32 篇（本篇）CRITIC：再进一步——把外部反馈从"环境奖励"升级成"主动工具批判"。

Reflexion 的 Evaluator 主要是被动接收：跑测试看通没通、查答案对没对，环境主动告诉 agent 一个标量。CRITIC 把这个 Evaluator 拓成了一组主动调用的外部工具：搜索引擎查证每条事实、代码解释器跑通每段程序、毒性 API 评估每段输出。反馈从"环境喊一声对错"升级成"工具喊出一堆证据"。这看似只是把 Reflexion 的反馈信号变丰富了，但它的真正野心是把"工具调用"和"自我纠正"焊死——任何能写成 text-to-text API 的工具，都能塞进这个 verify-then-correct 的回路。往回看它接 ReAct（Yao 等人 2022）和 Toolformer（Schick 等人 2023）这条"工具使用"主线；往前看，它直接喂出了 Self-RAG（Asai 等人 2023，下一篇预告）、Voyager、CRITIC 家族自己的 CriticBench——把"工具批判自我纠正"从一个提示协议演化成模型被训练的能力。

02研究背景

2023 年上半年，ChatGPT 让全世界第一次真切地用上了"会说话的机器"。但用得越熟，问题越显眼：它会一本正经地编造不存在的事实（hallucination），会写出看似能跑实则崩溃的代码，甚至会顺嘴吐出带偏见或攻击性的话。这三类毛病——事实幻觉、代码错误、内容毒性——是 2023 年 LLM 部署的三块最大绊脚石，它们卡的不是"模型有多强"，而是"模型有多可信"。

传统解法是再训练：行为克隆、强化学习、自训练、RLHF（上一篇 InstructGPT 那条路线）。但这条路又贵又脏——需要海量人工标注、需要专门构数据、需要为每类毛病单独训一个纠正器。更尴尬的是，模型一旦发布就只能调用 API，权重摸不着，想训练也训不动。2023 年 3 月的 ChatGPT 就是这样一个巨大的、闭源的、不可调的黑盒——你既不能让它变好，也不能让它自查，只能眼看着它犯错。

另一条线是自我纠正：不调权重，让模型自己回头批评自己。Self-Refine（第 29 篇）开了头，但很快被 Cannot Self-Correct（第 30 篇）戳穿——纯靠"同一个脑子审同一个脑子"，没新信息进来，越改越糟。Reflexion（第 31 篇）补了一条缝——加上外部环境反馈、塞进语言记忆，问题就活过来。但 Reflexion 的外部反馈本质还是标量：测试通没过、目标到没到。它能告诉你这次失败了，却没法告诉你哪一句说错了、哪个变量算错了。反馈仍然太粗，仍然只能事后追责，没法精准定位。

类比 想象一个闭着眼睛写新闻稿的实习生。Self-Refine 让他自己念给自己听——念错了也听不出来；Reflexion 让他写完之后，主编告诉他"这一版不行"——他知道不行，但不知道哪儿不行；CRITIC 给他配了三件工具：一个 Google 搜索框、一个 Python 计算器、一个"攻击性词汇探测器"。他写完一段，自己用这三件工具去验证——查不到的事实他会犹豫、跑不通的代码他会改、太毒的句子他会重写。工具给了他原本没有的"客观感官"。

CRITIC 抓住的就是这个直觉：把 LLM 当黑盒，外部给它一套 text-to-text 的工具 API，让 LLM 自己学会像人一样调工具去查证、再用工具反馈去改。不训任何参数，全靠 in-context learning 的几个示例，就把一个不会自我反思的 ChatGPT 改造成了一个会自己给自己审稿的"事实核验员 + 程序调试员 + 内容审查员"。

03核心问题

论文要回答的问题可以一句话讲清：一个不可微调、只能调 API 的黑盒 LLM，能不能靠"模仿人类用工具交叉验证"的方式，从外部工具反馈里学到东西，把自己的初稿改得更准、更对、更安全？

这里有两个关键词。第一是黑盒不可训——和 Reflexion 一样，它必须只靠 in-context learning，不碰权重；第二是工具批判——它要的不只是 Reflexion 那种"环境奖励"，而是具体到事实、代码、毒性三个维度的工具反馈，反馈能告诉模型"这句错了，因为 Google 上查不到"，而不只是"这次错了"。作者赌的就是这一条：只要反馈信息密度够高，纯提示协议也能驱动可信的自我纠正。

思考一下 先别往下读，凭直觉猜：让 ChatGPT 写一段数学题的解题程序，跑出来答案不对，然后让它自己再回头改一遍，不给它任何工具反馈、只让它"再想想"——你觉得它的正确率会涨还是会跌？很多人会猜"涨一点点，多想一遍总能改对几个"。CRITIC 论文给的数据是跌。Text-Davinci-003 在 GSM8k 上不调工具自纠正，solve rate 从 69.7% 跌到 67.9%——少了 1.8 个点。这就是开篇那句"自我纠正瘪回去"的来由。

04方法详解

CRITIC 的方法可以一句话概括：把"自我纠正"重新定义成"先用工具验证、再用验证反馈改写"的迭代循环。听上去朴素，背后是把"自我批评"这件虚的事，绑定到了"工具调用"这件实在的事上。我们分三步拆开。

第一步：一个 verify-then-correct 的算法骨架

论文给出 Algorithm 1，整个流程写得极简：

Input: 输入 x, 提示 wp, 模型 M, 外部工具集 T = {T1, T2, ..., Tk}, 迭代次数 n
Output: 修正后的输出 ŷ

1:  ŷ0 ∼ P_M(·|wp ⊕ x)                       ▷ 用模型先出初稿
2:  for i = 0 to n-1 do
3:      ci ∼ P_M(·|wp ⊕ x ⊕ ŷi, T)           ▷ 调工具验证，得到批判 ci
4:      if ci 表示 ŷi 正确 then
5:          return ŷi                          ▷ 工具都点头，停
6:      ŷ(i+1) ∼ P_M(·|wp ⊕ x ⊕ ŷi ⊕ ci)     ▷ 据批判改写
7:  return ŷn

翻译成人话：模型先按 in-context learning 出一个初稿；然后主动调外部工具去验证初稿的某些方面（事实对不对、代码跑不跑、毒性高不高），把验证得到的反馈拼成一段 critique，再用这段 critique 当上下文，让模型改写初稿。如果工具都点头说"没问题"，就停；否则再验证、再改写，直到收敛或迭代上限。整个流程只动 prompt 里的文本，不动一个参数。

第二步：三件工具，对应三种毛病

CRITIC 没有发明任何新工具，它的聪明之处是把每类毛病和一类现成工具精准匹配——这样反馈既能拼成一段统一的自然语言 critique，又能从外部客观世界拿到信号。三对对应关系如下：

  • 事实幻觉 ↔ 搜索引擎：QA 任务（AmbigNQ、TriviaQA、HotpotQA）让模型自己写出验证查询、调 Google Search API，把检索回来的片段作为证据，让它判断初稿里的事实能不能被外部证据支持。
  • 数学/代码错误 ↔ Python 解释器：数学程序合成任务（GSM8k、SVAMP、TabMWP）让模型把解题写成 Python 代码，调代码解释器执行，看返回的结果或报错。代码跑通且答案对就是点头，跑崩或答错就把报错拼进 critique。
  • 内容毒性 ↔ Perspective API：毒性降低任务（RealToxicityPrompts）调 Google 的 Perspective API 给输出打毒性分，分数拼进 critique，让模型据此重写。

统一在 text-to-text 接口下，意味着这套框架插什么工具就修什么毛病——只要新工具能写成"输入文本、输出文本"，就能塞进 CRITIC。这是它"plug-and-play"的关键，也是后来 Self-RAG、CRITIC 家族各种变体得以快速长出来的原因。

第三步：不用训练，全靠 in-context 演示

整套 CRITIC 的最妙之处是实现成本极低。作者没有为任何一类任务训练专门的模型，所有工具交互、critique 生成、改写，全部通过给 LLM 提供few-shot demonstration 来教会——演示里写明"看到这种答案，怎么写出搜索查询、怎么把检索结果拼进 critique、怎么据此改写"。模型靠 in-context learning 的涌现能力，照着示例就学会跑这套流程了。

具体来说，CRITIC 的 prompt 由三部分组成：

  • 初稿生成演示：教模型先按任务出初稿（QA 用 CoT、数学用 Program-of-Thoughts、毒性任务直接续写）。
  • 验证 + critique 生成演示：教模型在初稿后，调相应工具，把工具返回结果拼进上下文，再生成一段"What's the problem with the above answer?"的 critique。所有 critique 都用同一个触发句，意味着这个机制对任意工具都是同一个接口。
  • 改写演示：教模型根据 critique 直接给出修正后的输出。

把这三段演示拼起来喂给 ChatGPT、Text-Davinci-003 或 LLaMA-2 7B/13B/70B，它们就都成了"会自己审稿的 CRITIC agent"。模型本身一字没动，调的是 prompt 里的世界。

05实验结果

实验覆盖三类任务，模型从黑盒（ChatGPT、Text-Davinci-003）到开源（LLaMA-2 7B/13B/70B）。结果干净利落地回答了开篇那个问题——能，而且涨得稳。

任务类型ChatGPT 基线+ CRITIC提升
QA · 平均 F1（3 个数据集）基线+7.7 F1+7.7
数学 · 平均 solve rate（3 个数据集）基线+7.0%+7.0pt
毒性 · 概率降低基线-79.2%-79.2%
数学 · GSM8k（具体）基线+5.7%+5.7pt
TabMWP · LLaMA-2 7B → 13B → 70B基线+4.7% / +9.4% / +16.0%规模越大，CRITIC 涨得越多

三个任务里最抓眼球的是毒性降 79.2%——一个不调权重的提示框架，居然在 RealToxicityPrompts 上把 ChatGPT 的毒性概率砍掉了将近八成，已经接近专门用监督学习训练的 SOTA 毒性缓解方法。QA 平均涨 7.7 F1，全面碾压 CoT 提示、甚至胜过 ReAct 这种"边推理边调工具"的强基线。数学任务平均涨 7.0 个百分点，GSM8k 单项涨 5.7pt。而且最值得说的是规模 scaling：在 TabMWP 上，LLaMA-2 从 7B 到 13B 到 70B，CRITIC 带来的增益依次是 +4.7%、+9.4%、+16.0%——模型越大，CRITIC 涨得越多。这意味着这套框架和模型能力正交且互补：基础越强，工具批判的效果越好。

消融：把工具一撤，自我纠正立刻又瘪回去

作者做了一组关键消融——CRITIC w/o Tool：让模型走完整个 verify-then-correct 流程，但不给它任何外部工具，全靠它自己"反思"。结果和上一篇 Cannot Self-Correct 的结论严丝合缝：

  • QA 任务：去掉工具后，F1 增益从 +7.7 掉到只有 +0.03 ~ +2.33——基本等于没涨。
  • 数学任务：更狠，Text-Davinci-003 在 GSM8k 上不调工具自纠正，solve rate 从 69.7% 跌到 67.9%——少了 1.8 个百分点，越改越糟。
反直觉发现 作者还顺手做了一个有点让人后背发凉的实验：让 LLM 给自己输出做不确定性估计（self-verification），看它能不能识别自己哪句话是幻觉。结果是它在幻觉检测上经常比随机猜还差——也就是说，模型自己根本不知道自己什么时候在编。这正好从反面解释了为什么 CRITIC w/o Tool 会跌：模型的"内在自信度"根本不可靠，靠它来判断自己改不改，就是盲人给盲人引路。

把消融和主实验放一起读，能读出这篇论文真正的主张："工具批判"不是锦上添花，是"自我纠正"这条路的必要条件。流程一模一样，区别只在有没有外部客观信号——有就涨、没有就跌。这是 CRITIC 给这个领域的最硬一记锤。

06影响与意义

CRITIC 的影响远超它"QA +7.7、数学 +7.0、毒性 -79.2%"这组表面数字。它至少做了四件大事——

第一，给"工具交互型自我纠正"立了一个范式。在它之前，工具使用（ReAct、Toolformer）是一条主线，自我纠正（Self-Refine、Reflexion）是另一条主线，两条线一直平行。CRITIC 把它们焊在了一起：自我纠正不是反思、而是"调工具批判 + 据反馈改写"。这个"工具批判"范式后来成了 agent 圈的基础设施级思路，CRITIC 也成了 agent 自我纠正绕不开的引用。

第二，再次钉死了"无外部反馈的自我纠正不可靠"。第 30 篇 Cannot Self-Correct 是从推理任务上钉的，Reflexion 是从环境反馈角度补的，CRITIC 是从工具批判角度又钉一遍——三篇论文从三个不同侧面收敛到同一个结论：新信息必须从外部进入。这个共识在 2023-2024 年成了 agent 圈的共识，再没人敢写"纯内在自我纠正"的论文。

第三，把"plug-and-play 工具批判"做成了模板。CRITIC 的 text-to-text 工具接口意味着"插什么工具就修什么毛病"——这个模板后来被无数 agent 框架抄走。OpenAI 自己在 2024 年 6 月发布的 CriticGPT（用 GPT-4 训练专门写 critique 的模型，给人类 RLHF 标注员当助手），名字和思路都和 CRITIC 同源——只是把"提示协议"升级成了"训练一个 critique 模型"。CRITIC 是这条线最直接的祖先。

第四，直接喂出了 Self-RAG、Voyager、CRITIC 家族自己的 CriticBench。Self-RAG 把"调检索器 + critique"焊进了模型权重，训出了带"反思 token"的 retrieval 模型；Voyager 把"工具批判 + 记忆"升级成"技能库 + Minecraft 无限探索"；CriticBench（同一作者团队后续工作）专门给"critique-correct reasoning"立了个 benchmark。可以说 2023-2024 年那批最有想象力的 agent + critique 工作，几乎都站在 CRITIC 画的延长线上。

07局限性与未来方向

作者在附录里很坦诚地列了几条 CRITIC 的局限。最显眼的一条是推理延迟：每改一次要调好几轮工具，QA 任务光搜索就要多次，加上迭代，端到端延迟是基线的几倍到十几倍。对实时对话场景不友好，对离线批处理倒是不痛不痒。这条后来被 Self-RAG 用"把检索和 critique 焊进权重"的方式补上——速度代价被吸收进模型自身。

第二条是提示工程成本。CRITIC 全靠 few-shot 演示，每种工具、每类任务都要手写演示，门槛不算低，且对 prompt 措辞敏感。这意味着它没法完全 plug-and-play，新任务要新写演示。后续工作（Self-RAG、Toolformer）正是用训练把"什么时候调什么工具"内化进模型，让这步变得自动化。

第三条更微妙：CRITIC 的上限被"工具本身的能力"卡死。如果搜索引擎没收录某条事实、Perspective API 对某类毒性不敏感、Python 解释器对某类语义错误报不出错，那 CRITIC 的 critique 就会缺这块——模型以为"工具都点头了"其实只是"工具没看见错"。换句话说，CRITIC 把模型的自我验证问题外包给了工具，但工具本身也不万能。后来 Self-RAG 的"反思 token + 检索置信度"、CRITIC 家族自己的 CriticBench，都在试图把这块测得更细。

第四条是和 Reflexion 同款的隐忧：语言 critique 也有 reward hacking 风险。如果模型把 critique 拼得不对，改写就往错方向走。论文里没给形式化收敛保证，理论上不收敛。这是 prompt-time learning 普遍的硬约束，不是 CRITIC 独有。

08领域演进脉络

把本篇放回我们的演进时间线，能清楚看到两条线在 CRITIC 这里第一次合流——

  • 工具使用主线：ReAct（2022，给 agent 加工作记忆 + 工具调用）→ Toolformer（2023，把工具调用训进权重）→ CRITIC（本篇，工具批判 + 自我纠正） → Self-RAG（2023，把工具批判 + 反思 token 训进权重）。
  • 自我纠正主线：Self-Refine（29 篇，纯内在）→ Cannot Self-Correct（30 篇，戳穿）→ Reflexion（31 篇，外部环境反馈 + 语言记忆）→ CRITIC（本篇，外部工具反馈 + critique）。

这两条主线在 CRITIC 处汇成一条河——它既是自我纠正主线的"工具派"延伸，又是工具使用主线的"自我纠正"延伸。汇合之后再往前，一条支流奔向 Self-RAG（把 critique 焊进权重，进入训练时代）；另一条支流奔向 Voyager（把 critique 升级成可复用技能库，进入终身学习时代）。再往远看，这条"工具批判 + 自我纠正"的思路，最终在 2024 年 9 月汇入 o1 开启的"推理范式期"——只不过 o1 把"调工具批判"和"改写"都直接训进了 RL 训练目标里。CRITIC 正是这条河从"提示协议"流向"RL 训练"的关键中转站。

09趣味延伸

这篇论文背后有几个挺有意思的细节。第一个是血统：两位共同一作 Zhibin Gou 和 Zhihong Shao 当时都是清华大学深圳国际研究生院的硕士生，论文标注是"Work done during an internship at Microsoft Research Asia"——也就是说，这是一份实习生级别的工作，撞上了 ChatGPT 刚发布的窗口期，就成了 agent 自我纠正圈最常被引用的几篇之一。AI 圈的"实习生改变历史"现象，在 2023 年尤其常见。

第二个是代码所在。论文的 GitHub 链接是 microsoft/ProphetNet/tree/master/CRITIC——CRITIC 的代码被放在了 ProphetNet（一个 2020 年的预训练模型）的仓库下面。这背后大概率是 MSRA 实习生复用了组里已有基础设施的痕迹——一个 2023 年的 agent 论文，代码住在 2020 年预训练模型的仓库里，AI 圈的代码考古经常比论文考古更有意思。

第三个是团队后续。CRITIC 的两位一作 + 通讯作者 Yujiu Yang 在 2024 年 2 月又联合推出了 CriticBench（arXiv 2402.14809），专门给 LLM 的"critique-correct reasoning"立了个 benchmark——5 个推理域、15 个数据集、17 个 LLM。CriticBench 是 CRITIC 论文最直接的自然延续：CRITIC 提出了"工具批判自我纠正"的方法，CriticBench 就给它配套了评测标准。同一个团队把一件事从"提出方法"做到"立 benchmark"，这种工作连贯性在 AI 圈并不多见。

第四个是名字的双关。CRITIC 既是论文核心动作"批判"（critique），又读起来像"critical thinking"——作者在 intro 里直接引用了 critical thinking 的哲学文献（Marcus 1988、Ennis 1991）。一个 prompt 框架主动去坐"批判性思维"那把哲学椅子，比直白的 Self-Refine 多了一层学术野心——它要的不只是"改一遍"，而是"像人一样会查证、会反思、会改"。

第五个细节有点人情味。CRITIC 投稿到 ICLR 2024 之前一共改了四个版本——v1 在 2023 年 5 月 19 日挂出，v4 在 2024 年 2 月 21 日定稿。近 9 个月的修改里，作者把"工具批判"这条主线越说越清楚，最终把卖点从"在 ChatGPT 上自我纠正"重新框定成"plug-and-play 的工具批判框架"。一个标题保持不变、但故事越讲越准的论文，往往反映的是研究者自己对这个工作的认识在打磨中变深了。

10个人解读与延伸思考

读这篇论文，我最想留给你的是两个判断。第一个是关于"自我纠正"的必要条件被钉死了。我们这四篇连读下来，结论已经收敛到一句非常清楚的话：没有外部新信息进来，自我纠正要么不涨、要么越改越糟。Self-Refine 是反例、Cannot Self-Correct 是钉棺、Reflexion 是从环境反馈补正、CRITIC 是从工具反馈补正——四篇论文从四个角度收敛到同一个共识。如果你在生产里搭 agent，记住这条卫生习惯：任何"自我批评"模块，要么接外部工具、要么接环境信号、要么接人工反馈，别让模型自己审自己。

第二个判断更实操："工具批判"是一种 agent 设计哲学，不是一个算法。CRITIC 给的不是 verify-then-correct 这个流程本身——这流程 Self-Refine 早就有了——而是"用工具反馈当 critique 的来源"。这意味着你可以照搬这个思路到任意任务：写代码就让模型调 linter + 跑测试当 critique、做 RAG 就让模型调二次检索当 critique、做长文摘要就让模型调事实核查 API 当 critique。只要你能给 agent 接上"客观感官"，自我纠正就活过来。CRITIC 的真正贡献，是把这种"工具批判"思路做成了可复制的设计模式。

把这两条放一起，还能读出一个更深的判断：CRITIC 是"提示协议时代"的巅峰之作之一，但也是这个时代的尾声。它把"工具批判 + 自我纠正"用纯 prompt 做到极致之后，下一步显然就是把它训进权重——Self-RAG 把 critique 训成 token、Toolformer 把工具调用训进模型、o1 把"调工具 + 自我纠正"训进 RL 目标。CRITIC 站的位置，正好是"提示协议"和"训练时代"的分水岭：它一边把提示协议推到极限，一边把下一阶段要训的东西全部摊开摆好。

留个问题给你 CRITIC 的 critique 是模型用自然语言拼出来的，背后是工具返回的客观信号。如果未来我们让模型直接生成"我要调什么工具、调几次、怎么解读结果"的整套动作序列，并把这套动作训进权重——这还算"工具批判自我纠正"吗？还是说，它已经变成另一种东西了？提示协议和训练时代的分界线，到底画在哪里更准？你怎么分？

Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection

CRITIC 把"工具批判 + 自我纠正"用提示协议做到极致，但延迟高、要手写演示、上限被工具卡死。下一篇我们讲 Self-RAG：把 CRITIC 这套"调检索器验证 + 生成 critique + 据此改写"的流程，焊进模型权重——靠 RL 训出四种"反思 token"，让模型自己学会什么时候检索、什么时候拒绝、什么时候改写。提示协议的巅峰之作之后，自我纠正正式跨入训练时代。
